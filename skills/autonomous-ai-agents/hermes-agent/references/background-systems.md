# Durable & Background Systems

Four systems run alongside the main conversation loop. Quick reference
here; full developer notes live in `AGENTS.md`, user-facing docs under
`website/docs/user-guide/features/`.

### Delegation (`delegate_task`)

Spawn a subagent with an isolated context + terminal session.

- **Single:** `delegate_task(tasks=[{"goal": "...", "context": "..."}])` using the live tool schema.
- **Batch:** pass several task entries for parallel work; respect the effective `delegation.max_concurrent_children` limit.
- **Delivery:** follow the dispatch result's actual delivery contract. If it says background results arrive after the parent ends its turn, finish only independent work and end with a brief status. Do not poll transcripts or artifacts to wait for the child. Never invent a `background` argument when the live schema does not expose one.
- **Child limits:** follow the installed tool contract; current native children cannot recursively delegate or ask interactive questions. Do not assume orchestrator permissions from older runtime documentation.
- **Verify lifetime separately from backgrounding.** Native children are process-local. For work that must outlive the parent process, use a verified scheduler or an explicitly authorized persistent runner; a background flag or process handle alone is not durability evidence. Keep ordinary turn-level background execution distinct from session-release and reboot survival.

Config: `delegation.*` in `config.yaml`.

Keep native task prose free of unresolved angle-bracket template markers. The dispatch validator can reject sample output placeholders before launching any child; use a real `output_schema` or describe required fields in plain prose. Record that rejection as not dispatched, correct the packet once, and verify the successful native handle instead of claiming a reviewer started.

For native cloud lanes, pin provider, model and reasoning effort together in the dispatching turn, and verify the applied route before dispatch. A model-only override can retain a previous custom/local provider even after the parent switches models; an HTTP 400 `model not found` from that wrong destination is not proof the intended subscription provider lacks the model. Preserve the failed attempt, correct the provider once, and do not automatically move to an unrelated mixture fallback or billing route. Record intended routing separately from actual observed worker identity.

For optional legacy configuration keys, distinguish an explicit unset-key response from a lookup failure. The observed `hermes config get fallback_model` contract returns exit 1, empty stdout and `Config key not set: fallback_model` on stderr when absent; retain that exact key/message as absence evidence rather than requiring exit 0 or printing fallback/credential contents. Revalidate changed messages instead of accepting any nonzero/empty result.

For a bounded CLI alternative, preserve existing approvals and pin provider/model/effort per invocation; do not use `--yolo` or change single-query policy to admit it. Validate approval policy through `hermes config get approvals.mode` and `hermes config get approvals.single_query_mode`: raw YAML may omit keys supplied by defaults and is not the effective policy. For a fail-closed CLI lane, verify both `fallback_providers` and legacy `fallback_model` are absent/empty without dumping their contents; do not clear a shared fallback chain to admit the worker. For a foreground-only lane, fit the CLI budget and wrapper deadline inside the observed enclosing tool-call cap. For a managed background lane, keep observer waits short but give the worker its own task-sized total deadline; an observer cap is not the worker's lifetime. Record both budgets so a polling-window expiry cannot be mistaken for a runner timeout. A tool timeout does not establish process death: inspect the recorded PID/PGID/session before resuming. A requested terminal timeout can be cut off by a shorter enclosing cap; measure the effective cap for the current backend, keep foreground control-plane observation batches below it, and check whether the observer itself survived before launching another. An observer timeout is not the worker's timeout. Resume a completed discovery checkpoint with only its remaining judgement, not a fresh full review, and preserve unknown exit when a reboot kills the wrapper before it records one. Stop redundant relaunches after repeated host interruptions; incomplete independent review remains an acceptance gate.

### Recovering delegated-work authority and checkpoints

1. **Start with the retained source manifest and handoff.** Bind the candidate to its actual base, owned paths and artifact hashes before reopening history; these artifacts usually answer restoration questions more cheaply than rereading a full transcript. Validate artifact contents rather than existence: after an abrupt restart, dispatch metadata can be absent and transcript/manifest files can be empty despite earlier successful write reports. Preserve that missing evidence as unknown, not a completed or never-started task. Store large JSON snapshots in private evidence files and return compact handles; an exit-0 terminal capture can still contain truncated head/tail JSON. Recover from its `full_output_path` without repeating side effects. Retained full output may append `__HERMES_CWD_*` framing: parse the first complete document with `JSONDecoder.raw_decode` and independently verify the exact owned-CWD trailer rather than ignoring arbitrary extra data.
   - **Reconstruct history with bounded projections.** Start with `omh_resume` and recent `session_search` results, then follow the requested session's parent lineage and repository/cwd to the actual predecessor. Read anchored windows only for missing decisions or evidence pointers; broad keyword matches can surface copied memory blocks, nested compaction summaries and another project's latest activity. Use discovery to locate an anchor before opening a session. If retrieval returns a whole-session/read-mode dump instead of bounded matches, correct the retrieval mode before retrying: changing only the keywords can replay the same transcript and consume context without recovering the decision. If required metadata is still missing, resolve the active profile's `state.db`, inspect only the necessary table/column schema, and use a read-only SQLite connection such as `sqlite3.connect(f"file:{db_path}?mode=ro", uri=True)` with explicit session IDs, projected columns and bounded rows. Select identity, lineage, cwd and actual user/assistant content; do not select system prompts, model configuration, reasoning or unrelated sessions. Keep complete originals in their owning store and return only the missing decision plus its message/session anchor.
   - **Inspect artifact shape before loading its body.** Parse the original JSON locally and project only status, source bindings, commands/exits, ownership and remaining work. Do not reconstruct machine JSON by stripping line numbers from a human-oriented file rendering: long-line wrapping or truncation can corrupt an otherwise valid document. Keep that observer failure separate from worker state. Inspect named fields or bounded script regions before opening a large artifact; a task or review packet can embed the entire source corpus. Retrieve the missing interface or evidence fragment, then execute the first admitted unfinished stage rather than broadening historical reconstruction.
   - **Separate required checkpoints from optional reports.** Complete the independent source and ownership checks even when an ancillary handoff or approval-copy file is missing; record that absence instead of letting its read abort the entire recovery probe. Recover approval from its actual question/answer channel below and persist a new scoped copy. Keep dispatch blocked if a mandatory source binding or required approval genuinely cannot be established; missing optional packaging is neither permission nor proof the source was lost.
   - **Reconcile the accepted checklist before redeclaring it.** When available, read both `todo_list()` and `omh_todo(action='show')`; an empty process-local list can coexist with retained session scope. Resolve a mismatch against the same session/project's accepted plan, not another task's recalled list. Restore the same ordered requirements, nesting and evidence-supported states through the single chosen tracking tool; refresh obsolete executor/blocker wording without dropping unresolved gates. Compare a pause/reboot checklist against the retained accepted scope before advancing it: keep restart checks as additions or nested items, and restore any accidentally omitted delivery outcomes rather than inferring completion from their absence. Preserve valid completed proof. Name the scope of admission checks explicitly, so source-review readiness neither certifies native execution nor waits on unrelated runtime clearance. Keep exactly one active item, then read the mirrored list back. Resolve any later numeric `advance` index from that latest returned projection, not the submitted order or stable todo ID: priority ordering can move the active item. Pair the current index with its current text-prefix guard so a cross-tool update cannot target another requirement. Checklist reconstruction is metadata recovery, not fresh execution or acceptance.
   - **Persist the small ownership record before yielding.** Record the returned native delegation handle, session/checkout, current boot, source/index baseline, approvals, evidence paths and last observed state in a private persistent directory. Set final permissions, flush and fsync completed files, then fsync their containing directories. Require incremental source/test handoffs and separately fsynced logs, because a durable dispatch record does not make worker progress or external log files durable.
   - **Archive completed proof before volatile or pruned scratch can expire.** At a reboot or long-retention boundary, confirm the writer of the copied object set is terminal, copy the complete frozen source/support set into a create-only persistent task archive, then verify every catalog-bound object against its original bytes, mode and object kind. Carry recorded modes onto the owned archive copies before validating the catalog: a byte-verified text write does not establish preserved permissions. Do not change source permissions or refresh the original manifest to admit a mismatching copy. Preserve embedded source coordinates and record an explicit original-root-to-archive mapping rather than rewriting reviewed manifests to name the new location. Publish the archive catalog and parent acceptance reference only after those checks, then fsync archived files and directories; syncing scratch alone does not change its storage or retention policy.
   - **Preserve committed candidates before removing disposable checkouts.** First bind `git -C "$CHECKOUT" rev-parse HEAD` to the retained candidate. Create a private, new bundle with `git -C "$CHECKOUT" bundle create "$BUNDLE" "$BASE..HEAD"`; use a named positive ref such as `HEAD`, because a bundle must advertise a ref, not merely select commit objects. Verify it with `git -C "$RESTORE_REPO" bundle verify "$BUNDLE"` in the intended restore repository before cleanup. Record the advertised candidate, required base, bundle digest and verification exit alongside the frozen source/patch and proof catalog. Label this range bundle incremental, not a self-contained backup: its base must remain available, and the bundle alone does not preserve test evidence or independent acceptance.
2. **Retrieve only a genuinely missing decision.** Use an explicit answer already in the current conversation, its source-bound approval receipt or an approved project decision record before searching raw history. When reviewer availability appears to block progress, recall the project/task's reviewer-approval decisions first, then check the action, actor, allowed route and latest restrictions; a previously approved alternative may already resolve the gate. For an answer captured by `clarify`, search a distinctive question fragment plus `user_response` using the tool-role filter when supported; generic approval labels can return a valid but unrelated authorization.
3. **Validate scope using the actual answer channel.** For a `clarify` form, bind the original question, answered response and submitted outcome. For direct chat, bind the concrete pending question and the user's reply; do not demand a nonexistent form receipt. Use compaction summaries only as lookup anchors and check the matched message, because a summary or an interrupted assistant acknowledgement is not the decisive user answer.
4. **Stop retrieval once the authority and checkpoint are sufficient.** Give the worker a compact remaining-work packet with the base, owned paths, bound receipt/log handles, exact failing node and next acceptance boundary; do not forward the full transcript or repeat completed discovery. Reconcile each stage against newer source-bound command/exit receipts before assigning the remainder: a BLOCKED or WORKING handoff can predate a completed test, and a stale RUNNING owner record can coexist with a terminal completion receipt. Carry valid completed proof forward with its original execution and boot identity instead of scheduling it again merely because the summary is older. Record this reconciliation in the successor checkpoint without rewriting historical receipts.
5. **Transfer only after confirming the prior owner has ended.** Check the native task handle and scoped checkout/session descendants before replacement. Distinguish a genuine writer from your inspection command or ancestor shell containing the same task markers; command-text matches alone can falsely identify the observer as the old worker. Compare saved/current boot identities without inventing an unrecorded exit, preserve the predecessor artifacts read-only and give the replacement a fresh evidence directory. If a saved boot identity is missing, use current boot/uptime and artifact timestamps only as bounded interruption evidence; keep the original exit unknown. Reuse a matching source checkpoint and assign the first unfinished obligation rather than restarting discovery. Supersede every old evidence/output path in the replacement packet so the new worker cannot write into the predecessor's frozen evidence. If the original writer remains active, retain that lane and wait under its delivery contract rather than starting another.
   - **Reconcile delayed callbacks by their original handle.** When a predecessor's late failure arrives after a verified replacement is running, append a parent-labelled reconciliation and preserve the replacement's ownership. Do not restart the old task, stop the successor, or treat the delayed callback as the successor's result; asynchronous delivery can lag a completed ownership transfer.

### Local-helper routing safety

- Diagnose missing helper tools independently of injected plugin guidance. A plugin can register its prompt section unconditionally while an availability check hides the tool after a missing runtime import or policy refusal. Check the active source/gateway revision, the exact required module, plugin enablement and the backport's pinned base without invoking inference. Do not force an old pinned patch onto a newer runtime, clear shared deferral policy or change providers to conceal this dependency failure; preserve the diagnosis and qualify any separately authorized rebase before activation.
- Inspect effective routing before claiming local offload. Empty delegation route keys inherit the parent; auxiliary `auto` is not proof of localhost routing. Verify the installed resolver and plugins rather than relying on SOUL.md.
- Pin provider, endpoint identity, and model together. Prefer a resolved named local provider with its placeholder credential over setting only `delegation.model` or only `base_url`; the latter paths can retain the parent's provider or credential. Test with sentinel credentials, never real tokens.
- Verify failure routing separately for auxiliary calls and full child agents. Some installed versions permit explicitly pinned auxiliary calls to fall back to the main agent model. A localhost pin alone does not establish fail-closed behavior.
- Test the final HTTP wire, not just resolver outputs: inherited headers can carry credentials, extra_body can override model/token caps/tools, and middleware can rewrite a pinned request. Capture route, policy and parameters in one immutable snapshot; reject discovery routes after canonicalization. For a narrow tool-free local helper, prefer an independent loopback transport with no inherited headers/body, env proxies, redirects or recovery machinery. A guarded recovery ladder alone does not constrain resolution or request transformation.
- Enforce read-only worker access in runtime tool restrictions or isolation. In versions where `_build_children` passes `toolsets=None`, children inherit write-capable tools and the public task schema cannot narrow them; a read-only prompt is insufficient.
- Check OMH route compatibility before persisting a named custom provider. The installed OMH parser may reject provider identifiers containing parentheses, even when native Hermes accepts them.
- Check single-slot local-server ownership before helper inference. A resident alias and healthy router are not proof of an available worker slot or role qualification.
- Resolve re-exported auxiliary config readers to their current defining module before forward-porting loader guards. Preserve upstream inheritance and plugin/default behavior, and test malformed input through the real loader; pasting an old function over a new re-export can silently discard current semantics.
- Validate YAML root type before empty-document handling in both raw and merged readonly loaders. Only `None` denotes a blank/null document; `safe_load(...) or {}` can turn malformed falsy roots such as `false`, `0`, quoted empty strings and `[]` into defaults and lose a refusal marker. Cover actual loaders and inherited helper routes.
- Compare the actual caller-source hashes before revising a role contract. Reuse an independently reviewed contract when its bound callers are byte-identical; separately version/review a genuine caller change rather than silently refreshing pins or generating needless version churn.
- Assert a profile destination before creating fixture metadata. The installed named-profile resolver can remain installation-owned even with fixture `HERMES_HOME` and `HERMES_BASE_HOME`; exercise a private home's virtual `default` profile instead when its resolved home is verified. Preserve auxiliary settings when adding fixture model metadata, and never create a real user profile merely to test the describer.
- Report mocked resolver receipts as partial diagnostics when any check fails; discard contradicted assumptions. Imports can invoke bootstrap/update paths, so block networking and confine HOME/HERMES_HOME/cache writes in resolver probes.

### Bounded read-only review procedure

1. **Reuse the qualified runner and retained checkpoint.** Apply the authority/source checks above, then adapt the existing runner only where the current installed interface differs; rebuilding launch mechanics wastes budget before review begins. Inspect the selected launcher before using metadata flags in a no-host-change lane: even a runtime-command printer can enter shared checkout repair. Prefer the already-active interpreter and its resolved module-spec workspace for a process-local restricted worker when that avoids repair-capable bootstrap paths; record actual imports and leave shared launchers/configuration untouched. Query effective approval and fallback settings through `hermes config get`, using the prerequisites above rather than a new raw-configuration parser.
   When the runner relies on managed bootstrap, complete it before SDK imports, create-only output directories and preflight receipts. `hermes_bootstrap` can re-exec onto PM's committed store interpreter even when a venv symlink resolves to the same binary; SDK imports made earlier can be lost, and earlier output creation can fail on re-entry. An early-return preflight that never reaches the lazy bootstrap path does not qualify the real request. Resolve the store interpreter through the maintained launcher resolver or retain its verified preflight identity, and keep bootstrap/scaffolding failures separate from provider attempts. Use a durable script or `-c`, not stdin `-`, for probes crossing this re-exec: the relaunch path can treat `-` as a filename. After interruption, inspect retained preflight results and source bindings before retrying; preserve unknown OS exits rather than discarding valid proof or inventing a completed review.

2. **Qualify tool restrictions before the model request.** Validate the complete adapted packet against the runner's actual unconditional reads before launch: copying only source fingerprints can omit required fields such as `source_map`, `binding_mismatches`, `allowed_files` or `search_roots`. Derive required review coverage from the bound source manifest and pass it explicitly, for example as `required_source_paths`, rather than retaining the predecessor task's hardcoded filenames; otherwise a reused runner can validate the wrong scope despite a well-formed verdict. An empty tool allowlist does not remove bootstrap requirements. Run the offline preflight through the exact selected command/import bootstrap; a bare-interpreter dependency check can pass while the real script bootstrap loses its site-packages. Repair only the private adapter or its process-local import paths, preserve the failed attempt, and install nothing or change no shared settings merely to obtain a review. Record the active interpreter and dependency search directories separately: an isolated `-I` child can lose a venv site-packages directory injected into the running tool kernel even when the interpreter version matches. Reuse the named existing dependency directory through a process-local path after checking its module spec; do not reinstall a dependency that is already present or invoke a repair-capable shared launcher to recover it.

   Use ordinary `hermes chat -q/--query-file` with the effective single-query approval policy for restricted readers; do not add `--oneshot`/`-z` as a harmless explicit-exit flag. The inspected oneshot implementation automatically enables `HERMES_YOLO_MODE`. Reject approval-bypass state again in the agent constructor after CLI setup, as well as at bootstrap entry. Prefer a native interface that supports the required per-launch restriction. Otherwise, for an authorized CLI alternative, register a process-local toolset containing only `read_file` and `search_files`, with no included write-capable toolsets. Assert the emitted schema names equal that allowlist. Keep registration out of persistent profile settings. If a `timeit` wrapper is used, catch normal `SystemExit(0)` inside its snippet so wrapper failure is not confused with a successful preflight.

   **Use a zero-tool branch when the complete causal review corpus fits.** First trace the changed invariant to its callers and side-effecting helpers. Freeze the complete changed code and added tests, exact interacting dependency excerpts, semantic diff, original findings and required proof supports. Include constants, imports and dispatch seams needed to interpret those excerpts, with source-file hashes and line spans. Do not add entire unrelated subsystems merely because the context window can hold them: oversized packets increase review latency and interruption exposure without establishing more relevant coverage. Require complete text for the declared review scope, exact manifest identities, and room for reasoning and a terminal verdict. In the actual agent bootstrap, assert that emitted tool schemas are empty and exercise rejection through every reachable dispatch path before inference; repeat the tool/fallback checks after completion. Keep these controls process-local rather than changing shared routing or approvals. Require the verdict to echo the exact manifest/source identities, enumerate all supplied paths and name unassessed surfaces. Keep the original candidate fingerprint, the review snapshot's source-map fingerprint and the support-manifest fingerprint distinct: different path roots, record shapes, mode notation or serializers can legitimately produce different digests. Preserve the original manifest unchanged, validate every copied file's bytes and mode against it, compute the runner's fingerprint using its own declared contract, and require the verdict to echo both candidate and review identities rather than silently replacing one with the other. Label source inspection separately from parent-verified hashes and reused execution: an inline reviewer has neither recomputed file hashes nor run tests. If essential material cannot fit or is missing, use the qualified restricted-reader branch or retain HOLD instead of summarizing away the dependency.
3. **Assert the constructed agent's identity.** Before its first request, capture and verify the actual provider, model, reasoning effort, tool names and empty fallback chain. Reject a mismatch rather than accepting a dispatch label or silently switching providers; configuration can change between preparation and construction.

   Trace the live tool-execution call path before wrapping a dispatcher: a previously imported `run_agent.handle_function_call` alias can disappear during a runtime refactor. Guard the handler actually reached by the current executor, and exercise denied names and out-of-scope paths through that patched central dispatch, not only through a standalone access predicate. Requalify emitted schemas and a positive source read before inference; an unused wrapper is not an enforced reader boundary.

   Serialize process-local reader audit writes: parallel tool dispatch can race on a shared `.writing` path even when every source read is valid. Protect both audit-list mutation and atomic-save publication with the same reentrant lock, or use an equivalently safe writer. Reproduce the shared-temp rename failure with an offline concurrency regression, then verify the repaired runner before provider dispatch; keep logger failures separate from source-review findings.
4. **Dispatch a finite source task.** Pass the bound candidate manifest, exact delta including untracked files, requirements pointer and proof handles. Build the read allowlist around the interacting dependency closure, not only edited paths. Test admission of every explicitly required named artifact before inference: a prior verdict or incremental diff referenced by an index is not necessarily present in the underlying file allowlist. Supply mechanically generated, source-bound diffs for the complete actual changed-path set, including added versioned fixtures compared with their named predecessor; a diff of the unchanged predecessor proves nothing about the added version. Admit the precise old/new caller leaf files needed for comparisons rather than forcing a reader-only reviewer to hunt tiny whole-file differences manually. Resolve relative read/search paths against the declared lane root and pass that same validated absolute path to the actual handler; a resumed session can retain a different file-I/O working directory. Supply newly introduced artifact paths absolutely in continuation packets. Exercise positive scope checks with distinct read regions so legitimate duplicate-read protection is not mistaken for path denial; retain that protection. If an essential adjacent helper was omitted, bind its bytes/mode and admit only that named file rather than widening access to the whole home or changing shared permissions; read scope does not grant write ownership. Supply specific instruction-file paths and a discovery stop condition; repeated recursive ancestor searches consume the judgement budget. Require a structured verdict, cited findings and explicit could-not-assess surfaces. State that reader-only review cannot independently execute reproductions or recompute hashes; the parent must verify those bindings.
5. **Track the CLI process separately from its wrapper.** Record session ID, PID/PGID, transcript and deadline before waiting. Use a fresh private per-launch scratch child: a preflight or interrupted attempt may already occupy a generic scratch path, so preserve older directories rather than deleting or reusing them to admit a new run. For a foreground-only run, fit the worker and wrapper budgets inside the observed enclosing deadline. For a managed background run, give the worker its own task-sized deadline and bound observer waits independently; a short observation window must not truncate a valid long review. Follow native asynchronous delivery for children. When a managed terminal job hands completion watching to notifications, record its handle as the acceptance dependency, finish noncontending work and yield instead of repeating wait/status loops. On notification, verify the terminal verdict, controller exit and exact target readback before reporting application; automatic completion watching is not installation evidence.
6. **Recover only genuinely unfinished judgement.** Inspect the programmatic result's `completed`, `turn_exit_reason`, `failed`, `interrupted` and actual final verdict alongside host exit: an exit-0 wrapper and a saved JSON HOLD can coexist with `completed=false` after an iteration cap. Never promote process completion into review acceptance. Avoid arbitrary small iteration caps for a bounded review; use a finite objective and observed wall-clock budget. When a retained reader history is much larger than the remaining proof work, start a fresh compact successor with the bound partial judgment, completed source scope and exact missing artifacts instead of replaying the huge context or restarting discovery. On `agent_close` or another interruption, inspect the terminal result rather than inferring success from transcript growth. An interrupted result with empty text supplies no verdict. Confirm process-group death and source freshness before one same-session continuation, and provide only the remaining judgement plus retained read/proof handles. When source reading is complete but report emission was interrupted, request one bounded complete JSON object, use finding IDs across axes instead of duplicating finding bodies, and retain explicit unassessed surfaces; an output-size cap must not erase findings or turn incomplete scope into PASS. Keep a fresh evidence directory for the continuation and preserve the interrupted prefix as unaccepted evidence. Prefer a bounded foreground continuation when this caller's release would terminate a background job; use managed background completion only when its ownership/delivery survives that caller, and never enable persistence or weaken approvals without authorization. If a complete verdict already exists, verify and retain it instead of resuming for prose.
7. **Close from the complete evidence set.** Reserve distinct create-only receipt names for the wrapper's observed OS exit and the worker's application/model completion (for example, `process-exit.json` and `review-completion.json`). Check path ownership before launch: a worker's successful completion file can otherwise make the wrapper fail after `wait()` and lose its observed child exit. Preserve a collision and recover a complete source-bound verdict without overwriting completion evidence or rerunning the model for prose. Persist a completed verification child's exact exit immediately after wait/reap, before potentially slow repository/source audits; otherwise an outer observer timeout can erase the exit despite a full green log. Bound those control-plane subprocesses separately. Preserve a full green log with a missing outer exit as partial evidence, not an observed successful receipt. Stop new sandbox/test reproductions when an owned child remains in D-state or unreapable; record its PID/boot/wait channel and preserve the source checkpoint without weakening isolation or treating signal delivery as reaping. Inspect `/proc/PID/task/*/stat` before calling a zombie leader terminal: D-state sibling threads can survive beneath a Z-state leader, so an empty command line or leader-only check does not establish cleanup. At a user-requested reboot boundary, fsync the checkpoint and critical artifacts, preserve blocked thread/wait-channel identities, keep unaccepted updates inactive, and disclose possible shutdown waits rather than repeatedly signalling zombies or killing their unrelated parent. Check wrapper/child exits, no remaining descendants, one successful final result, unchanged source hashes/modes and the actual reviewer route together. Preserve unknown OS exit status when the wrapper died before recording one; a model's interruption event is not an observed OS exit. Keep review findings, test proof and integration approval separate even when all offline fixtures are green.
8. **Use the direct qualified subscriber route when its separate CLI account is credit-locked.** Resolve `openai-codex` through the maintained runtime resolver; require `codex_responses`, a first-party ChatGPT host, explicit model/Max effort and an empty fallback chain. Do not retry the known locked CLI/app-server or reload credits. Keep only `read_file`/`search_files` in a process-local toolset; guard central tool dispatch against other names, credential paths and paths outside named evidence/docs/research roots. Assert the constructed tool schemas before inference and after the result, and preserve constructor identity separately from the terminal judgment. A reader-only successor reuses identity-bound executed proof; it does not relabel interrupted reviewers complete or claim new executions.
9. **Do not treat dossier capacity as missing execution.** If an OMH completion checkpoint refuses for capacity, retain the refusal separately, read the live checklist back, and close only from verified original artifacts. Do not archive or delete other task histories merely to admit a current declaration. Keep blocker text within the runtime's observed 200-character cap; if validation refuses an overlong reason, shorten it without changing the actual gate and read back the saved blocked state.

### Cron (scheduled jobs)

Durable scheduler — `cron/jobs.py` + `cron/scheduler.py`. Drive it via
the `cronjob` tool, the `hermes cron` CLI (`list`, `add`, `edit`,
`pause`, `resume`, `run`, `remove`), or the `/cron` slash command.

- **Schedules:** duration (`"30m"`, `"2h"`), "every" phrase
  (`"every monday 9am"`), 5-field cron (`"0 9 * * *"`), or ISO timestamp.
- **Per-job knobs:** `skills`, `model`/`provider` override, `script`
  (pre-run data collection; `no_agent=True` makes the script the whole
  job), `context_from` (chain job A's output into job B), `workdir`
  (run in a specific dir with its `AGENTS.md` / `CLAUDE.md` loaded),
  multi-platform delivery.
- **Invariants:** 3-minute hard interrupt per run, `.tick.lock` file
  prevents duplicate ticks across processes, cron sessions pass
  `skip_memory=True` by default, and cron deliveries are framed with a
  header/footer instead of being mirrored into the target gateway
  session (keeps role alternation intact).

User docs: https://hermes-agent.nousresearch.com/docs/user-guide/features/cron

### Curator (skill lifecycle)

Background maintenance for agent-created skills. Tracks usage, marks
idle skills stale, archives stale ones, keeps a pre-run tar.gz backup
so nothing is lost.

- **CLI:** `hermes curator <verb>` — `status`, `usage`, `run`, `pause`,
  `resume`, `pin`, `unpin`, `archive`, `restore`, `list-archived`, `prune`,
  `backup`, `rollback`.
- **Slash:** `/curator <subcommand>` mirrors the CLI.
- **Scope:** only touches skills with `created_by: "agent"` provenance.
  Bundled + hub-installed skills are off-limits. **Never deletes** —
  max destructive action is archive. Pinned skills are exempt from
  every auto-transition and every LLM review pass.
- **Cost:** the deterministic inactivity/prune sweep runs for free. The
  aux-model "consolidate overlapping skills into umbrellas" pass is
  **off by default** — opt in with `curator.consolidate: true` or
  `hermes curator run --consolidate`. Routine background curation costs
  zero tokens.
- **Telemetry:** sidecar at `~/.hermes/skills/.usage.json` holds
  per-skill `use_count`, `view_count`, `patch_count`,
  `last_activity_at`, `state`, `pinned`.

Config: `curator.*` (`enabled`, `interval_hours`, `min_idle_hours`,
`stale_after_days`, `archive_after_days`, `backup.*`).
User docs: https://hermes-agent.nousresearch.com/docs/user-guide/features/curator

### Kanban (multi-agent work queue)

Durable SQLite board for multi-profile / multi-worker collaboration.
Users drive it via `hermes kanban <verb>`; dispatcher-spawned workers
see a focused `kanban_*` toolset gated by `HERMES_KANBAN_TASK`, and
orchestrator profiles can opt into the broader `kanban` toolset. Normal
sessions still have zero `kanban_*` schema footprint unless configured.

- **CLI verbs (common):** `init`, `create`, `list` (alias `ls`),
  `show`, `assign`, `link`, `unlink`, `comment`, `complete`, `block`,
  `unblock`, `archive`, `tail`. Less common: `watch`, `stats`, `runs`,
  `log`, `dispatch`, `daemon`, `gc`.
- **Worker/orchestrator toolset:** `kanban_show`, `kanban_complete`,
  `kanban_block`, `kanban_heartbeat`, `kanban_comment`, `kanban_create`,
  `kanban_link`; profiles that explicitly enable the `kanban` toolset
  outside a dispatcher-spawned task also get `kanban_list` and
  `kanban_unblock` for board routing.
- **Dispatcher** runs inside the gateway by default
  (`kanban.dispatch_in_gateway: true`) — reclaims stale claims,
  promotes ready tasks, atomically claims, spawns assigned profiles.
  Auto-blocks a task after `failure_limit` consecutive spawn failures
  (default 2; configurable via `kanban.failure_limit` or per-task
  `max_retries`).
- **Isolation:** board is the hard boundary (workers get
  `HERMES_KANBAN_BOARD` pinned in env); tenant is a soft namespace
  within a board for workspace-path + memory-key isolation.
