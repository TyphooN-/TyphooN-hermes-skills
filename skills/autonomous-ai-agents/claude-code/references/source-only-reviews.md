# Restricted Source-Only Analysis and Reviews

Use this recipe for independent source review, architectural synthesis from accepted evidence, or bounded investigation of a missing proof boundary when edits and execution are not authorized. It establishes reader-tool restrictions, not an OS sandbox or dynamic verification.

## 1. Freeze the target and declare the claim

Classify the input first. For a repository, record BASE and HEAD, the complete tracked/untracked overlay fingerprint, relevant source hashes, requirements and baseline/diff artifacts. For preserved non-Git media or evidence, record Git state as not applicable and use the admitted path/size/hash inventory; do not initialize Git or open original media merely to satisfy repository preflight. Give the reader an immutable snapshot, never a changing writer's tree. Recover unfinished findings as leads, not accepted verdicts; carry completed source-bound judgments at their existing qualified scope.

After extracting an archive, finalize or observe actual on-disk modes before producing every manifest and strict launch binding. Python `tarfile.extractall(filter='data')` can add owner read/write bits to regular files, turning archived `0400` into actual `0600`; never copy `TarInfo.mode` into a claim about the extracted file. Preserve and classify a prelaunch mode mismatch as configuration, then fix only the packaging metadata with all content checks intact—not the provider route or permission guard.

For a missing-source continuation, close the named evidence gaps before another review request:

1. Turn each missing-source finding into an inventory row: required symbol, defining module, actual caller/binding, supplied line span and source hash. Verify that the frozen packet contains the complete definition, not merely its import, declaration or dispatch site.
2. Follow imported siblings, dynamic method forwarding and alias bindings explicitly. Index definitions by module/class-qualified name and retain relevant enclosing-function and decorator spans; a simple-name AST match can supply a nested factory while omitting its outer return. Include the import/inheritance binding when a method comes from a mixin. Do not certify closure from an AST same-file traversal alone: it can miss the constructor helper that actually assigns initial identity or a restoration collaborator invoked through another module.
3. Supply complete relevant files or complete called bodies with context. Cover initial credential binding, fallback resolution, authority/locking, durable persistence and generation merge, reactive recovery, and restoration/reselection when those boundaries support the claim. Constructor dispatch does not establish binding, a guarded primary path does not establish fallback isolation, and snapshot creation does not establish restoration.
4. When test isolation is part of the evidence, include the actual import-time guards and imported credential/network/HOME filtering bodies, not only a fixture that delegates to them. Label executed proof, source inspection and unassessed boundaries separately; a large passing test count does not replace missing implementation or guard bodies.

Keep the inventory bounded to the causal path at the pinned revisions, not another whole-repository dump. Check that every named evidence obligation is present before dispatch; repeatedly enlarging a packet without that check spends another review on the same omissions.

Freeze and bind the expanded review input set while retaining the rejected implementation's identity separately; adding dependency evidence changes the review-input fingerprint, not the implementation fingerprint. Partition the prior findings into demonstrated defects and missing-source obligations. Require regression/fix proof for the former and evidence completion for the latter; source omissions alone do not authorize redesign. Assign the newly supplied call boundaries and affected findings, not another full-corpus discovery pass. Keep upstream source support distinct from installed binary/configuration equivalence, which these additional files do not prove.

### Assemble a multi-tranche architectural handoff

1. Select the accepted public judgments and the first unresolved architecture question. Verify their retained acceptance and manifest bindings before copying sources; preserve historical HOLD records without assigning them to the new reader as unfinished reviews.
2. Stage only the admitted reports and definitions needed for that question. Exclude credentials, private model reasoning, raw conversation dumps and unrelated evidence before traversal. Do not copy an entire verification tree or reopen an original binary to replace an already-qualified frozen definition.
3. Preserve each source set in its own namespace, such as `inputs/corpus/<component-group>/<original-relative-path>`. Copy source as bytes with `read_bytes()`/`write_bytes()` and verify each staged digest against its original before dispatch; text round-trips can normalize line endings and silently change the purported snapshot. Record a component-to-namespace map, original frozen path, staged path, byte length, SHA-256 and evidence role. Do not flatten identical basenames: different tranches can contain different versions of the same helper. Treat historical absolute paths as provenance, not instructions to read outside the admitted snapshot.
4. Freeze a manifest of the staged bytes and bind its own digest into the output schema. Retain original receipt identities separately from the new analysis-input identity. Run the reader with the private evidence directory as its working directory and explicitly admitted file scope, rather than launching inside preservation-restricted originals.
5. Direct the first reads to the accepted summaries and the relevant entry point or consumer, then allow focused definition reads. Supplying many files is not a request to reread them all. Ask for the exact nearest missing body, configuration input or semantic contract and its smallest discriminating proof, rather than another generic helper search.
6. Require an evidence-linked component matrix separating requirements established in the selected path, conditional dependencies and unknowns. Keep safe-omission fields null when unproved. Return the manifest identity, actual reviewed paths, reused-proof versus new-source-reasoning boundaries, open gates and one next decision. Label this result as an architectural assessment or proposal; it does not renew independent acceptance or prove runtime viability.

### Keep passive-assessment continuations compact

Supply a single boot-bound observation artifact with collection time, relevant signal matches, device/runtime fields, ownership and budget limitations, and receipt references. Include implementation source only for a specific unresolved semantic question; fields already marked unresolved do not require rediscovering unchanged code. After a reboot, preserve old observations as historical and refresh only the observations before requesting the unfinished final judgment. This prevents a Max-effort reader from repeating completed discovery while another interruption can erase its conclusion.

## 2. Match capabilities to the review

Check installed `claude --help` for restricted-mode support. Retain the skill's Opus-Max and included-subscription contract, and invoke with:

```text
claude -p --name "$SLUG" --add-dir "$EVIDENCE_DIR" "$FROZEN_EVIDENCE" \
  --model opus --effort max --output-format stream-json --verbose \
  --permission-mode auto --restricted --tools Read,Glob,Grep \
  --json-schema "$REVIEW_SCHEMA" \
  --strict-mcp-config --mcp-config '{"mcpServers":{}}' --no-chrome
```

Provide the complete task through stdin; do not insert a multi-file packet into one argv element. For a tracked Python launcher, construct argv with `-p` and the compact flags above, then use `with task_path.open('rb') as task_input:` around `subprocess.Popen(command, stdin=task_input, ...)`. Keep the task handle open through process creation and bind the packet's original bytes in the checkpoint. This avoids both variadic parsing and per-argument size limits while preserving the same frozen review inputs.

Add only required frozen source/evidence directories and exclude credentials. When moving a packet from a zero-tool transport to restricted readers, replace only obsolete transport/tool/output instructions in the new task header; preserve source identities, review scope and approval limits, and leave the historical packet unchanged. Require initialization tools to be a subset of `Read`, `Glob`, `Grep` and schema-only `StructuredOutput`; fail closed if execution, mutation, network or delegation tools appear. Restricted file tools are not an OS sandbox.

## 3. Use an output channel the reviewer actually has

Request a final schema-backed result rather than asking a reader-only worker to write `handoff.json`; granting Write to satisfy that request would weaken the intended boundary. Include ranked findings with paths/lines/evidence, reviewed paths and overlay fingerprint, correctness and spec verdicts, checked-clean surfaces, missing checks and the next decision. The parent persists a returned result after checking completion and bindings.

Keep source reasoning, previously executed evidence and fresh reproductions distinct. For quota/interruption-sensitive reader lanes, request concise public intermediate findings or scoped-clean summaries before expanding dependency reads; preserve them as incomplete judgments, not acceptance. Require a compact public contract row with the defining path/lines, established fact and remaining proof before moving to the next contract; narration such as "facts captured" is not a transferable finding. If a reader exhausts quota, preserve its public rows and source-bound completion/exit evidence, then continue the first unresolved admitted obligation without rereading its entire discovery transcript. Private thinking blocks and read-tool counts are not transferable review findings and must not substitute for a terminal verdict. Record tests that cannot be executed in this lane as missing; source analysis can establish a blocker but cannot prove cancellation, races, atomic persistence or resource bounds by reading green tests alone. Schedule any required reproduction in a separately scoped execution lane without silently broadening this reader.

## 4. Accept only the completed scoped judgment

1. Establish the actual top-level exit, absence of owned descendants and presence of the final result; preserve an absent result or unknown exit explicitly.
2. Validate the returned structured output against the frozen schema before interpreting its verdict. Declare required fingerprints and claim boundaries as schema `const` values with `--json-schema`, then independently check the returned values and identifier formats. A zero exit, required field names and unchanged source bytes do not establish that the report names the right inputs.
3. Recheck frozen hashes and reported reviewed paths against separate implementation and admitted-metadata inventories. Permit an explicitly supplied manifest or catalog to appear in `reviewed_paths` even when it is not an implementation-map key; verify that artifact's own retained digest and its internal map before admitting it. Classify a role-tagged reference such as `metadata:candidate.diff` through an exact admitted-metadata map and verify its target bytes; preserve the returned label rather than treating it as a repository path or rewriting the verdict. Keep metadata inspection separate from implementation coverage, because reading a manifest does not mean reading every file it lists. Persist accepted handoff data only after source, metadata and report bindings pass.
   - Partition bundled evidence by its declared proof kind before applying pair-specific schemas or totals. Numbered product-finding RED/GREEN pairs, retrospective tripwire mutants, workspace controls and invalid setup attempts can share one catalog without sharing fields or causal requirements. Require matching test and producer bytes for product-fix pairs; for a harness mutant, verify its explicitly declared producer mutation instead of counting it as another product repair. Preserve malformed or unclassified entries as unresolved rather than silently filtering them out.
   - Preserve fully qualified testcase identities when checking retained coverage, and label top-level tests, subtests and unique normalized AST assertion forms separately. If claiming unchanged assertion occurrences, compare an occurrence-aware inventory rather than only a set of forms, because set equality can hide removal of a duplicate assertion.
4. Classify a validation failure before requesting another model response. Check the verifier's coordinate base, inventory, schema and fingerprint serialization against the frozen contract; an implementation-only allowlist can falsely reject a correctly reported metadata read. Preserve the failed check and repair only the parent verifier when the original report already satisfies that contract, then validate the unchanged report without repeating inference. If the report itself has an invalid binding, retain it as rejected evidence rather than repairing its token in the parent. Preserve useful findings as leads and permit one bounded corrective continuation with the exact expected bindings and only unfinished source obligations; a binding typo is not a reason to repeat the whole review.
5. Reuse a valid terminal judgment only for matching final paths and its stated claim. Keep initialization, tool activity, partial notes and prepared schemas distinct from review completion, and never promote source-only reasoning into runtime or whole-project acceptance.

## 5. Reset the architecture after repeated failed fixes

1. Freeze the rejected candidate and retain its terminal findings, original requirements and valid prior proof. Assign a bounded design question instead of requesting another patch or repeating completed discovery, because another narrowed race window can leave the same invariant unsatisfied.
2. Use the restricted reader invocation above. Require source references, an assessment of each blocker, the smallest coherent design, alternatives and limits, a causal proof plan and the next required decision; do not grant writes or shell merely to produce the proposal.
3. Require the proposal to name the real publication/cancellation linearization point, failure model, recovery and reusable-success eligibility. Reject an unapproved redefinition of the commit boundary, because moving the final observation earlier does not establish what can happen before publication.
4. Require the ownership and concurrency contract relevant to the proposed change. For in-process binding swaps, identify coherent request capture, cancellation/shutdown serialization, and cleanup of newly owned resources without closing active or borrowed ones. For process/lease designs, require identity-preserving signalling through launch, leader exit/reaping, helper survival and lease release; numerical PID/PGID existence alone does not establish ownership. Do not impose process-specific proof obligations on unrelated state transactions.
5. Require deferred causal tests at the actual uncovered seams, with separate attempt evidence and deliberately broken controls. Distinguish preparation failure, refusal, cancellation immediately before publication, and required work after publication. Add actual identifier-reuse controls only where the design owns reusable process or lease identities; green tests of a different failure interval do not close the claimed seam.
6. Present the concrete architecture choice before another fix when it changes an unsettled compatibility, availability or security-policy contract. State the recommended behavior, affected legacy callers, safer alternative and exact decision needed; do not treat the proposal's own `approval_required` field as user authority. If only a source contract is missing, assign that named gap rather than repeating the whole proposal. Apply the SKILL.md execution-authorization rules to work already within accepted scope. Preserve the existing BLOCK until corrected source receives its required execution and independent acceptance, because a completed design proposal supplies neither.
