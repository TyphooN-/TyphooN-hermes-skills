# llama.cpp Upstream Refresh

## Portable scope

This copy preserves a locally developed workflow, not transferable approval. Resolve the current task, repository, active Hermes profile, tools and ownership on this machine first. Historical project choices and TyphooN-specific executor/build policies are context, not permission to start services, run targets, modify security settings or publish. Project-root variables are documented in the collection's `PORTABILITY.md`; unset variables are not usable paths. Installing a skill installs no external tools or plugins.

## When to Use

Use for local llama.cpp source/submodule refreshes, declared-patch forward ports and their build verification. This does not authorize public upstream contributions or live router activation.

## Workflow

This user's usual target is latest upstream `master`, not a linked release tag. Read the active repository's instructions, lock, patch verifier, build entry point and focused pin tests first; discover actual source/runtime paths instead of duplicating their configuration here.

1. Preserve parent/submodule HEAD, staging state, original binary diff and dirty-file hashes in private persistent evidence. Seed an isolated refresh with the current lock, declared patches and exact dirty source overlay, not parent HEAD alone: staged or working dependency updates can be newer than that commit. Pin the freshly fetched upstream SHA and its observation time; check release ancestry separately. On resume, distinguish finishing that selected snapshot from establishing the current upstream tip: query the validated source remote with `git ls-remote "$REMOTE" refs/heads/master`, retain the literal SHA and observation time, and refresh that evidence before declaring the latest-master request complete. If upstream advances during an owned build, keep its frozen source and outputs untouched; prepare the newer fixed revision in a separate source-only candidate instead of retargeting the running checkout. Select one observed tip per candidate rather than repeatedly chasing a moving branch during proof.
2. Forward-port declared patches in an isolated target checkout. Review actual conflicts, retaining new upstream parameters, callers and renamed test targets. Compare unchanged production additions/removals mechanically before reusing earlier review. Keep regressions intact. Before porting the convolution-kernel cast, grep the selected tip for `ggml_ssm_conv` call sites: a clean apply of the old patch misses model files added after that base, and those sites still need the shared F32 cast.
3. Regenerate the patch against the new base and update its path/SHA, lock and gitlink together. Run the maintained patch-tree verifier; clean status is not proof of the declared overlay. If a retained transfer patch differs from the current checkout diff, locate the regenerated patch referenced by the active candidate lock and rerun exact-tree verification against that candidate root and source. Forward-porting can change blob IDs and hunk positions; neither a loose patch mismatch nor matching selected-file hashes establishes the complete tree's correctness. Preserve the mismatch and its verified resolution instead of ignoring arbitrary diff lines or rebuilding an already correct overlay.
   - Guard untracked compiler inputs before both patched and clean/no-patch success paths: tracked-tree equality cannot detect a quoted-include shadow beside a source file. Enumerate with `git ls-files --others -z` without `--exclude-standard`; ignore rules can conceal source headers as well as build artifacts. Exempt only explicitly defined build-output roots using anchored patterns such as `--exclude=/build/`, never every ignored file or a broad directory-name wildcard. Exercise ordinary and ignored shadow headers with and without declared patches, plus allowed-output positive controls. Require unchanged real-index bytes and worktree contents on refusal; use `GIT_OPTIONAL_LOCKS=0` for read-only Git inspection so status refreshes do not rewrite the real index.
   - Prefer a proper worktree for isolated builds: copying a submodule directory leaves its relative `.git` pointer aimed at the wrong location. When recovering an already-built Git archive with a synthetic commit, compare every actual expected path's bytes and Git mode, including ignored/unindexed files. A fresh `git add` obeys ignore rules and can omit originally tracked archive files without changing their working bytes. Preserve the synthetic emitted build identity and bind it to the verified upstream/patch origin; do not relabel it as the upstream HEAD or rebuild merely to repair metadata.
4. Integrate only after preservation and focused proof. User-authorized Git native merge/switch may leave conflicts, stage reapplied changes or retain an automatic stash. Inspect its actual result; reconcile only owned index entries and tested files without changing working bytes or losing original staging intent. Do not discard a stash containing user work. When the exact-tree verifier proves that the entire dirty source is only the declared overlay, a bounded alternative is to preserve it, reverse only that patch, switch the now-clean source to the selected revision, and apply the verified forward-port. Check and journal every phase; require a recovery checkpoint if interrupted. Never use this route with additional user edits. Compare unrelated parent file hashes/modes and index entries before/after, and stage only the owned contract paths.
5. Inspect executable/library mappings before rebuilding a directory. Never replace mapped artifacts or restart the router merely to finish a source update. Do not start a HIP build while a native bench, or a dead PID still listed by `rocm-smi --showpids`, owns device memory; reclaim is not a GPU reset. Serialize builds, retain source/toolchain/boot/commands/exits per attempt, and treat a reboot-interrupted exit as unknown. Confirm owners are gone before resuming cached work. After reboot, reconcile actual files and worktree metadata even if a previous tool reported success; use atomic replacement with file and parent-directory fsync for small recovery records. A checkpoint on the same filesystem is not an independent backup.
   - During repeated abrupt reboots, flush the actual Git transition as well as its journal: fsync changed/new source files and ancestor directories, submodule HEAD/index/reflog, parent index, and newly staged lock/patch objects and their directories. A durable success record or fsynced lock can survive while an unflushed checkout and gitlink revert. Reconcile the observed generation against exact old and new source/patch preimages before repairing; do not replay the whole integration or reset unknown edits. Revalidate lock, HEAD, staged gitlink, complete declared overlay and preserved user work after reboot. Treat one observed persistence check as source durability evidence, not host-integrity clearance.
6. Run the concrete local regression and focused patch/backend/preset contracts against the newly built binary, not an old existing one. Preserve raw native logs and parse a display-normalized copy: strip ANSI CSI styling before matching status lines, for example `re.sub(r"\x1b\[[0-9;]*[A-Za-z]", "", text)`, because the harness can emit colored `OK` even when redirected. Require nonzero parsed testcase identities to reconcile with the producer's reported count; zero matches with a successful producer is a projection discrepancy to investigate, not an empty successful suite or a reason to rerun unchanged tests. Count pytest nodes, subtests, CTest cases and internal comparisons separately; match complete enum labels (`bf16` contains `f16`). When backend comparison counts differ, compare architecture/mode/dtype identity sets and trace the current compiled backend's source gates before declaring a regression or changing a hardcoded count. Keep CPU baseline counts separate from requested-device comparison counts: an explicitly selected non-CPU target must execute comparisons or return an explicit non-successful coverage outcome. Cover both discrete and integrated GPU selection when the API accepts them; accepting a device name before filtering out its device type can produce a false CPU-only pass. Do not equate a device-configured context with observed placement of the operation under test. Preserve explicit exclusions as coverage gaps; do not force an upstream-disabled architecture or claim all-architecture coverage from a nonzero subset. Inspect actual CLI contracts rather than assuming every tool supports `--version` or `--help`; retain invalid-probe exits honestly. Inspect test setup as well as module descriptions before calling a suite offline: `PresetCompatibilityTests` in the upstream-pin suite executes `llama-server --help` when a binary exists. Explicitly deselect binary-backed cases while execution admission is held, including after integration into a checkout with old artifacts. Canonical-path service/launcher contracts can legitimately fail in a disposable worktree; preserve those failures, run the portable subset there, and rerun the unchanged offline suite at the canonical path after integration. Do not rewrite production paths or weaken assertions merely to accommodate the temporary checkout.
   - Map every required build target to its CMake option before trimming a private configuration. Some locked tools live under `examples/` (for example, `llama-gguf` under `examples/gguf`), so `LLAMA_BUILD_EXAMPLES=OFF` can remove a required target even when tools are enabled. Keep the needed gate on and build only explicit targets; classify Ninja's unknown-target exit as configuration failure, correct the option, and resume the owned cache without modifying already-reviewed source.
7. Investigate compiler ICEs before editing source. Preserve the exact failing translation unit, compiler argv/version, phase log, boot and resource counters, then verify its bytes against the selected upstream plus declared overlay; an internal compiler assertion is not a demonstrated application-code defect. Unrelated translation-unit crashes plus kernel faults establish neither a source defect nor a specific hardware cause. For an admitted alternate-toolchain attempt, use a fresh private build directory and rebuild the complete runtime closure: pin C/C++ compilers and compatible linker/archive tools, including LTO support, rather than mixing old objects or libraries with the new frontend. Reuse the existing resource controller and reviewed optimization flags; do not clear shared caches, replace mapped binaries or patch unchanged source merely to hide the crash. Run the focused native regressions against that new closure and bind its version, commands, exits and artifact manifest. Preserve the original failure even if the alternate succeeds: success supplies provisional build/test proof, not proof of the original cause or host clearance. Bind faults to the observed boot and do not apply another project's waiver.
8. Separate source/lock update, CPU/HIP build, real-model qualification and live activation. Before reporting “tracking latest,” compare the fresh remote SHA with the primary working pin/gitlink, staged contract and isolated candidate separately; a master branch label or an in-flight private refresh is not an updated primary pin. If integration is held, name which copy is current and which remains behind. Preserve service/configuration and commit/push gates. Back up unique forward-port changes, confirm no process uses the owned disposable worktree, then remove only that worktree; leave other owners' checkouts alone.

## Build supervisor recovery

- Persist command exits and progress independently of stdout. Use an EXIT trap or supervising finally for fail-fast shell scripts; a trailing success-only write cannot record a failure under `set -e`. An observer can close its pipe after a command succeeds; preserve the controller's BrokenPipeError separately, reconcile every planned phase against its recorded exit, and resume only missing proof rather than recompiling completed phases.
- Distinguish failed launch plumbing from failed compilation. A background login shell can stall in `mise activate bash` before the prepared runner enters; use its missing entry artifacts and exact descendants to establish that no compiler/test was dispatched. Inspect threads behind zombie leaders after cancellation, and do not bypass confinement or start another native job while an owned uninterruptible thread remains.
- Track cgroup leaf creation, limit setup and entry as owned prelaunch operations with an outer observer and exact process generation; persist the current stage before each potentially blocking cgroupfs operation, not only before migration or compiler launch. A preparation process can itself block before any build starts. A timeout execed only after cgroup migration cannot bound a blocked migration. If owned tasks remain in D-state at `cgroup_kn_lock_live`, stop new builds/sandbox probes, fence only verified owned processes with pidfds, preserve unreaped ownership and pending signals, and require host recovery before another attempt. Signal delivery is not reaping; never bypass confinement or alter host settings to escape the stall.

## Cache-free recovery and approved activation

- Reproduce the failing HIP translation unit with the installed ROCm compiler and its cache launcher bypassed before editing source. A successful clean build with `GGML_CCACHE=OFF` and empty compiler-launcher settings supports a recovery path, not proof that the shared cache caused an earlier crash; boot and toolchain changes are confounders. Preserve the partial build instead of clearing shared caches.
- Validate version output using stdout plus stderr. A zero-exit `--version` may print entirely to stderr; do not reject a correctly staged runtime merely because stdout is empty.
- Hash the complete versioned runtime closure against its build manifest, including relative SONAME symlinks and the implementation libraries used by modular llama.cpp executables. Preserve the previous user-service drop-in before a separately approved cutover.
- Verify user-service changes by reading the exact drop-in back, checking health, then observing the serving parent and model child executable/library mappings. A `/proc/<pid>/exe` read immediately after restart can race process startup: retry the read after readiness without another restart, permission changes or privilege escalation. Union child IDs from every `/proc/<pid>/task/<tid>/children` file: a router can fork models from worker threads while its main thread's children file stays empty.
- Compare the preset file bytes and inference settings before/after activation. Preserve raw catalogs, account explicitly for ephemeral child ports resetting on restart, and trace any newly injected logging option to upstream source before accepting it as a non-inference delta. Never ignore arbitrary argument or preset differences.
- Keep a successful bounded model load/decode smoke test separate from comparative model qualification and host-integrity clearance. Save an atomic recovery receipt and the actual response before declaring activation verified.
