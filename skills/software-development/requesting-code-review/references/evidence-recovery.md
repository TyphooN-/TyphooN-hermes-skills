# Recovering source-bound verification and review evidence

Use this recipe when an executor stops after useful work, a reboot interrupts review, or a broad receipt catalog appears stale. Recover only the missing obligation; preservation and passing tests do not supply an unfinished independent verdict.

## 1. Establish the exact frontier

1. Match the notification to the recorded delegation/session ID and source generation. Check managed ownership and matching processes before assigning a replacement; a delayed predecessor callback is not current replacement liveness.
2. Inspect the artifact inventory, then read the actual draft or terminal verdict. Do not guess a single draft filename: an incrementally saved draft may have a numbered name.
3. Verify current and frozen source hashes/modes, index baseline, retained logs and their receipts before crediting earlier proof. Record the absence of a terminal result explicitly; do not promote a nonterminal HOLD to acceptance.
4. Reduce the producer-ordered receipt catalog into a recovery matrix: exact argv/selectors, executed and failed testcase identities, actual exit, log-hash validity, relevant input matches and any superseding execution. Retire an earlier failure only for identities covered by a newer valid pass with the intended assertions intact; keep uncovered broader checks pending. Resolve this matrix before reading an old traceback as the current defect, because a saved draft can lag both a fix and its passing regression.
5. Preserve original inputs and controller records. If a catalog binds their bytes, append a superseding parent record instead of changing their status.

Completion criterion: the next executor receives an explicit list of verified reusable checks and unresolved review obligations, not a transcript or an instruction to rediscover the task.

## 2. Validate the verifier before sweeping evidence

1. **Inspect schemas before coding the adapter.** Read a representative receipt and catalog through `read_file`, or reduce their JSON with `execute_code`. Confirm top-level mapping/list shape, field types, and one representative row for EVERY distinct object kind. Inspect optional fields by kind: a symlink row can legitimately have `path` and `target` without a regular file's `mode`, byte length or digest. Keep absence distinct from zero or success.
2. **Build an explicit coordinate map.** Resolve artifact references against their declaring evidence root, candidate rows against the declared candidate root, and command `source_manifest` rows against that command's recorded `snapshot`. Admit absolute paths only under the allowed declared roots and reject unintended escapes. Do not recursively interpret every path/size/hash triple as an artifact reference; identical field names do not give embedded rows the same base.
3. **Validate objects without following unintended aliases.** Use `lstat` to check the declared kind. For regular files, verify actual size, original-byte hash and the declared mode. For symlinks, compare `readlink` with the exact declared target without statting or reading the target; require mode only when its schema supplies it. Compare modes in their documented representation: use `stat.S_IMODE(info.st_mode)` against numeric modes, and identify the encoding before parsing string modes. Do not convert a missing field into evidence corruption or silently skip an unknown kind.
4. **Reconcile fingerprint methods before their values.** Keep original manifest-file hashes, candidate fingerprints, command-source fingerprints and packet fingerprints separate. Reconstruct each using its producer's exact row projection, list ordering and serialization. A candidate fingerprint may include modes while a run fingerprint omits them, so unequal digests alone do not prove stale source. Compare complete, duplicate-free per-path `(size, sha256)` rows and verify modes separately wherever required; preserve both original fingerprints instead of normalizing either to the other.
5. **Qualify the verifier on representative bindings.** Check a regular file, a symlink with its actual schema, an evidence-root artifact, a snapshot-relative source row, and any distinct fingerprint methods before sweeping the catalog. Reuse the saved command's exact pinned interpreter, argv, selectors and isolation when execution is actually needed; do not translate it into a guessed unittest module invocation. Python isolated mode ignores `PYTHONPATH`, so that variable cannot repair a speculative import path.
6. **Sweep once and report compactly.** Use a named, lintable verifier after syntax/schema/type checks. Reconcile declared path totals and exact command/log/source bindings, and emit one bounded audit summary with verified counts and actual mismatches; retain full inventories privately. Preserve a failed verifier and use a new version when its bytes are already bound by evidence. Correct an observer-only schema or coordinate error without changing inputs or rerunning otherwise valid behavioral suites, because an adapter failure is not a reproduced product defect.

For untracked additions, calibrate `git diff --no-index --check /dev/null <path>` through `terminal` with disposable clean and trailing-whitespace controls. A clean content addition can return exit 1 with empty diagnostics, while a whitespace-error control can return exit 3 with diagnostics. Inspect actual output and preserve both controls and true exits; neither stage files nor weaken whitespace checking to avoid a normal difference exit.

Completion criterion: the adapter can validate representative positive, expected-refusal and preservation records without changing their inputs, and any no-index whitespace checker distinguishes a clean difference from a real diagnostic.

## 3. Classify each binding mismatch

| Binding category | Reuse decision |
|---|---|
| Production code, selected test, transitively loaded helper, fixture or generated input | Require an exact match to the relevant producing version; otherwise rerun the affected check. |
| Recorder, launcher, private-environment checkpoint or native/tool input used by the check | Verify the recorded version and environment association; a valid source hash alone is insufficient. |
| An unrelated test captured by an all-files recorder | Exclude only after tracing actual imports/callers, dynamic discovery and fixtures. Record the exact path/reason and separately exercise its changed version. If relevance is uncertain, rerun. |
| Documentation or metadata | Determine whether the test loads it or it changes the acceptance contract; extension alone does not establish irrelevance. |
| Boot ID, PID or live runtime identity | Refresh runtime observations before qualification or activation. A changed boot alone does not invalidate intact source-only proof. |

Do not declare a whole test history stale merely because one unrelated test changed, and do not relabel an old receipt as a full current-tree run. Build a small required-input matrix and publish the reuse decision alongside the unchanged original receipts.

## 4. Resume with separate roots

Keep four paths explicit: writable candidate, frozen review source, new evidence output, and private fixture HOME. Reuse an intact frozen snapshot rather than recopying or mutating it merely to obtain new labels. Copy/version a runner only when necessary and explicitly retain its source-binding root; its location-relative evidence path and its reviewed source path are different authorities.

Before the first profile-aware import, qualify the complete private outer environment with a harmless probe. Put any new boot/control metadata in the new checkpoint; do not refresh an old checkpoint whose hash existing launcher receipts bind. Use fresh labels for genuinely new checks, not reruns of already valid cases for prose.

Give the replacement reviewer the prior HOLD, exact reusable receipt pointers, source manifest and remaining scope. Require a small discriminating executed check before a large new harness, and checkpoint actual inspection/proof after each batch so another interruption does not erase the frontier.

### Correction generations after a source BLOCK

Use this branch when fixes are authorized and a complete terminal BLOCK supplies an actionable source trace, even if its remaining review scope is unfinished.

1. **Preserve the judgment and transfer ownership.** Validate the reviewer result, exact candidate identities and process completion. Leave its source, manifests and verdict immutable. Seed a separate writable candidate from those exact bytes; assign corrections to the implementation owner, not the independent reviewer. Carry the prior BLOCK and its unreviewed remainder into the next task.
2. **Save the inputs before running RED.** After adding the discriminating regression, retain the exact source and test versions, modes and hashes before changing either again. Run the maintained guarded checker with a fresh evidence label and retain its argv, cwd, host exit, receipt, log and failed identities. Finalize type-narrowing and fixture assertions before the retained RED where possible. If regression-test bytes change afterward, preserve the earlier check and recapture RED against verified pre-fix production before claiming a byte-identical RED/GREEN pair; use a disposable baseline if the writable production source has already changed. State whether it exercises real behavior, lexical source guards or a separate synthetic oracle; a source-bound oracle does not become execution of the implementation it models. If preimages were not saved, reconstruct only from a verified baseline and retained delta, require exact agreement with the original RED receipt hashes, and label the reconstruction as preservation rather than a new execution.
3. **Make preservation guards admit only the authorized edit.** If a test promises an inherited prefix is preserved, keep the old preimage, byte length and digest fixed. Construct the expected new prefix by applying explicit context-qualified before/after replacements to that preimage, requiring the exact expected occurrence count at each site. Compare the whole constructed prefix with the current prefix, not just the edited lines. Derive the appended-code boundary from `len(expected_prefix)` rather than the old byte count, because even a literal correction can shift the suffix. Do not strip whitespace, accept arbitrary differences or replace the historical digest with the current file hash to obtain GREEN. Exercise the revised guard against disposable mutations outside the authorized replacement set, including removal of a relevant refusal condition; require the intended preservation testcase to fail rather than error during setup. Label these as source-text mutation controls, not execution of the native implementation.
4. **Verify the complete corrected generation.** Check inherited-path drift against the saved baseline and inspect both the incremental correction and complete original-base delta. Preserve unrelated helpers and previously accepted components. Run the focused regression and the appropriate full suite after all source, test and guard changes; bind each receipt to its actual inputs. Deduplicate testcase identities across focused and full runs rather than adding a subset to the full-suite total.
5. **Reuse the qualified review machinery, not old candidate identities.** Regenerate source/input maps, the complete review packet and schema constants for the new frozen generation. Keep the existing qualified worker/controller when their runtime and enforcement contract are unchanged; do not rewrite the launch and validation scripts for each small source fix. Keep the original candidate manifest, review source-map fingerprint and support-manifest digest distinct. Supply complete current interacting sources, the aggregate delta, original finding and relevant proof; do not forward the full implementation transcript or describe manifest-only artifacts as reviewed bodies.
6. **Require completion of the original source scope.** A successor may issue another fail-fast BLOCK with a newly explicit remainder. PASS must cover the complete assigned current source scope, not merely confirm that the previous defect is fixed. Respect the main skill's bounded correction limit. Once a complete source PASS and its bindings validate, advance that source component and preserve its immutable checkpoint; let separate build, native, host and publication gates govern their own next actions.

Completion criterion: the original failure remains recoverable, the correction has source-bound proof, preservation guards still protect unassigned bytes, and the next independent verdict states exactly which complete scope is accepted or still unresolved.

### Refresh a derived custody catalog

Use this branch when a pin refresh leaves duplicated metadata stale while the independently reviewed implementation remains byte-identical. A correctness PASS and a metadata/spec HOLD are different judgments; preserve both instead of calling the code rejected or the whole candidate accepted.

1. **Freeze the mismatch and its canonical inputs.** Retain the original verdict, manifest, preparation and accepted-source identities. Seed a separately owned writable candidate; do not repair a frozen review set in place. Parse the preparation as data rather than importing its producer, because a nominal metadata loader can have side effects.
2. **Make consistency the regression.** Compare every derived immutable-input row with the pinned preparation's path, byte length, mode and digest, then verify those declarations against the actual files. Check the preparation file's own binding separately. Require exact inventory agreement and reject duplicate paths; checking only operational manifest entries misses a stale explanatory catalog. Preserve the intended failing identities and pre-fix bytes before mutation.
3. **Regenerate only the stale metadata.** Derive replacement rows from that same preparation and the actual preparation bytes. Preserve code, tests, recipes, policy text and unrelated manifest entries. If any of those also need changes, expand the declared correction and proof closure instead of labelling it metadata-only.
4. **Exercise and bind the corrected generation.** Run the consistency regression and the affected existing guarded suite with exact commands/exits and fresh receipts. Compare the complete candidate against its preimage and record the exact changed-field set; a passing catalog check alone does not establish that implementation bytes stayed unchanged.
5. **Re-review the changed claim, not an unchanged corpus.** Freeze the corrected manifest under its new digest. Give the approved independent reviewer the original finding, complete old/new catalog and preparation, actual consuming functions, preservation comparison and source-bound proof. Reuse earlier correctness judgments only for matching bytes and scope; require a new independent judgment for the corrected metadata before any new review/admission binding consumes its digest. Never refresh an old frozen verdict or admission to imply approval.
6. **Reconcile the original acceptance boundary.** Compose the new scoped judgment with the retained prior judgments and outstanding requirements. A metadata-only PASS supplies neither compiler/native execution, host clearance nor publication authority; keep those gates separate and open where required.

Completion criterion: all duplicated catalog bindings agree with their pinned inputs and actual files, the original mismatch and causal regression remain recoverable, unchanged implementation proof is preserved, and independent acceptance identifies the exact corrected generation.

## 5. Interpret and publish the result

Validate expected status per command. An installed pipeline can deliberately reject malformed or unsupported input and then prove last-good preservation and recovery; that nonzero child exit is not the same as a failed test wrapper. Bind the expectation to the source assertion and retain the actual exit sequence.

Count fresh and reused proof separately using command, relevant environment and source generation. Do not add repeated executions of the same methods to inflate coverage, or combine unit-method counts with native scenarios and static assertion scripts.

Publish supporting manifests, checks and preservation artifacts before the terminal verdict references them. Label parent-created packaging as recovery evidence, not a newly authored independent judgment. A parent summary or successful checker cannot supply a missing verdict; a complete original independent verdict may supply that judgment after the validation in section 6. Keep any unreviewed remainder at HOLD and preserve live-data, installation, activation and publication gates independently of a source-only PASS.

## 6. Recover a completed verdict after report-finalization failure

Use this branch only when the model's complete judgment survives in its saved result and the wrapper failed while packaging it, such as enforcing a compact-report size preference. Do not restart source discovery or request a shorter judgment merely because its artifact was not emitted.

1. **Establish completion and classify the failure.** Match the worker/session, retain the wrapper's actual exit and error, and confirm its process/group has ended. Locate the saved model result before launching anything. Trace the failure to the reporting check; an earlier source, permission, runtime or missing-proof failure is not a size-only refusal.
2. **Validate the actual result schema.** Require terminal model completion, a complete final response and no failed, partial, interrupted or iteration-capped result. Where the runtime exposes `completed`, `failed`, `partial`, `interrupted` and `turn_exit_reason`, check those fields under that runtime's contract rather than defaulting absent fields to success. Parse the complete `final_response`; never invent closing tokens or promote partial JSON.
3. **Validate the independent judgment itself.** Check its explicit verdict, complete assigned scope, unresolved surfaces and exact source identifier against the frozen contract. Recheck candidate/frozen bytes and modes and the required evidence bindings. A malformed identifier, missing semantic scope or required support still needs correction or HOLD; packaging recovery cannot repair those by inference.
4. **Preserve the original response verbatim.** Save the original `final_response` UTF-8 bytes to a new private artifact and verify byte-for-byte equality with the retained result. Do not reserialize a shortened object and call it the original report. Keep the original result, failed wrapper artifacts and input preimages unchanged.
5. **Publish supports before a compact parent index.** Bind the full verdict, model result, constructed route, restricted-reader audit, observed exit/error, source manifest and new preservation audit by exact path, size, mode and file SHA256. Verify every declared binding. Then publish a small parent acceptance record referencing that complete independent judgment; identify its author as the parent and retain the real failed wrapper exit. A successful recovery checker is a separate exit, not a replacement worker success.
6. **Close only the proved scope.** Read back the exact full verdict and parent index, verify all support bindings and record the recovery without another model request. Preserve the reviewer's PASS/BLOCK/HOLD and all broader runtime, integration and publication gates. A read-only reviewer may rely on explicitly parent-verified hashes; do not relabel those checks as independently executed by the reviewer.

Completion criterion: the original complete judgment is preserved unchanged, its exact source and required supports are verified, failed execution/reporting history remains visible, and the compact parent record introduces no new findings or authority.

## 7. Recover an altered frozen review set

Use this branch when a previously reviewed source snapshot, its manifest or bound qualification evidence was modified in place. Internal checksum agreement is insufficient: an edited source and an edited catalog can agree while no longer representing the reviewer's inputs.

1. **Check the external binding first.** Compare the manifest file's actual SHA256 with the exact manifest digest recorded by the retained reviewer verdict or parent acceptance. Then check the referenced source hashes and modes. Preserve expected and observed identifiers exactly; do not recompute a source fingerprint and overwrite the old claim.
2. **Preserve and label the affected evidence.** Leave the surviving snapshot, manifest, verdict, reports and logs unchanged. Write a new parent-labelled integrity notice identifying the broken bindings and the acceptance scope that can no longer be credited. Do not restore old bytes over the altered set merely to hide the mismatch, or reinterpret the old PASS as approval of the newer code.
3. **Separate candidate preservation from historical recovery.** Record the current writable candidate's HEAD, index, complete tracked/untracked owned paths and hashes in a fresh evidence directory. Use retained original preimages only after validating their independent bindings. If original reviewed bytes cannot be recovered, report that gap rather than inventing a baseline or discarding useful current edits.
4. **Reuse only demonstrably intact proof.** Apply the dependency matrix in section 3 to checks whose original source, producer, environment and log bindings still validate. An unchanged module may retain valid proof; an altered manifest does not justify either blanket reuse or blanket invalidation. Require a new source-bound independent verdict for changed or unprovable review scope.
5. **Version qualification attempts instead of recycling outputs.** Give every genuinely new run fresh output, log and report paths, including after a preflight-only failure. An existing directory or exclusive-create error is not permission to delete earlier evidence. Refresh runtime associations in a new parent record after their prerequisites are revalidated, not by replacing old guard hashes.
6. **Keep the gates distinct.** Treat a real-data run of unaccepted source as diagnostic evidence only. Its exit cannot renew independent acceptance or authorize installation. Resume guarded integration or activation only when the revised source, applicable review, qualification and user approval all bind to the same candidate.

Completion criterion: the integrity failure remains visible, useful current work is preserved separately, reused proof retains verifiable original bindings, and no stale judgment is promoted to approval of changed source.

## 8. Compact review inputs without changing evidence or coverage

Use this preparation recipe when formatted JSON or duplicate source bodies dominate a bounded review packet. Input qualification does not prove that a smaller or partitioned review will finish, and it never supplies a missing independent verdict.

1. **Bind the original scope first.** Verify the whole manifest against its retained external digest, then validate its required paths, sizes, hashes and relevant modes. Keep this original inventory immutable; give compact copies their own manifest and digest.
2. **Compact only JSON review copies.** Parse the complete admitted JSON, serialize with `json.dumps(value, ensure_ascii=False, separators=(',', ':'))`, and verify the copy preserves the original parsed structure and value types. Preserve array order and strings exactly. Refuse duplicate-key, nonstandard-number or precision-sensitive inputs unless the selected parser/serializer preserves their semantics; otherwise send the original bytes. Preserve non-JSON source as exact UTF-8 bytes rather than stripping whitespace, comments or line endings.
3. **Record both identities.** For each copy retain its original path/size/SHA256, review-copy path/size/SHA256 and the precise transformation. Verify equality before freezing and again when admitting the result; a copy digest must not replace an original receipt digest.
4. **Alias only genuinely identical source bodies.** Match the original byte hashes, retain each original path's mode and role, and expose the complete alias list to the reviewer. One inspected body may cover those explicitly bound aliases, but it is not several independent inspections or fresh test executions.
5. **Declare projections precisely.** For a selected JSON subtree or instruction window, bind the full source hash and exact pointer/extent, retain guards, assumptions and unresolved frontiers, and compare every supplied value against that selection. Do not credit a small return-contract view as inspection of the complete helper graph. Compute the union of actual whole-file and explicit partial coverage; list gaps instead of inferring that filenames or prepared packets establish review completion.
6. **Exercise the transformation predicates without hash masking.** Use clearly synthetic mutations to change a scalar, remove a field, change identifier case, alter plain-source bytes or line endings, and corrupt projected entries. Require the relevant equality/selection predicate to reject each mutation independently of whole-file hash refusal. Include a positive compact-JSON whitespace/object-key-order control while preserving array order. Bind these results as parent preparation checks, not reviewer executions.

Completion criterion: copied values and source identities validate, aliases and projections have explicit coverage, and original-path/content/execution counts remain distinct. Preserve whole-milestone HOLD until the required complete independent judgment exists; validated preparation or a component-only PASS is not aggregate acceptance.

## 9. Bind journal evidence after a reboot-interrupted review

Preserve the original `/proc` boot UUID, validate its canonical format, and select the matching observed 32-hex ID from `journalctl --list-boots`; pass that exact observed token as `--boot=<id>`. Some versions reject dashed UUIDs or interpret a separate `-b` argument as a match. Retain parsing refusals as missing evidence, not as a clean empty journal. Correlate saved reviewer launch/progress times with the correctly bound kernel records, but do not infer the exact reboot cause, model failure or host recovery from temporal correlation or a quiet current-boot sample.
