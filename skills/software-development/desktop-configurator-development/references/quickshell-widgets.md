# Quickshell bar widgets and usage panels

## 1. Discover the installed contract before editing

Resolve the actual command, plugin manifest, QML implementation and active bar entry. Read packaged sources without modifying them. Inspect the active user widget ID rather than assuming it is still the stock ID; a supported clone can replace that ID while retaining its origin in manifest metadata.

For a missing usage tab, check these in order:

1. Enumerate installed collector commands and the widget's actual usage-record directory, honoring HOME/XDG paths.
2. Read provider enabled flags in the active bar entry.
3. Read the collector discovery loop and the widget's provider-admission predicate.
4. Inspect only non-secret identity/status/count fields from existing records.
5. Compare the CLI's own quota display with the panel's source. Treat screenshots as observations, not values to hardcode into a collector.

Do not diagnose a missing integration as failed login: authentication, collection, publication and tab visibility are separate stages. A provider with a real quota window can be visible despite no calls in the current session; an exhausted allowance is not missing data. Check whether a displayed percentage means used or remaining before transforming it.

## 2. Clock precision and format changes

Trace the displayed format through its SystemClock precision binding. Use Qt tokens correctly: `HH:mm:ss` is 24-hour time with seconds; uppercase `MM` represents a different field. Preserve existing date/day components and quoted literals when transforming time tokens.

Use the supported plugin-clone mechanism when package-owned QML needs a new precision binding. Resolve stock and manifest-backed clones consistently in all clock options so changing precision does not break date or 12/24-hour controls.

- Strip Qt quoted literals before detecting a real seconds token; literal `:ss` must not force second-resolution refresh.
- Choose second precision only while seconds are actually displayed, because permanent second ticks add unnecessary refresh work.
- Validate the expected precision declaration and refuse ambiguous or unfamiliar custom code, because textual replacement is not a general QML transformation.
- Back up supported custom files and preserve line endings; normalize only explicitly owned content.
- Verify tick intervals with a headless Quickshell runtime, not just a string assertion. Also verify the minute-only and quoted-literal cases.

## 3. Publish provider records without replacing the panel

Read the installed collector and renderer contracts for fields such as provider ID, limits, recent days and per-model usage. Inspect which fields the UI actually uses to admit providers and construct totals. Do not fabricate sessions or activity merely to force a tab to appear.

Inspect the updater's discovery path before installing a custom collector. If it enumerates only a package-owned directory, a command in the user's bin directory will not automatically join refreshes. Use an independent opt-in publisher or a supported user extension point, and atomically replace the provider JSON record in the watched state directory. Keep cloud collectors unchanged.

A supported user clone may be needed to show pending/error states or unknown days. Preserve custom clones, validate each expected source replacement exactly, refuse existing staging destinations, and update the clone's identity/IPC strings consistently. Keep original styling and controls. Check whether the renderer truncates model rows before promising a complete breakdown.

Exclude machine-local observer records from cross-device snapshot export and aggregate import when their intended scope is this machine; merged zero-filled histories can destroy unknown-day semantics as well as mixing measurement scopes.

## 4. Collect counters with honest semantics

For llama.cpp router observers, first establish the authorized observation phase. Under metadata-only scope, send no router or worker requests; use the qualification procedure in section 5.1. Only during a separately authorized live phase, verify installed routing behavior and list models without requesting configuration reload. Route admitted per-model metadata requests with `autoload=false` and skip unloaded/loading models, because GET requests may otherwise load a model and consume GPU resources. Do not treat `autoload=false` as a guarantee against waking a sleeping worker; establish the endpoint-specific sleep prerequisite separately.

Treat native prompt counters as evaluated tokens when the source excludes cached input. Do not label them full request input or add Hermes local-route event totals to router samples, because those observations overlap. For the requested combined Cloud + Local summary, select remote cloud ledgers once and the sole Local sampler once; retain a sampled/partial scope rather than claiming exact billing usage. Establish a baseline on the first observation rather than assigning a worker's lifetime counters to today.

Identify model-process generations with boot identity, PID and start time; counter-decrease detection alone misses a replacement worker whose new counter exceeds the old one. Check identity before and after a read. Persist snapshots and day/model deltas in one transaction, enforce one collector per ledger, bound retention/model cardinality, and retain valid history when collection fails.

Inspect metadata GET semantics separately from no-wakeup admission. A pinned `/metrics` handler may reset scrape-averaging buckets even though cumulative counters remain monotonic and no model wakes. Under a strictly observational/read-only qualification, reuse detached existing observer history instead of silently adding such scrapes, and record live throughput as unmeasured. A no-reload model-list observation with all models unloaded does not justify loading one for proof or claiming current-worker argument coverage. When detached copies are authorized, copy only validated owned regular main/WAL files without locking or opening live SQLite, require stable metadata and matching second-read hashes, preserve raw copies, and run integrity/migration/render checks on separate private working copies; never reconstruct legacy sample counts from token totals.

Label polling as sampled/best effort. Model unloads between polls can lose increments, and midnight-crossing intervals cannot be split exactly without completion events. Keep unrecorded days distinct from recorded zero counts and preserve first/last sample coverage. Exact request accounting requires an event ledger, not a claim layered over polling.

When the user asks for tokens this week, expose a local-calendar Monday-through-now aggregate separately from the rolling last seven days. Preserve coverage/freshness and evaluated-input versus generated-output semantics; never backfill unobserved use or add overlapping Hermes and engine totals. Tie live tok/s to the current worker/task generation and observed interval, and label reported engine averages or last-completed-request rates separately. Sanitize /slots in memory because raw replies can contain prompts; persist only bounded allowlisted numeric/state/model metadata.

### 4.1 Offline canonical accounting adapters

Use this sequence when repository implementation is authorized but live runtime/database access is not. It proves an explicit-input producer/consumer contract, not actual user-history ingestion or independent acceptance.

1. **Resolve the producing runtime as metadata.** Identify the active profile, launcher/interpreter and source overlay before inspecting the usage schema. Use maintained launcher metadata, such as `hermes --print-runtime-command` where supported, without bootstrapping the runtime or selecting credentials. Inspect only the relevant normalizer, persistence schema and callers; do not widen into auth stores or raw session transcripts.
2. **Write the semantic contract first.** Trace persisted counters back to canonical normalization. In a contract separating uncached input, cache reads and cache writes, include them once in prompt totals; do not apply that formula to raw provider input that already includes cached tokens. Do not add reasoning again when it is an output subset. Preserve missing values separately from explicit zero, and require nonnegative integers and JavaScript-safe component and aggregate sums.
3. **Keep identity and dates honest.** Define the provider/profile/route/aggregate identity used for deduplication and publication. Exclude local-route usage already covered by the Local sampler, and select provider aggregates or their account ledgers once. Treat first/last timestamps as coverage bounds, not permission to allocate an aggregate to every date or a particular credential. Retain undated/unattributed history; label subsequent observed deltas as observations rather than reconstructed request events.
4. **Accept explicit offline inputs.** Exercise documented JSON exports and, when supported, immutable SQLite snapshot bytes in an isolated in-memory database, for example with `sqlite3.Connection.deserialize`. Bound input bytes and row work, validate the exact supported schema and reject malformed/duplicate data. Use synthetic or separately authorized frozen inputs; do not discover/open the live database with `mode=ro`, because that can still touch WAL/SHM state. Snapshot creation from live files is a separate authorization and consistency step.
5. **Test the real producer-to-consumer path.** Inspect the producer's CLI before choosing flags. Resolve the consumer's actual watch path and basename under isolated HOME/XDG, and assert that the producer's explicit output destination is that exact owned fixture path before interpreting native totals. A successful export to another filename proves serialization, not FileView delivery; distinguish this fixture mismatch from a product ingestion defect. Invoke the producer with the qualified interpreter, `-B` and explicit owned input/output destinations, then load its actual publication through the real consumer. Include a valid zero, missing counters, cache/reasoning overlap, duplicated aggregate identities, local/cloud overlap, unknown dates, malformed/privacy markers, component overflow and sum overflow. Require whole-record rejection rather than a silently truncated ledger. A manually constructed consumer fixture is supplementary, not evidence the producer can ingest anything. For filtered history, publish one measured-zero source and one newly baselined source, select the latter, and execute the actual generated status-label expression. Require unknown summaries/bars and a baseline label, with measured-zero and empty-selection positive contrasts; a global-state label can otherwise contradict correctly filtered numbers.
6. **Verify publication separately.** Exercise bounded sanitized output, private atomic replacement, failed writes, unsafe links and input-preimage preservation without targeting the real scanner. Keep raw endpoints, prompts, credentials and session identifiers out of records and diagnostics. Validate source IDs and provenance at both publication and admission; an opaque-looking ID alone does not establish distinct historical events.
7. **Close only the exercised level.** Record exact argv, exits, source/producer/log bindings and exclusions, and fsync logs before publishing receipts. Describe an offline adapter as implemented and exercised, not connected to actual user history. Keep independent judgment, authorized live export/ingestion, installed maintenance and rendered UI proof as separate gates; ask only for the smallest missing live authority after finishing admitted offline work.

### 4.1.1 Persistent source-file association across reboots

Keep immediate open/path replacement fences separate from a persistent association. On Btrfs, `st_dev` can be an anonymous mount number that changes across boots; do not persist it as the sole filesystem component of a source identity. For supported Linux filesystems, qualify descriptor-derived `os.fstatvfs(fd).f_fsid` together with the explicit path, inode, owner, mode and link count. Python exposes `f_fsid` as an integer here, not a byte string: validate its type/domain instead of calling nonexistent `os.statfs` or packing the integer with a string-format specifier. Refuse an unavailable/unsupported stable identifier rather than weakening the fence. Same-process descriptor/path comparisons may still require `st_dev`.

Version a changed persistent scheme and upgrade a legacy export only when its complete legacy binding matches the current source. Retain the association token, counters and journal while adding the stable witness; never guess/brute-force a prior device number, auto-adopt a mismatch or delete history to make it pass. Prove device-only changes, actual file/filesystem/owner/mode/path replacements, malformed IDs and failed-upgrade last-good preservation with synthetic fixtures. Qualify the accepted producer on explicitly authorized real input, install through its existing guarded path, then read back the stable scheme, retained token, monotonic prior rows and journal continuity. Label simulated reboot proof separately from an actual reboot; do not reboot merely for acceptance without approval.

### 4.1.2 Admit compatible canonical schema evolution

1. **Identify what the version governs.** Compare the active runtime's maintained schema declarations and migrations with the adapter's supported version and exact ledger expectations. A global version can advance for unrelated worker/runtime tables; neither reject compatible accounting forever nor accept arbitrary future versions on that assumption.
2. **Make the upgrade discriminating offline.** Seed a supported synthetic database, produce a valid publication and retain its association, baseline and observed history. Apply the additive schema change without altering usage semantics, then require successful ingestion and retained identity/history. Include a subsequent counter increment so preserving stale output cannot masquerade as accepting the upgrade.
3. **Keep admission narrow.** Add only the independently established compatible version to the explicit allowlist and retain exact ledger column/type checks. Reject empty, multiple/ambiguous, malformed and unknown version declarations and ledger-shape drift. Require refusals to preserve last-good publication and state; do not delete history or establish a new identity to make an upgrade pass.
4. **Finish proof before real input.** Preserve the failing regression receipt, run the corrected CLI regressions and relevant accounting/history/delivery suites, and obtain review bound to those source bytes. Keep broader-suite timeout recovery separate from semantic failure. Real-input qualification remains a distinct authorized gate, not permission to inspect live SQLite during offline diagnosis.
5. **Prove installed continuation.** After authorized guarded replacement, verify the same association and history remain usable and observe the ordinary scheduler publish again. Follow selective managed helper repair below; this closes canonical ingestion only, not calibration or popup behavior.

### 4.2 Diagnose token-count and account-attribution discrepancies

1. **Identify the actual source inventories.** Resolve the live generated QML, its maintained generator, and each published record's producer before comparing numbers. Keep native CLI transcripts, Hermes canonical usage, account quotas and Local samples distinct. Inspect bounded nonsecret schema, counter, freshness and inventory metadata; do not open auth stores or raw conversations to explain a display mismatch. A shared provider name or login does not make native CLI history Hermes history.
2. **Reproduce account copying at the display seam.** Exercise the actual display helper or generated consumer with two distinct synthetic principals and one provider aggregate. Assert that neither account inherits the aggregate unless an independently supported attribution/deduplication contract exists. A provider record without account leaves cannot supply either credential's measured tokens; remove that fallback rather than copying the same total onto every card. Preserve a defect-reproduction result separately from the regression asserting safe behavior.
3. **Compare components and scope, not headline totals.** Apply the canonical rules in section 4.1, calculate cache-read versus generated-output components with tools, and state each source's recorded coverage. Large cached-context totals are not newly generated output or proof of a larger subscription allowance. Do not turn aggregate first/last timestamps into daily events or compare unmatched lifetime histories as a plan benchmark.
4. **Check current published policy before interpreting quotas.** Follow the official pricing page's current canonical redirect and distinguish live text from stale search snippets. Separate credit rates from included subscription allowance; even published per-token credit prices do not establish a fixed weekly raw-token budget or invert a mixed workload into a token count. Keep current rates out of standing calibration logic unless the product explicitly needs a versioned rate card.
5. **Correct the maintained path and verify each deployed link.** Change the assigned generator/collector and its tests, not a second manual live implementation. Verify the exact installed helper, any separate feed unit, its current public output, the consumer's watched path and the rendered provider list after authorized installation. An active Local collector does not establish that canonical Hermes accounting is scheduled, publishing or consumed. Preserve missing sources rather than skipping them merely to clear a partial-coverage warning.

### 4.3 Acceptance requirements for opt-in quota/token calibration

Treat these as design and acceptance requirements, not evidence that a calibrator has been implemented or qualified.

1. **Record the passive-only scope.** Reuse existing sanitized quota publications and canonical cumulative usage; do not generate benchmark conversations, load models, rotate accounts, read credentials or spend extra tokens to obtain samples. Keep implementation, real-input qualification and live activation separately authorized.
2. **Define identities and units before learning.** Key state by sanitized principal and quota-window/reset identity, never display-slot order. Establish whether the producer reports used or remaining percentage. Define freshness, counter domains, quota resolution, sampling bounds and sufficient-data rules before emitting a number; the first observation is a baseline, not dated historical usage.
3. **Prove learning is reachable at the configured cadence.** Inspect timer and producer observation-clock cadences as data, then replay them with a synthetic clock through the full required learning span. Assert earned sample counts, accumulated token/quota deltas and the eventual eligibility transition. Hand-picked long intervals alone miss implementations that advance their learning baseline on every short poll and therefore never qualify. Keep this reachability regression separate from proof of any proposed repair; do not lower admission thresholds merely to populate the display.
   - Diagnose retained-state validity, committed-export association, canonical freshness and sanitized-quota freshness independently before proposing recovery. A valid journal with disappeared source identities is a conservative continuity refusal, not corruption; stale inputs can mask that later guard. Read the existing producer cadence and use a bounded passive observation rather than forcing quota fetches, manufacturing clocks or deleting state to make the check pass. Keep any explicit journal-only recovery separate from canonical-history authority, and resolve a newer conflicting no-rebaseline limit before spending an older exception.
   - Preserve producer-declared inventory/manifest basenames exactly, including extensionless dotfiles. In passive wait loops, record failure phase and reason; retry only expected stale/transient conditions rather than swallowing assertion or snapshot-copy failures until the final stale tick masks the real harness defect. Retain the failed receipt and replay only the missing qualification, not already-passing guard cases.
4. **Withhold unsupported attribution.** Reject or rebaseline stale/missing/out-of-order observations, counter decreases, resets, inventory changes, long gaps and simultaneous or ambiguous account activity. Evaluate unresolved usage before duration-based early returns: positive tokens without visible quota movement must not leave old rates eligible simply because that pair was too short or too long to sample. Under a conservative clear-on-unresolved contract, clear retained samples and require fresh usable segments; test that a later rounded quota tick cannot omit earlier unresolved tokens. Treat apparent exclusivity of quota movement as correlation, not proof that Hermes caused every change; disclose other clients, delayed quota updates and changing model/cache mixes as limitations. Never transfer a learned rate between principals merely because their plans match.
5. **Keep estimates visibly separate.** Label any usable result estimated and workload-dependent, with sample count, observation span and an honestly defined range. Display `calibrating` or an actionable unavailable reason when requirements are unmet. Never add estimates to measured Cloud/Local totals, charts or token ledgers, and never present a weekly extrapolation as recovered credential history or a published entitlement.
6. **Exercise joined clocks and timestamp precision.** Drive the actual generated consumer with producer-valid fractional reset timestamps; preserve the producer's precision instead of widening equality tolerances around JavaScript millisecond parsing. Test a fresh outer envelope with an older required quota observation, missing/nonpositive/future component clocks, and expiry driven only by the display clock while the file remains unchanged. Require the earliest observation/reset deadline to win.
7. **Exercise the real seams before activation.** Use isolated explicit-input fixtures through the actual CLI and generated consumer. Cover distinct principals, missing input, baseline/learning/estimate transitions, ambiguous activity, stale/reset/quantized observations, identity reordering, repeated snapshots, malformed numeric types, overflow, bounded retention and last-good recovery. Reconcile documented byte/cardinality limits with maintained constants and actual reader caps. Require source-bound review and real sanitized-input checks before passive installation; passing synthetic learning cases cannot prove that real per-account calibration has occurred.

### 4.4 Failure-isolated collector ticks and provider merges

Use this sequence when a sampled Local publisher joins optional Cloud history or CLI-derived daily records. Keep sampling, primary publication, optional ingestion and combined publication as separate failure domains.

1. **Stage the complete merge before changing shared state.** Validate every incoming day, counter and aggregate sum, including JavaScript-safe bounds, before appending a source or cell. Reject the optional contribution as a whole if a later row fails; do not leave an inventory entry or a valid-looking prefix behind. Preserve established source-overlap exclusions.
2. **Recompute derived coverage after the merge.** Apply the real consumer's partial/unknown rules to the final inventory and each affected day. Run the actual resulting JSON through the maintained consumer with complete Local coverage and no canonical Cloud providers, canonical Cloud without the incoming provider, and an already-present provider. Include measured-zero, overflow and malformed-later-row controls; arithmetic checks alone miss whole-record coverage rejection.
3. **Commit an ingestion stamp only after success.** Treat a missing optional pathname separately from other `stat` failures. On expected read, validation or SQLite-transaction failure, preserve retained days, mark that optional feed unusable and leave it retryable. Replay the identical inode/mtime/size after clearing a one-shot failure; changing the fixture file would hide premature stamp consumption.
4. **Contain primary record/publication errors in run mode.** Catch expected OS/SQLite failures around those operations, continue the normal sampling cadence and independent roll-up work, and update the published-value cache only after a successful write. Log the exception class once per continuous failure class, clear that suppression after recovery, and omit arbitrary exception payloads. Keep one-shot operation failure exceptional/nonzero rather than silently returning success.
5. **Drive recovery through the real entry point.** Execute the CLI/main loop in a private HOME/HERMES_HOME/XDG fixture; mock signal registration and use a bounded sleep sentinel to stop after the required ticks. Inject one failed record/write followed by success and assert a real output appears on the next tick. Separately prove that an optional-ingest failure still permits Local output, that an unchanged failed projection retries, and that a synthetic private error marker never reaches stderr.
6. **Preserve discriminating proof.** Save RED receipts before the fixes, then focused GREEN and the appropriate complete producer/consumer suite with exact child exits and source/log bindings. Separate harness failures from product regressions; passing offline recovery tests neither supplies independent review nor authorizes installation.

## 5. Verify without touching the live desktop

Run numeric/source-contract tests in isolated HOME/XDG fixtures. Mock cloud refresh commands and privileged/desktop/service operations; reject unexpected calls rather than allowing mocks to fall through to the host.

Cover quota inversion, missing history, event/counter deduplication, worker replacement with larger counters, regressions, local-calendar grouping, persistence, malformed schemas, identity races, concurrent writers, retention and atomic publication. Test secrets with explicit fixture markers and ensure they cannot reach records or diagnostics. Use observed/documented schemas rather than inventing a provider API; unfinished provider discovery is not a validated recipe.

Use the installed Qt tooling to parse staged QML; resolve its binary location instead of assuming PATH contains it. A formatter's successful parse proves syntax only. A headless Quickshell harness loading the native data model can prove provider discovery, quota-only/pending visibility, seven-day fields and local-only sync behavior. Replace the cloud updater with an isolated no-op command in that harness.

Keep final proof categories separate: offline parser tests, native QML syntax, native data-model runtime, live counters, and rendered popup QA. Activate only at the authorized boundary, then read back the exact installed record/widget and inspect the actual popup before claiming live completion.

Correlate asynchronous playback timing with a track/availability generation, not just a song ID: A-to-B-to-A and absence/reappearance can make an obsolete ID match again. Keep same-ID metadata refreshes valid. Exercise the production IPCRequest completion handler using a private controlled stdin-JSON helper; an observation-only alias in a disposable Service copy can expose its completion signal without replacing the handler. Require actual helper completions, fresh-response positive controls and natural Qt.quit, rather than crediting direct acceptTiming calls as asynchronous proof.

Disable service activation explicitly on fixed-destination D-Bus reads that promise to observe only an already-running app. For busctl, pass --auto-start=no; read-only Properties.GetAll alone does not enforce that boundary. Inspect the actual subprocess argv through a private absent-owner fixture and preserve successful typed-snapshot controls; do not test activation against the live session bus.

Keep native Quickshell fixture paths short enough for its full UNIX IPC socket path, not just the fixture root:

1. Inspect the effective outer TMPDIR, inner fixture prefix and Quickshell-added runtime/by-id/ipc.sock suffix before launching; nested wrappers consume the same pathname budget.
2. Allocate unique fixtures under the runtime-approved scratch root with short outer and inner prefixes, for example `tempfile.TemporaryDirectory(prefix='a-', dir=scratch_root)`. Shorten disposable wrapper names or remove an unnecessary nesting layer rather than moving fixtures into system /tmp.
3. Retain the assertion rejecting `Failed to start IPC server`. Preserve the failed receipt, bind the retry to unchanged source/candidate hashes, and rerun the affected scenario after correcting only path plumbing. A printed QML result followed by a nonzero exit is not acceptance.

### 5.1 Read-only deployed-collector qualification

Use this procedure when source acceptance is complete but installation, endpoint requests and live rendering remain prohibited. Finish the feasible qualification once; new blockers are findings, not permission to repair or activate.

1. **Freeze the source and authority.** Save HEAD, raw dirty state/index binding, reviewed feature hashes and the exact allowed actions in private evidence. Preserve the independent verdict and its source/receipt/producer/log bindings; do not rerun unchanged matrices merely to obtain a fresh summary.
2. **Resolve the deployed entry points.** When service metadata reads are authorized, use `terminal` with selected `systemctl --user show <unit>` properties such as `MainPID`, `FragmentPath`, `DropInPaths` and `ExecStart`. Capture and project the response before printing: retain needed helper paths and nonsecret launch-policy fields, not raw units, arbitrary argv, environment values or logs. Resolve the selected plugin from layout/manifest metadata and the publication destination from the installed collector's parser; do not infer a directory from a service name or execute a stager to discover it.
3. **Refresh runtime identity.** Read boot identity and the relevant `/proc/<pid>/exe`, `stat` and child metadata without executing the engine. Bind each observation to boot, PID and start ticks; use only stable identity fields for before/after comparisons. Consume argument values according to the version-matched lexical declarations before projecting names or safety values. If no child exists, record eligibility as unobserved instead of manufacturing a loaded-model or idle claim.
4. **Bind the actual runtime.** Hash the running executable and relevant libraries listed in its process maps against the same-build manifest. Match the specific parser/status source files to that manifest's revision; a small launcher binary can match while its implementation library differs. Record missing provenance honestly and label a local build-manifest association as such, not as reproducible-build attestation. Keep earlier-boot argv evidence historical even when the runtime files still match.
   - Check the filesystem's identity semantics before requiring `/proc/maps` device numbers to equal `stat().st_dev`. On Btrfs, maps can expose the superblock device while stat exposes a subvolume anonymous device. Preserve a failed generic comparison and prove the narrow equivalence using the shared mount namespace, longest matching Btrfs mount's device, subvolume stat device, exact kernel `map_files` link and inode, and pinned file hashes. Never accept a guessed device offset or drop identity checks. A denied `map_files` dereference does not authorize privilege or security changes; pathname/inode/current-file binding is not a hash of mapped memory.
5. **Inspect destinations without collecting.** Check ledger/publication ancestors, node types, ownership, link counts and writability with metadata reads only; do not change modes to make checks pass. Do not open live SQLite even with URI `mode=ro`, because auxiliary WAL/SHM activity can violate the no-write boundary. Compare schema expectations with isolated legacy-ledger fixtures and leave live database integrity unproved. If publication reads are allowed, bound their bytes and emit only the numeric/state/schema allowlist derived from the real producer and consumer fields, never raw status, model, prompt or account records.
6. **Prove static compatibility safely.** Inspect the deployed formatter, its actual plain-text/wrapping surface and refresh source. For pure parser/path checks, inspect module initialization first, invoke Python with `-B`, and install guards before importing: deny sockets and SQLite connections, restrict subprocesses to exact approved metadata commands, and confine writes to evidence. Never invoke collector, render-only or publication entry points on live state. Treat audit hooks as protection for that controlled Python proof, not confinement of arbitrary descendants or a same-user sandbox; use the maintained isolated harness for broader fixtures. Plain-text field compatibility does not prove the canonical rich component, freshness expiration, watch delivery or popup geometry.
7. **Close with scoped evidence.** Compare the frozen source/index and nonsecret helper/unit/plugin/layout bindings; record natural ongoing publication or reboot-related metadata drift separately from lane writes. Persist the actual command exits, producer/log hashes, omissions and target verdict. A successful verifier may emit HOLD when worker coverage, safe endpoint eligibility, migration or rendered acceptance remains unproved. Name the next approval gate without installing, waking a model or restarting inference to satisfy it.

### 5.2 Offline worker-argument compatibility acceptance

Use this procedure for a bounded engine-option coverage extension, not for live collector qualification or a generic parser rewrite.

1. **Freeze the complete candidate and source pin.** Bind the original-base delta, owned source/test/docs, exact modes and link text, raw index and relevant engine declarations. Match current and frozen content before handing ownership to the reviewer. Check read-only snapshot modes against the producer's documented write-bit removal, not against an assumed package mode.
2. **Establish lexical semantics from pinned source.** Inspect option names, aliases, arity, normalization and split/attached-value handling without executing an engine. Separate proving token consumption from validating the engine's payload: a flag-looking or nonnumeric value can be a useful synthetic boundary control without being a valid launch. For zero-arity Boolean flags, test attached-value refusal; for one-value options, test missing, empty and packed-short forms against the actual source contract. Do not normalize consumed values into option names.
3. **Exercise real admission and mocked request paths first.** Run a small discriminating fixture with realistic admitted launches, genuine explicit disabled-sleep controls, option-shaped consumed values, duplicate/conflicting identity or sleep fields, and generation changes. Assert the exact requested routes and forbid `/slots` unless the unchanged unique disabled-sleep prerequisite is proved. Include admitted positive contrasts because a fixture that refuses everything can otherwise appear safe. On refusal, retain the loaded row and synthetic recorded history, report activity unknown, and assert that privacy markers never reach output.
4. **Use a source-frozen offline runner.** Inspect a prior runner before reuse: a producer using `Path(__file__).parent` may write into its historical evidence directory. Derive a newly named producer/launcher in the new reviewer-owned directory, mount source/base/engine/interpreter read-only, deny networking and host commands, and make only the synthetic fixture writable. Save exact argv, exit, timeout and source/producer/log bindings; fsync logs before publishing receipts. Preserve setup failures and replay only the aborted scope after an isolation-preserving correction.
5. **Recover proof without laundering provenance.** Reuse intact prior matrices after checking every source generation, producer, log and receipt binding. Inspect actual receipt shapes before comparing them: producer hashes may be strings or objects, and source paths may be snapshot-relative or absolute. Match historical RED/GREEN source bytes to their own receipts, not only the final candidate. If a named launcher changed, validate the retained content-addressed original and label historical-byte verification separately from current-path preservation. Recount marker populations from raw logs without rewriting original receipts; report static AST/pin checks separately from behavioral cases.
6. **Close the independent source gate, not the deployment gate.** Save a draft immediately after the first executed proof, finish the full original-base review and remaining provenance/preservation checks, then issue terminal PASS/HOLD/BLOCK with source references and reproductions. Bound schema coverage explicitly: supported new flags do not prove arbitrary future argv safe. A clean offline verdict does not qualify current workers, production ledger integrity, live counters, installed freshness or actual popup rendering.

### 5.3 Compact pinned totals and native lazy popup proof

1. **Preflight the current native shape.** Resolve the live shell's source first, then invoke the inspected stager's non-mutating `render(source, plugin_id)` in an isolated environment. Record native Main/Panel/manifest and imported Ui/Commons bindings with the producer/test hashes. If native input changed, preserve old receipts as historical and refresh the affected proof before installation; auditing every old log first wastes the executor's allowance.
2. **Pin the accounting contract.** Sum known remote Cloud counters and Local sampled counters once. Select provider aggregate OR account ledgers, never both. Do not add Hermes local-route observations to Local samples or count CLI aliases as extra accounts. Reject unsafe integer sums; show unknown when no counter is known and partial coverage when some are missing. Test duplicate providers, account roll-ups, shared CLI aliases, missing versus measured zero and combined overflow. Do not discard retained source histories merely to remove their redundant UI row.
3. **Keep the visible summary compact.** Use Total, Cloud and Local breakdowns; omit the extra Codex CLI row. Keep totals outside both rotating summaries and the scrolling body. Put scope/cache/coverage explanations in a plain-text tooltip rather than repeated card paragraphs.
4. **Support complete eager/lazy layouts, not one loose anchor.** Eager panels fit `header.implicitHeight + gap + column.implicitHeight`. Lazy panels fit `panel.loadedContentHeight`; their loaded root's `implicitHeight` must include that same header + gap + body. Anchor the Flickable below the pinned header. Retain native work-area fitting without a fixed cap, and reject duplicate, missing or mixed eager/lazy anchors.
5. **Mirror the lazy API in offscreen fixtures.** A plain Item stand-in needs native `content: Component`, a cached Loader, `loadedContent`, `loadedContentHeight` and first-open activation. Keep the Loader active after closing. Call the public `Panel.open()` rather than assigning readonly `opened`; open before waiting for provider Texts, because a lazy tree does not exist at startup. Prove startup remains unloaded, first-open layout is correct and the same header object survives reopening.
6. **Assert geometry and actual labels.** On a tall fixture, require every provider card and footer to fit with zero scroll. On a short fixture, require overflow scrolling with the header still pinned. Verify the combined bar count in horizontal and vertical layouts, PlainText sinks, missing-counter cases and preserved quota/model controls. Require `Qt.quit()` plus child exit zero, not only a printed marker.
7. **Apply and inspect at the authorized boundary.** Generate one managed candidate, bind its exact files to final proof, use guarded replacement, and read back the installation. Open the enabled clone through exact-PID IPC and capture the actual settled card; a fullscreen layer can register before its fade-in paints content. Preserve an early empty capture as diagnostic evidence, not visual acceptance.

## 6. MPRIS music timing and live widget upgrades

- Inspect real MPRIS values before designing a QML fixture. Qt can expose `metadata["mpris:trackid"]` as an opaque `QDBusObjectPath` QVariant that serializes to an empty string; a primitive-string mock misses this failure. Do not fall back to title/album matching when exact IDs are required.
- Decode exact player/track identity through a typed, read-only `busctl --user --timeout=1s --json=short call <player> /org/mpris/MediaPlayer2 org.freedeselta.DBus.Properties GetAll s org.mpris/MediaPlayer2.Player` snapshot when the Qt wrapper cannot expose the object path. Interpret `o` track paths and signed `x` microsecond counters explicitly; reject malformed, negative, mismatched, and unrepresentable values. For Supersonic 0.22.1, derive the expected path from UTF-8 base32 with `0` replacing padding, not from titles.
- Bound subprocess reply bytes and whole-call time, kill and reap only the spawned reader on failure, suppress raw diagnostics, and prevent overlapping timing requests. Reject completions overtaken by an IPC track change. Keep missing timing distinct from zero and clamp position to a known positive duration.
- Verify recurring sampling in the native QML fixture by observing multiple helper invocations, rather than only a timer declaration or first successful value. Match live-check expectations to playback state: Playing advances; Paused remains stable. A failed unconditional advancement assertion while paused is a faulty probe, not a demonstrated player defect; correct and rerun it explicitly.
- Preserve managed-plugin hashes, custom modifications and existing configuration during an authorized live upgrade. Stage a fresh candidate, back up the exact previous plugin, guard against concurrent changes, and verify installed bytes match the tested source.
- Check actual live geometry and rendered labels after a user-plugin update. Registry rescan can report reloading while cached components retain old widths/code; if the authorized hot reload has failed, use `omarchy restart shell`, not a configuration reset or inference-service restart. Verify both monitors when both display the widget.
- Treat a successful native panel `open()`/`opened` contract as necessary but not proof of a visible popup. Inspect the actual popup surface and placement separately before declaring dropdown controls or live library selection accepted.
- Hide unavailable-app widgets through item visibility and zero implicit dimensions; verify the native loader slot also has zero size. Keep status polling independent of visibility, close popups on disappearance and guard programmatic opening while hidden. Prove automatic return with a real timer-driven IPC fixture, not just a manual state assignment.
- Parent visibility-test widgets to a visible offscreen FloatingWindow. A detached widget beneath ShellRoot can remain effectively invisible even when its own visibility binding is true, producing misleading failures. Reject geometry binding-loop warnings; use a separate TextMetrics measurement instead of a Text width binding that reads its own implicitWidth.
- Resolve the active shell process and use `quickshell ipc --pid <pid>` for exact-target checks. Packaged-source paths can differ from the actual launch checkout; a no-instance error for another path is not evidence the live shell stopped.

## 7. Hermes-owned Codex accounts in an external widget

- Inspect the installed Agents multi-account contract before building another account UI. Native Omarchy accounts and Hermes credential pools are separate registries; multiple Hermes logins are not automatically discovered by the stock Codex collector.
- Resolve the active Hermes home and installed runtime before reading its pool schema. Do not use a pool load/select or credential resolver as a supposedly read-only inventory: those paths may seed, rotate, refresh or persist credentials. Limit discovery to a bounded, regular-file JSON snapshot and print only necessary non-secret metadata.
- Identify Codex principals by both the JWT's `chatgpt_account_id` and `sub`, never the workspace/account claim alone: different members can share a workspace but have distinct quotas. Validate each claim for its actual sink: a subject used only in a principal hash is a bounded opaque identifier, not an HTTP-header value. Permit legitimate punctuation such as `auth0|synthetic-subject` while rejecting empty, oversized and control-containing subjects; retain strict token, account/residency-header and expiry validation. Pin both acceptance and malformed negatives with synthetic tokens. Decoding claims is an identity hint, not proof of authentication; the authenticated server response establishes successful access.
- Verify quota feasibility with an authenticated GET to the fixed official usage endpoint, using account/residency headers derived from the same token. Keep tokens in memory, disable redirects, bound time and response bytes, and expose only allowlisted quota fields. Do not invoke inference, consume reset credits, copy logins into another store or refresh credentials merely to inspect quota.
- Show each principal's actual quota windows, reset timestamps and freshness separately. Label by reported window duration rather than response position. Expired, failed, missing or stale measurements must remain unknown/stale, not zero usage or 100% allowance.
- Keep externally owned Hermes account rows read-only through the entire normalization and rendering path, not only in the published JSON. Guard switch, rename and sign-in predicates and handlers explicitly: native defaults can assign an account-switch mode or infer sign-in from a stale status even when the external row has no accounts. Exercise those action paths with logging stubs and assert no native auth/account command ran. Preserve native accounts, cloud collection and active-account selection; publish only sanitized display metadata to a separate managed state record.
- Map external provider IDs to their native family in the icon resolver, including dark/light variants, rather than creating one asset alias per credential slot. Run native QML with both Hermes rows and reject missing-asset warnings; successful row discovery alone does not prove a clean rendered surface.

## 8. Persistent provider admission and safe clone upgrades

- Resolve the live Quickshell PID and its config path before selecting native source. A development-linked desktop can run `/home/.../omarchy/shell` while package paths contain a different version. Fingerprint the source used by the candidate and check it again before installation.
- Derive fixture consumers from the native helper's actual return contract. Omarchy `MenuModel.mergeMenuSources` returns an `items` map plus `itemOrder`, not an array; count/render through that order and compare against the merged native baseline, including its synthesized root. Preserve a wrong-shape fixture failure separately and correct only the fixture before interpreting the product result.
- Group repeated Hermes credentials by their dynamically discovered provider family and sort each group by numeric credential ordinal, using labels such as `Codex (Hermes 1)`, `Codex (Hermes 2)` and onward. Preserve the user's family ordering rather than interleaving individual credentials with other providers or using lexical numbering. Derive IDs and ordinals from inventory/metadata rather than a fixed pair.
- Keep Hermes credentials distinct from Omarchy's native account registry. Discover the active profile's complete credential inventory and use its sanitized identity/family metadata to generate provider rows, labels, icons and admission dynamically; never special-case credential slots or impose a business account-count limit. Reject unregistered or forged records by inventory provenance at local/sync admission and snapshot export. Deduplicate only demonstrated duplicate accounts or aggregates, not different API credentials and native subscription identities merely sharing a provider name. Preserve native accounts and credential files. Test zero, one, three and more than the previous safety-count boundary, plus add/remove/reorder, aliases, disabled credentials and unsupported quota providers; bound bytes, work and polling without silently hiding credentials.
- Execute admission functions with native Codex, both Hermes IDs, native Grok, a stray custom Grok record, and sync-only records. Then run the real native-QML fixture to prove discovery and visible status. A source substring or zero syntax exit is not provider-list proof.
- Preserve native Grok when its manifest advertises support. The custom hook collector does not automatically supply native quotas. Respect manage.py's shadowing refusal rather than injecting another Grok Agent into the Local stager.
- Require unique replacement anchors and exactly one supported complete panel layout. Add explicit variants for known native source drift, preserving stock semantics; refuse unknown, duplicated, or mixed-layout input. Never return success from a fallback that only hides Local trouble but omits its formatter/Text section.
- Pass manage.py `--shell` the full shell.json FILE path, not the Omarchy source directory. Repeated `--enable` may be an idempotent no-op; use a verified managed-update path or a fresh complete candidate with exact prior clone/config/registry preservation and concurrent-change guards. Keep all persistent behavior in source rather than maintaining divergent manual live patches.
- Bind clone ownership to a separate registry or independently retained original hash snapshot, including the manifest and complete immutable file set. The editable clone manifest cannot authorize its own unknown Agent.qml or extra assets. Register every generated clone file at initial staging; an exact current preimage may approve narrow task edits but is not a substitute for a trusted historical baseline. Refuse legacy adoption when that witness is missing.
- Validate the complete bounded native source tree before reading contents or creating installation state. Reject linked roots/ancestors/entries, hardlinked files and nonregular nodes, and bound count/depth/per-file/aggregate bytes; use no-follow leaf reads and a validated copy path. State that these checks and advisory locks are not atomic protection against hostile concurrent writers.
- Qualify the installed maintenance path independently of the repository path: install into an isolated HOME, invoke the installed manager with repository access removed, and verify that its upgrader, stagers, collectors and service templates are all present and hash-owned. Supply explicit profile, private-state and scanner paths in bridge units; test unit escaping and prove installation leaves services/timers inactive. A successful repository CLI test does not prove the installed update or scheduled-publication path works.
- Publish per-account Hermes records only to explicit controlled destinations. Preserve sanitized identity, actual quota windows, `limitsStale`/freshness fields, read-only ownership and honest unavailable status. Do not hardcode the real XDG scanner path inside a fixture run or swallow publication exceptions; test removal/order, atomic failure, symlink refusal and secret markers.
- Read collector `--help` before choosing flags. Grok's `--initialize` is a waiting-state publisher and `--hook` consumes documented metadata; it is not a subscription poller. Local status can accurately report metrics disabled while the collection service runs.
- Resolve `systemctl --user show llama-router.service -p FragmentPath -p DropInPaths -p ExecStart` before enabling `--metrics`: a later runtime drop-in can override the base unit. Verify the selected binary advertises the flag, preserve the runtime/preset/library values, validate the unit, reload the manager, and read back its effective command. A daemon reload does not change running argv; keep activation pending during active qualification or inference, and never invent unrecorded usage history.
- Resolve collector publication paths from its installed parser rather than interpolating the service name. The installed Local collector defaults to `$XDG_STATE_HOME/omarchy/local-router/agents/local.json` (normally `~/.local/state/omarchy/local-router/agents/local.json`), not a `local-router-stats/` directory.
- For a managed Agents clone, open the exact enabled plugin through `quickshell ipc --pid <pid> call shell summon <managed-plugin-id> ''`. A retained stock IPC target can address another instance, and `togglePanelAt` counts eligible widgets rather than raw shell.json layout entries. Inspect a popup-only Wayland capture after the card is painted and settled; successful IPC or a fullscreen layer registration can precede fade-in and is not visual acceptance.
- Reload the shell with the verified supported restart command only at the authorized boundary, preserve router/model processes, open the actual popup, and capture just its geometry. A new PID or successful IPC open does not prove the requested row list or visible content.

For guarded clone replacement, exercise the same recovery matrix through both explicit upgrade and ordinary disable/re-enable after a native-source update. Assert registry, shell and collector preservation alongside the clone state:

| Injected condition | Required observation |
| --- | --- |
| Foreign owner on the clone root, a traversed nonempty directory or a regular file | Refuse before backup/swap; preserve the complete original tree and registry. Simulate UID metadata in the fixture rather than performing real chown. |
| Staged rename fails, original restoration succeeds | Restore the exact original clone; report the operation failure without claiming incomplete recovery. |
| Staged rename and original restoration both fail | Report incomplete recovery, retain the original-at-swap backup and identify the absent destination honestly. |
| A newer destination appears during restoration | Preserve its bytes/nodes, retain the original backup and report incomplete recovery; do not overwrite the newer destination. |

When a native headless test uses an isolated KeyboardPanel stand-in, label its evidence as native data-model/text-tree proof, not live placement or visual acceptance. Keep unavailable counters distinct from recorded zero; do not start inference or load models just to produce statistics.

Trace a disabled provider through the actual generated/native `updateCommand()` and `--except` into the native updater's collector admission. Execute that updater only under a synthetic installation with logging mock collectors and `mise`, retaining enabled and disabled contrasts. A hidden card alone does not prove unnecessary dependency setup stopped. Qualify new installed sibling helpers with original-repository reads denied, not only by file presence or `--help`.

### 8.0.2 Selective managed helper repair

- For a pre-transaction recovery after reboot, revalidate all original target/registry/dependency preimages and old ownership before continuing. Read the timer's actual current state, pause only the owned feed timer if active, wait for its service to become quiescent, and retain that current state for restoration. Do not reuse a predecessor's `timer must already be inactive` assumption: reboot can reactivate an enabled timer even when neither target was replaced. Keep historical attempt records immutable and use fresh recovery evidence.

1. **Freeze the actual dependency set.** Bind the accepted helper, required installed siblings/templates, current target preimage and ownership registry. Require the repair's prerequisites to match; unrelated managed-file drift is not authority to overwrite the whole installation.
2. **Use the maintained transaction.** Inspect the installer's selective replacement API and recovery tests rather than inventing a CLI flag or using a raw copy. For the Agents manager, inspect `extras/agents-clone/upgrade.py:install_files` and its current signature. Supply only admitted target/data pairs; retain managed original-backup and registration semantics, concurrent-preimage checks and refusal of unknown ownership.
3. **Verify the exact transaction.** Read back the installed target and expected registry entry, retain the rollback preimage, and compare non-target registry entries and managed files with preflight. Do not rewrite unrelated records to make a broad installer pass. If a helper supports a pure `--render-service` branch, generating unit bytes in private evidence proves rendering only; installation, enablement and scheduling remain separate gates.
4. **Exercise the installed entry point.** Reuse the exact qualified argv with the absolute interpreter, `-I -B` for Python, explicit profile and approved source/publication paths. Verify the actual publication and retained identity/history, not merely candidate fixture output. Keep real-input reads and publication writes within their separately approved scope.
5. **Observe a natural scheduled successor.** Record the direct run's publication clock, then require the existing service/timer to produce a strictly later observation without another manual collection. Read back the relevant service result and publication; unchanged token counters are legitimate when no usage occurred. An active unit, rendered service or successful manual run alone does not prove scheduled delivery.
6. **Close only the repaired branch.** Keep quota estimates, Local live-rate admission and rendered popup/flicker proof open unless each was exercised. Do not generate inference or load a model to manufacture acceptance activity.

### 8.1 Updatable development checkouts

Use this procedure when private desktop development must remain compatible with regular upstream system updates. Keep source development, the updater checkout and supported user-plugin previews as separate ownership roots; use the root convention in SKILL.md without assuming the active launcher still selects those paths.

1. **Resolve the actual updater and deployed dependencies.** Read the selected updater/launcher as data and identify its real Git root, tracking ref and pull policy. Do not infer `--rebase` versus `--ff-only` from an error message or another checkout's configuration. Before moving private helpers out of the updater root, inspect maintained entry points or selected service metadata for dependencies on those paths; expose only needed paths/policy fields, not raw argv or secrets.
2. **Checkpoint both Git and filesystem state.** For each validated root, record `git -C "$ROOT" rev-parse --show-toplevel`, `branch --show-current`, `worktree list --porcelain`, `rev-parse --absolute-git-dir`, `status --porcelain=v1 -uall`, and its actual upstream ancestry. Capture raw status, staged/unstaged patches and HEAD directly into private evidence. Record regular-file hashes and permission modes, symlink text, tracked deletions and untracked files separately. Git hashes/stashes do not preserve arbitrary filesystem permissions, and `--include-untracked` does not cover ignored files; preserve relevant ignored preimages explicitly rather than sweeping caches or model trees into a stash.
3. **Resolve a blocking index lock without discarding it.** Locate `index.lock` under the Git directory returned above, not an assumed `.git` directory in a linked worktree. Inspect its node type, owner, inode/device, size and timestamps; check repository-bound Git/writer processes and file-descriptor openers. Stop on ambiguous ownership or liveness. Once it is established stale, revalidate the pathname's exact preimage and archive it with a unique guarded same-directory rename, retaining its bytes and destination. Do not delete a nonempty lock as disposable: it may contain an interrupted index. This is a Git recovery operation, not permission to stop another user's process or change credentials/security settings.
4. **Preserve local history before updating.** Create a uniquely named backup branch at the original HEAD. For a dirty root, save a named `git stash push --include-untracked --message "$LABEL"` and record the new stash object ID only after verifying a stash was actually created. Validate saved private file bytes and retained deletions against the preimage. Keep both backup ref and stash; do not apply the updater stash wholesale just to restore an experimental system tree.
5. **Rebase only the authorized private development stack.** Fetch the validated upstream in the development root, rebase the intended private commits and resolve only in-scope conflicts. Respect shared-history approval boundaries. Restore saved development changes and restrictive modes from the checkpoint, then compare index, uncommitted bytes/modes and the old/new private commit ranges; use focused tests and `git diff --check` to verify the preserved feature behavior. A backup branch is not evidence that the working changes were successfully restored.
6. **Prove the actual update path.** Keep the updater branch upstream-only and use its maintained Git-update phase with its existing pull policy; do not weaken fast-forward checks or merge private commits into it. Record the exact invocation, child exit, final HEAD/upstream relationship and clean status. Report this as Git-update proof only, not package, migration, snapshot, kernel or boot completion. After a user reports a full update succeeded, independently inspect both roots and preserved development preimages; distinguish that observation from having executed the full update yourself.
7. **Refresh only affected integration proof.** A successful update can leave private source bytes intact while changing native QML/imports. Compare external native bindings and run the smallest admitted current-native render/fixture before reusing layout results. Preserve source-only backend proof whose inputs still match. A staging refusal is a compatibility finding, not evidence that retained accounting data was corrupted or authority to bypass drift checks. Keep installation and live activation separately gated.
