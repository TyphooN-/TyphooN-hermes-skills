# Desktop Configurator Development

## Portable scope

This copy preserves a locally developed workflow, not transferable approval. Resolve the current task, repository, active Hermes profile, tools and ownership on this machine first. Historical project choices and TyphooN-specific executor/build policies are context, not permission to start services, run targets, modify security settings or publish. Project-root variables are documented in the collection's `PORTABILITY.md`; unset variables are not usable paths. Installing a skill installs no external tools or plugins.

## When to Use

Use when adding or reviewing desktop configuration scripts/TUIs, managed migrations, bar widgets, or desktop usage collectors. The Omarchy skill governs installed-system safety; this skill covers the application and integrations being developed. Follow the active coding-agent routing and approval policy.

Honor explicit do-not-wait executor steering: confirm the previous owner is terminal, release the current checkpoint, and continue through an allowed available executor rather than waiting for a preferred provider's reset. Preserve the independent-review and activation gates when changing executors; a route change is not acceptance.

Pin a replacement writer to its intended provider/model/effort in the dispatching turn after a driving-model switch. Task prose naming an executor does not configure its route; do not inherit an unqualified local model into repository-write ownership. Keep requested routing separate from observed model usage, and label identity unknown when an interrupted child emits no runtime evidence.

## Scope and baseline

1. Bind each accepted outcome to its actual producer, installed target and consumer before assigning evidence; shared labels such as Local or helper do not identify a component. An unrelated plugin's installation cannot satisfy a collector/popup outcome. Separate **implement in the repository**, **install**, and **activate on the running desktop**. Record which stages are authorized. Keep read-only, staged-only and no-restart boundaries in force across a generic continuation; permission to test bar settings does not authorize restarting inference services or loading models.
   - Recover an interrupted approval from an actual answered result or saved decision artifact before widening scope. If the answer is missing, ask one explicit scope choice; a dot or generic continuation does not supply the lost approval. Reuse the completed qualification checkpoint instead of rerunning it while waiting. Record the answer and allowed actions before assigning a writer, because approval for offline repair/review does not also authorize installation, live requests, restarts, commits or pushes.
2. Record branch, HEAD, worktrees, staged and unstaged diffs before assigning a writer. Describe a dirty checkout without competing writers as available, not clean, because ownership release does not erase or validate its preserved changes. Preserve staged user work independently of new edits; compare the final staged diff against the saved baseline rather than relying on status letters. Require a long-running executor to write a draft handoff before lengthy verification and update it incrementally, because an owner exit can leave useful code without a recoverable result.
   - Classify tool-owned diagnostic language servers separately from source writers. Edit-tool linting can leave TypeScript server/typings children with the checkout as cwd; inspect their actual entry scripts and parentage, record exact boot/PID/start/argv bindings, preserve the source/index guard, and do not stop them or blanket-exempt Node processes.
   - Bind Git comparisons to the exact producing argv, checkout root and rendering configuration. Match status porcelain version, NUL framing and untracked-file mode before comparing bytes: `status --porcelain=v2 -z --untracked-files=all` is not interchangeable with porcelain-v1 text. Preserve the raw `ls-files --stage -z` index baseline separately. Mnemonic/no-prefix formatting can likewise change patch bytes while source and index remain identical; reproduce the original representation before classifying a mismatch as mutation. Repair only the observer when its representation was wrong, because repeating tests or repository discovery does not resolve a serialization mismatch.
   - Treat the canonical development checkout, running/update checkout and user-created backup as separate ownership roots. After a user-performed system update, record each root's actual HEAD, branch and dirty state before resuming; do not assume the frozen development candidate changed with the installed system. Preserve the backup and any stash without applying, dropping or cleaning them automatically. Reuse unchanged offline source proof, but refresh deployed-version qualification only within its authorized scope because the running checkout may now differ.
3. Inspect the existing configuration helpers, menu wiring, confirmation flow, backup behavior, tests, and docs. Reuse them rather than introducing another configuration ownership scheme.
4. For a future fork, inspect download URLs, fallback launcher URLs, remotes, and locally available upstream refs. Report upstream destinations still embedded in the product; do not change remotes, commit, or publish unless authorized. Distinguish local refs from freshly fetched remote state.

## Behavioral migration

- Compare source dispatchers, not shortcut labels. Relative numeric workspaces, existing-workspace cycling, monitor-local cycling, and previous-workspace history are different operations.
- Trace the reference configuration and installed target defaults before consulting broad upstream source. Escalate to version-matched documentation/source only for a concrete semantic uncertainty; do not exhaustively research a small binding change.
- State empty-workspace, wraparound, monitor, and workspace-rule behavior. Preserve unrelated shortcuts.
- For TyphooN's workspace requests, prefer the requested HyDE-style Ctrl+Super+Left/Right relative navigation over numbered-workspace recommendations, unless the current request says otherwise.
- Check conflicts before writing. Explain any stock action displaced and its remaining shortcut. Match unbind behavior to the installed API: equivalent key combinations may have different literal spellings.
- A textual Lua scanner is not a parser. Specify supported call forms and limits; test modifier aliases/order, quotes, and whitespace. Do not claim exhaustive conflict detection for computed keys, multiline calls, custom wrappers, or recursively loaded modules.
- Managed blocks must be reversible and idempotent. Test interactions with keybinding editors: a later generated unbind can erase an earlier custom bind. Do not silently delete user bindings to repair ordering.

## Privacy, hardening and custom-kernel menus

- For this user's configurators, keep **Privacy & OPSEC**, **OS Hardening** and **Custom Kernel** as separate menus when requested; mixing convenience, security policy and boot operations obscures their different risks.
- Make status/audit the non-mutating entry point and require individual confirmation for each change outside any global **Apply all** choice. Creating a menu does not authorize activating its controls on the host.
- Preserve explicit values, unset defaults and original service state separately. Carry the caller-checked configuration version through Apply and Restore instead of rereading and adopting an intervening edit as the overwrite baseline; test refusal with the newer bytes and recovery journal intact. Treat verified absence as an expected preimage too: do not authorize a newly appeared target by fingerprinting it only when creating the journal. Exercise both initialization and established-state races. State the actual concurrency boundary: no-follow paths and advisory locks do not provide atomic compare-and-swap against non-cooperating writers. Retain stronger existing protections instead of replacing them with a preset.
- Derive service mocks from the complete version-matched property tuple, including unit identity, load/file/activity states, fragment pathname and overrides; correcting only one field can leave Apply or Restore broken behind green fixtures. Keep reported pathnames distinct from symlink targets. For strictly scoped persistent user masks, validate both the exact allowed fragment pathname and the physical owned `/dev/null` symlink through trusted no-follow parents; accepting any suffix or resolving the path loses provenance.
- Exercise recovery from the actual retained partial-failure state, not only clean Apply/Restore round trips. Construct synthetic ownership journals with the real serialization context (HOME/XDG layout and fixed IDs), and distinguish a malformed-fixture refusal from a product failure before counting a RED proof.
- For multi-command service restoration, inject a failure after each successful transition and retry after the failure clears. Before/after tuples alone cannot recognize the configurator's own unmask-then-start intermediate state; require narrow journaled transition ownership rather than accepting any candidate merely because the operation phase is failed. Preserve genuine newer-edit and provenance refusals alongside retry tests.
- Require an explicit "resume" record (phase in {changing,failed}, id, parent 8-int vector from stat) in journal data for any Restore that performed a successful unmask. The owned() check must match resume["parent"] via unmasked_parent() before treating a stock static/inactive tuple as the configurator's owned intermediate; a phase=failed Stop journal is not ownership and must refuse retry mutation.
- Trace code provenance and the demonstrated attacker boundary before attributing a security finding upstream; defects in new configurator helpers and internal release-gate priorities are not proof of an upstream vulnerability or bounty eligibility. Keep security proofs out of public issues and PRs while disclosure terms are unresolved.
- Separate stopping future recording from clearing existing history. Never back up the history being purged; configuration backups are different. Describe one-shot deletion as irreversible, not secure erasure, and identify retained application databases.
- Inspect custom-kernel shell configuration as data, never by sourcing/evaluating it. Report static hints and unresolved overrides separately from effective configuration; previewing a build command is not executing or validating a kernel.

See [references/security-controls.md](references/security-controls.md) for discovery commands, state/rollback design and isolated acceptance recipes.

## Safe verification

1. Create a disposable fixture HOME and configuration root. Verify resolved destinations remain under it before invoking mutation functions.
   - Validate every checkpoint field consumed by a reused private runner before dispatch, especially `fixture_outer_root` and the complete `outer_environment`. A source-manifest-only checkpoint is not runnable isolation. Exercise a harmless private-environment probe first, require verified success from every file-write tool, and preserve checkpoint preimages if a later metadata-only refresh changes a hash already bound by that probe.
   - Replay frozen probes through their matching private runner when they assert an owned fixture root. A generic TMPDIR wrapper can fail every setup before product code runs. Preserve that invalid-harness receipt, correct only invocation plumbing, and rerun the unchanged assertions; do not classify setup failures as product defects. Before wrapping an existing harness, inspect its setup assertions and preserve its required TMPDIR, review-root and guard bindings; a new outer sandbox can otherwise fail every case before product code runs. Preserve such setup failures as harness evidence, not defect reproductions.
2. Mock live commands such as hyprctl; remove live display/session variables or replace them with explicit fixture values. Inspect top-level code before sourcing only a function prefix.
   - Bound Node-based sandbox fixtures with an owned transient cgroup memory/task/CPU limit rather than a small `RLIMIT_AS` or `RLIMIT_DATA`: V8 can fail reserving its virtual CodeRange before any test runs. Retain that failed infrastructure probe, verify the replacement scope's actual `memory.max`, `memory.swap.max`, `pids.max` and `cpu.max` before target execution, and preserve read-only sources, hidden real HOME/buses, no network, bounded disposable scratch and wall deadlines. A resource-probe repair is not a product fix or permission to remove limits; collect the owned scope after completion.
   - Resolve each fixture's actual source constants before binding native-input hashes: setting `OMARCHY_PATH` does not override a hardcoded `/usr/share/omarchy` input. Keep the packaged tree and update checkout separate, bind every actually admitted root before and after the run, and label later byte-concordance checks as later observations rather than retroactive unchanged-input proof.
   - Resolve each required test executable before constructing a read-only namespace. Node or Python may live in a maintained tool directory outside `/usr`; mount the exact needed executable/runtime read-only and set an explicit fixture PATH instead of exposing the user's whole HOME. Inspect the runner's final child-environment construction before changing the caller's PATH: a wrapper that replaces PATH discards the caller's export. Verify resolution with `shutil.which(name, path=child_env['PATH'])` and a bounded version probe in that exact private environment before replaying the suite. A missing executable that aborts setup is an invalid harness, not a product regression. Preserve that receipt, repair only the mount/PATH, and replay only the aborted checks with the same source bindings.
3. Exercise enable, repeated enable, disable, repeated disable, backups, unrelated-content preservation, existing conflicts, editor ordering, missing files, and command/configuration failures. For interactive menus, drive the real renderer, selection and confirmation through an isolated PTY while sourcing only inspected definitions; helper tests alone miss category-routing and `/dev/tty` failures.
4. Capture the actual child command's exit independently of diagnostic text or a shell pipeline; `test-command | tail` can return the formatter's success after the test failed.
   - Inspect artifact size and project only top-level keys, required nested field shapes, source bindings and selected results before reading a large handoff or receipt in full; embedded source snapshots and SDK conversation results can consume the supervisor's context without adding acceptance evidence. Read the receipt producer/schema and require its actual target-exit field, such as `exit_status` versus `exit_code`. Do not use guessed `.get()` fields that silently yield null, substitute the outer tool's exit, or infer zero failures from absent arrays. Preserve a failed projection, correct its field path or schema once, and validate the unchanged artifacts without rerunning completed tests; genuinely missing required fields remain invalid or incomplete evidence.
   - Bound cleanup waits as well as the test deadline. Print/persist collected diagnostics before requesting child termination, and use a bounded communicate/wait afterward; an uninterruptible child with SIGKILL pending can otherwise wedge the verifier past its outer timeout and erase its in-memory receipts. Record an unreaped target with a null exit, preserve its PID/start/argv identity and stop new native reproductions rather than claiming cleanup succeeded.
   - Check the exact serialized next configuration's byte length against the reader's limit before creating a backup or replacing the file. A compact admitted input can exceed that limit after indentation or escaping; test compact-to-oversized refusal with unchanged bytes and backup inventory, plus exact-limit acceptance.
   - Distinguish real publication permissions from retained evidence-copy permissions. Assert private usage/state/history modes at the actual producer output before teardown, then verify copied artifact hashes and enclosing evidence-directory privacy separately; a copy's default0644 does not refute a source-bound0600 publication assertion or justify altering a frozen receipt.
   - Validate command-specific expected exits in an installed pipeline, not blanket exit0. A successful failure-path regression may deliberately record a refused CLI exit2 followed by last-good preservation and recovery; bind that expectation to the source assertion and keep actual wrapper/verifier exits separate.
   Prefer a bounded `subprocess.run(..., capture_output=True, timeout=...)` and save its argv, returncode and full log before summarizing. Budget a full suite from retained timings and its workload, not the focused regression's deadline. On an actual runner timeout, retain the partial receipt/log, identify the last progressing case and owned descendants, and confirm ownership release before retrying unchanged source once with a larger bounded allowance. Use a tracked background run when needed; a timeout is not a semantic test failure, and a passing prefix is not suite completion. Aggregate the newest coherent source-bound receipts programmatically, deduplicating scenarios by command, relevant environment and source generation rather than trusting a stale draft's totals. Report unit tests, marked subcases, static source/AST contracts and native scenarios separately, because they are different proof populations; a corrected count is not a new test execution. A static assertion script can exit successfully without behavioral case markers; report its actual assertion scope rather than inventing a test count or declaring missing behavioral proof satisfied. Empty stderr or empty configerrors output does not prove a reload command succeeded.
5. If supported by the installed compositor, run offline configuration verification on copied defaults plus the generated block, with an isolated HOME/runtime environment. Verify the check cannot launch autostart or affect the session first. Include a deliberately invalid binding as a negative control.
6. Treat a Lua mock as a model, not compositor proof. Keep it compatible with the actual interpreter; use a new local variable when normalizing a generic-for loop value rather than assigning to the loop variable.
7. Run syntax checks, focused regression tests, and diff whitespace checks. Record exact exits and optional skips. Report a passing `git diff --check` as whitespace proof only; inspect Git status separately before calling a checkout clean. Do not label an inventoried migration comprehensively tested.
   - For untracked owned deltas, distinguish `git diff --no-index --check`'s diff-present exit from whitespace diagnostics. Preserve the exact exit/output and verify the checker with a deliberate whitespace-error negative control; do not relabel a normal diff exit as a failed product regression.
8. Classify each check as **defect reproduction** or **safe-behavior regression** before interpreting its exit. An adversarial test that succeeds because it demonstrated unsafe behavior is a blocker, not green acceptance; preserve that frozen proof and add a regression asserting the safe requirement, observed failing before the fix and passing afterward. Treat unexpected nonzero regression exits as unresolved acceptance failures. Do not call them pre-existing or out of scope without baseline reproduction, and never mark a handoff ready to commit/publish while required tests or independent review remain blocked. Correct a stale readiness checkpoint before using it for continuation.
   - Trace a safety-harness failure to the actual product boundary before classifying it. Python may choose `os.posix_spawn` behind an already-validated `subprocess.Popen`; an audit guard that rejects that internal path can fail every test before the product executes. Correct only the disposable guard/execution strategy without weakening executable or destination checks, preserve the failed receipt, and rerun the same source-bound assertions.
9. Create ad-hoc verification artifacts in the active runtime's configured scratch directory, using an OS-generated unique name rather than a hardcoded temporary root. Write a fail-fast sequence, invoke it directly, record the exit, and remove only the exact disposable artifact after preserving necessary evidence. Do not rerun identical tests merely to obtain a different tool label.
   - Before interpreting a native harness deadline, resolve the fixture's actual stage sequence (setup, provider admission, refresh, assertion) and its per-stage budgets; a deadline shorter than setup plus a realistic refresh window is a harness defect, not a product timeout. Preserve the deadline-receipt and correct the budget or stage ordering before relaunching unchanged source. A timeout is not a semantic test failure, and a passing prefix is not suite completion.
   - For a republish or file-change assertion, establish the producer's scheduled or triggered publication cadence before asserting a refresh within the fixture deadline. If the producer is systemd-timer driven, compute the expected next elapse from its unit's timer properties and either wait for the natural elapse or invoke the maintained manual publication path with an explicit owned destination; do not rely on an implicit refresh that may not occur within the test window.

## Bar widgets and usage collectors

- Validate explicit publication outputs against the collector's own ledger, database sidecars and lock by both canonical pathname and existing inode before creating directories, opening the lock or opening SQLite. Reserve absent sidecar names too. Exercise the real render-only CLI with relative paths and hardlinked aliases, asserting unchanged ledger bytes and lock inode; ordinary file-safety checks alone do not prevent replacing an open database or locked pathname.

- Reuse the installed widget's data contract and theme before adding a separate panel; a signed-in CLI does not imply that the desktop has a collector for it. Derive schema-presence checks from the actual producer and consumer keys, because a guessed field name can falsely classify a valid publication as an older schema.
- Trace both the value and its refresh source. A format that includes seconds is insufficient unless the clock actually ticks each second. Drive observation expiry from an independent UI clock, not only a producer/file-change event, because stopped producers otherwise leave stale rates looking current. Age cached upstream-feed metadata on scheduled ticks even when its inode/stamp is unchanged; preserve admitted dated facts separately from liveness, and never renew the upstream observation time merely by republishing an envelope. Publish freshness-state transitions without waiting for ordinary output cadence. Test the exact expiry boundary, the first expired tick and fresh-input recovery without recounting retained totals; prove UI expiry in the instantiated native consumer with publication stopped, including independently expiring phases.
- Reject a future-observed usage projection before aggregating any of its buckets or snapshots; a fresh helper and matching week/year keys do not make later observations current. Preserve independently valid Local data and test same-day/cross-date future publications across every metric and grain, plus exact observation-time admission.
- Bound an IANA clock lease by the first actual calendar-key change within its fixed TTL, not just tomorrow's nominal midnight. A midnight rollback can return to yesterday before that deadline; prove both rollback and forward date skips through the actual helper and consumer.
- Synchronize controlled native fixture clocks with every synthetic publication and await pending helper completion before injecting a clock payload. Restoring a same-day helper key does not restore the UI tick; require the whole payload and observed tick, preserve the failed receipt, and retain all semantic assertions when repairing this observer.
- When reducing reactive-list churn, retain delegates by semantic record identity while keeping displayed values reactive. Before switching nested Repeaters to count/index models, inventory retained editor, focus, selection and pending-action state. Test same-ID refresh, reorder, equal-count identity replacement and removal during an active edit; require its action to retain the original target or cancel on identity change, because a surviving positional delegate can keep old text while its bound record changes. Do not treat retained objects, hover or scroll alone as action-identity acceptance.
- Treat operational metadata reads as potentially stateful: `/slots` may wake a sleeping worker. Before admission, establish a unique process generation and an unambiguous safety policy. Reject duplicate/conflicting port, alias or sleep options rather than guessing CLI precedence; exercise both split and equals forms through the actual admission and request path. Derive equivalent option names from version-matched engine parser source: short aliases and underscore-to-hyphen normalization can bypass an exact-name duplicate check. Normalize or refuse safety option names without rewriting their values, and test mixed spellings in both listed metadata and synthetic process args. Classify actual option-name positions using version-matched argument consumption before normalizing: a literal `--path` value such as `--sleep-idle-seconds=-1` must not become an explicit disabled-sleep policy. Preserve values consumed by one- and multi-value options, or reject argv whose positions cannot be proven; exercise the negative admission and mocked-request path plus genuine explicit-option controls. Report unavailable when safe read admission cannot be proven.
- Bind worker-safety semantics to the running engine's executable and relevant mapped libraries through maintained build/source provenance; compare the receipt's exact source revision, overlay and artifact set with the deployed set before closing that gate. A passing isolated build of a different revision, a repository pin or a version-looking pathname does not qualify the deployed parser. Keep source association distinct from reproducible-build attestation. For no-wake slot admission, supply every admitted option's exact registration/aliases/handler arity, parser environment/CLI precedence, final sleep-parameter flow into both response creation and queue sleeping, and real child-spawn/model-route selection. Generic dispatch and endpoint fragments omit essential connections; a synthetic argv fixture cannot prove the native parser or exclude router/proxy mode. Treat an independent HOLD for missing definitions as a source-context gap, not an executed bypass, and complete that context without rewriting the retained verdict or rerunning unchanged proof.
- Classify pin-valid engine options rejected by the collector as bounded-schema coverage gaps, not invalid engine syntax. Preserve fail-closed admission until a minimal arity/alias extension has test-first positive and decoy-value proofs plus independent review; recognizing a new option must not relax sleep or identity prerequisites.
- Validate model-listing status shape and supported values before claiming no loaded models. Treat an absent current child as unobserved worker eligibility, not proof of no loaded models or zero activity. Summarize unknown worker activity as unknown or an explicitly labeled lower bound, not an exact zero processing count; test collector output, compatibility text and the visible native header together.
- Test quota freshness through the instantiated QML Repeater/modelData delegate, not only copied JavaScript objects. Qt can expose nested limit lists as sequences for which `Array.isArray` is false; assert the provider-scoped visible window title, meter value and nonzero geometry, and retain a negative control using the old array-only guard.
- Gate every newly bridged quota on the independent display clock before inherited native reset forecasting. A guard for Grok does not protect Hermes: retain measured zero, withhold expired/unobserved samples, and prove the actual provider meter cannot change a retained nonzero sample to a fabricated zero. For joined observations, bound validity by the earliest required source/reset deadline and preserve producer timestamp precision in exact joins; a fresh envelope cannot repair a stale component or a millisecond-truncated reset. Choose a reset inside the freshness-age budget so the reset test discriminates those gates.
- Place a multi-tick UI characterization before one-shot refresh-completion handshakes, not between their terminal marker and quit. Otherwise a correct prior state machine can emit its last stage repeatedly; retain that strict failure and fix sequencing without weakening stage counts.
- When a presentation cleanup removes a status qualifier, gate native refresh handshakes on the changed publication fields and stable delegate identity, not the removed label or unchanged retained value. A formatter can be correct while the old textual handshake waits forever; preserve the timeout receipt and fix only the observer.
- Make completed fixture phases sticky when a later phase needs several timer ticks: return done on every subsequent call, rather than advancing and snapshotting the completed phase again. A resize phase that returns true only once can starve a later Loader stimulus until the native deadline.
- Wait for stable instantiated geometry after data-driven Repeater rebuilds before capturing positions. Two equal layout snapshots plus the actual containment/column assertions distinguish settled content from newly created delegates still positioned at the same origin; retain strict row/column checks instead of dropping an intermittent failure.
- Scope native Text lookups to the visible provider delegate when object names repeat across a Repeater. A first-match traversal can return another provider's hidden Local label and stall an otherwise working fixture; preserve the failed child/timeout receipt and correct only that selector before replaying unchanged product assertions.
- Preserve native lazy panel loading when porting pinned headers: size the loaded content's implicitHeight to include header + gap + body, and use fittedContentHeight(loadedContentHeight). Accept only complete, unique eager/lazy shapes; reject mixed anchors so Omarchy updates fail closed.
- In offscreen lazy-panel fixtures, mirror KeyboardPanel's cached Component/Loader API and open through Panel.open(), not its readonly opened property. Verify no startup allocation, first-open geometry, short-screen scrolling and content retention on reopen.
- Before a broad matrix, verify the generator's shared code contracts and fixture imports, run the smallest isolated render/stage against the current native source, then instantiate the offscreen consumer only after generation succeeds. A present sibling module missing an expected literal constant or schema key is a source-generation mismatch, not native layout drift; reconcile the provenance-matched support component and fixtures instead of inventing keys or weakening refusal. Bind the candidate, generator dependencies and native QML/import hashes together, because an upstream update can invalidate layout proof while private repository bytes remain unchanged. Retain the first failing command, boundary and log before widening scope. Keep in-memory generation, native execution and live rendering distinct; regenerate only affected checks and never substitute earlier output for a successful child exit.
- Preserve package-owned code and unfamiliar custom plugins. Stage supported user clones with fail-closed source checks instead of overwriting custom implementations.
- Diagnose token-panel faults as separate producer branches joined at the consumer: quota collector → sanitized quota files; canonical usage ledger → feed unit/publication; Local sampler → Local projection. Follow each consumer watch path into generated QML. Track ingestion, optional calibration and rendered/live-rate behavior separately; restored canonical publication proves neither quota learning nor flicker resolution. Inspect whether the deployed Local helper still unconditionally refuses slot admission before blaming quota freshness for missing Local speeds; preserve the safeguard and resolve its qualification dependency instead of removing it.
- Read timer cadence from its unit configuration or same-clock elapse differences. Systemd `NextElapseUSecMonotonic` and `LastTriggerUSecMonotonic` are boot-relative instants, not interval durations. Enabled/active status proves scheduling, not successful service execution, numeric calibration or visible UI behavior; check exact service exits and natural publication separately.
- Prove service quiescence from process and cgroup state, not only the activity label: a stopped failed oneshot may retain `ActiveState=failed`. Require inactive/failed with zero MainPID and ControlPID and no live service cgroup members, plus an inactive timer, before its guarded installation. Re-observe and stop the owned timer after reboot instead of assuming an earlier stop survived.
- Recover original timer intent from the first complete ownership-bound record, not an intermediate checkpoint that omitted the field. Preserve newer user configuration and keep original intent separate from current observations; private recovery tests must cover active-after-reboot and missing-intermediate-field states before live continuation.
- When a canonical feed stops after a runtime update, distinguish an explicit global schema-version gate from a changed usage-ledger shape or counter contract. Inspect the maintained version-bump rationale, add only specifically reviewed compatible versions, preserve exact table/SQL/privacy guards, and prove upgrade continuity plus unknown-version/shape refusal through the real isolated CLI. Never reset retained history or auto-admit future versions merely to clear a generic refusal.
- Trace persisted token fields to the active runtime's canonical normalizer before designing an accounting adapter, because raw provider input/cache/reasoning fields can overlap. For a global schema-version bump, inspect maintained declarations/migrations and admit only explicitly proved compatible versions while retaining exact usage-ledger shape checks; refuse ambiguous version rows and preserve source identity and observed history. Count each category once under that contract; never treat first_seen/last_seen aggregate bounds as exact daily events or credential attribution. Exercise the actual explicit-input producer through its consumer, because a mocked ledger can leave the production ingestion path missing. Use the offline accounting procedure in [references/quickshell-widgets.md](references/quickshell-widgets.md#41-offline-canonical-accounting-adapters).
- Treat a capacity increase as one end-to-end resource contract: trace source cardinality and lifetime identities through retained events/cells, journal loading, serialized exports, generated file-reader transport and parser byte limits before choosing finite bounds. Justify the linked limits with serialized-size proof; test old-state compatibility, distinct identity resets, exact-cap acceptance, beyond-cap refusal and last-good preservation through the actual generated consumer. A small fixture above the former limit or a parser-only pass does not prove the advertised maximum fits the real reader, and a larger limit must not be satisfied by collapsing identities, truncating records or wiping history.
- Validate live-rate fields against the producer's numeric domain before renderer coercion; reject booleans, numeric strings, nonfinite values and out-of-range numbers. At text-metrics ingestion, validate the documented ASCII numeric grammar before Decimal coercion, which also accepts Unicode digits and underscores. Preserve supported integral decimal/scientific spellings rather than changing compatibility controls to bless a digits-only parser; exercise each counter name through the real sampler and require rejected samples to leave snapshots and daily totals unchanged. Treat a missing/null phase as unobserved while retaining a valid other phase; invalidate the owning sample when a supplied phase is malformed, because rendering only its plausible fields conceals a broken record. Clone the baseline fixture separately for each mutated subcase so a malformed-rate case cannot contaminate the valid missing-phase control.
- Label measured scope and recording coverage. Keep unknown history distinct from zero activity, evaluated tokens distinct from full input usage, and sampled counters distinct from exact request accounting. Derive filtered lifecycle/status labels from the same selected-source view as summaries and bars; another source's measured zero must not relabel a baseline-only selection. Call numeric-returning validators for validation rather than truth-testing their result: a valid zero is falsy. Contain rejection of an optional malformed Local ledger to that source, and prove that explicit unrecorded/null gaps do not erase other valid dates or known Cloud counts.
- Validate an optional provider merge completely before mutating shared source inventory or dated cells, then recompute coverage with the combined consumer's exact rule. Exercise the actual merged publication through that consumer, including a complete Local day with no canonical Cloud feed, because a valid extra provider can otherwise invalidate the whole calendar.
- Scope read-attempt counters to the exact input path or provider when multiple optional inputs share a bounded reader. A canonical-history freshness test must not count expected Claude-file reads as rereads of the unchanged history projection; preserve the failed observer receipt and retain all liveness/counter assertions when correcting that selector.
- Isolate expected optional-ingest and publication failures within each running collector tick; commit projection stamps and published-value caches only after their corresponding operation succeeds. Serialize and enforce the consumer's actual byte ceiling before creating publication temporaries or replacing the last-good output. Give an expected publication-limit refusal a dedicated exception caught by the continuous loop, rather than catching every validation error; prove exact-limit acceptance, oversized refusal before file effects, next-tick recovery and nonzero single-shot failure. Keep retained history and independent outputs usable, retry unchanged failed inputs, and report sanitized failure classes without log spam. See [failure-isolated collector ticks](references/quickshell-widgets.md#44-failure-isolated-collector-ticks-and-provider-merges) for sequencing and regressions.
- Check publication eligibility before constructing a full dated rollup, because discarding an already-built view still pays its history scans and allocations.
