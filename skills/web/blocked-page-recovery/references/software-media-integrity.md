# Software media recovery: integrity after retrieval

## When to Use

Use these checks when a page-recovery hunt leads to legacy installers, disc images, split clients or patches.

- Treat listings, range probes, complete downloads and verified payloads as distinct acquisition states; an HTTP 200 or an MZ prefix does not prove a working installer.
- Preserve original downloads unchanged and record source URL, expected/actual bytes, retrieval time, SHA-256, metadata hash matches, exact test commands and exits. Archive metadata hashes identify the archived copy, not publisher authenticity or malware safety.
- Keep one writer per download file. Confirm old curl/aria2 processes have exited before changing transfer tools; preserve aria2 control files for actual resumability. A sparse/preallocated file's logical length is not completed progress. A wait-window timeout is not a transfer failure.
- Validate each HTTP range's status, Content-Range and exact returned length. Matching samples do not prove whole-file equivalence or the origin of corruption. Do not combine different mirrors without byte-identity evidence.
- Identify the OUTER wrapper before choosing an extractor. An SFX RAR or ZIP can contain an inner Inno Setup installer and multiple .bin slices. An unsupported-Inno error on the outer EXE is not proof that the installer is broken; inspect the outer archive first.
- Parse split Inno installer headers statically even when data slices are missing. Restore the source-listed basename in a disposable copy to learn expected slice names. Generic setup-1a.bin/setup-1b.bin names recur across builds; never substitute slices from a different version.
- Treat CRC failures as real blockers. Confirm with an independent archive implementation or direct stored-member CRC calculation before blaming a tool or mirror. Preserve the failing source and exact diagnostics.
- If an embedded RAR recovery record exists, perform at most one bounded static reconstruction into a NEW output using a legally usable native tool. Do not buy licenses, enable billing, reset trials, or globally install/configure software. Record tool provenance/license constraints, corrected sectors, source hash and reconstruction hash. Verify every outer archive member and the complete inner installer payload before calling the reconstruction integrity-verified.
- Inspect the repair tool's actual output path rather than globbing only *.rar: repaired SFX outputs may retain .exe.part or another original extension. Do not rerun a successful repair merely because the collector missed its filename.
- Never execute recovered Windows installers, DLLs or game binaries on the host as a validation shortcut. Static extraction and checksum tests provide integrity evidence, not installability or LAN playability.
- Model patch chains as version-specific directed edges. Separate newest identified build, newest recovered patch, and proven final service build; document missing bridges and incomplete later full clients.
- Do not infer a dedicated server or offline mode from a ServerFramework script, generic engine port, or conventional engine command-line flag. Report server/authentication functionality as unknown until actual software and runtime evidence establish it.
- Promote bounded receipts, file listings, logs and research catalogues from auto-pruned scratch storage into the user's preservation folder. Label derived files and corrupt sources explicitly; a checksum manifest establishes identity and can include unhealthy files.
- Stream-hash large inputs at an ownership checkpoint when byte preservation matters; size and mtime alone cannot prove immutable content, even when both remain unchanged.
- Preserve a failed historical-manifest check before diagnosing it. Independently hash the exact path, compare its bytes with known copies, and verify stored member CRCs when applicable. A path now identical to a verified reconstruction is an identity/provenance exception, not proof of random filesystem corruption or original-source retention. Keep historical hashes/receipts unchanged and create a separately labelled current manifest; never recompute the old manifest merely to manufacture a pass.
- Classify non-text configuration before decoding it. A .txt suffix does not establish UTF-8, and a permissive legacy-codepage decode can turn binary bytes into misleading prose. For a justified reversible byte transform, record the unparsed header, validate structure and roundtrip, and redact credentials before saving or printing any decoded representation. Never contact or authenticate to embedded endpoints.
- Distinguish FURY-specific developer/listen-server diagnostics from generic Unreal LAN settings: both are static leads, neither is runtime proof. Read the containing configuration section before treating a port as gameplay; statistics-provider ports are not verified LAN-server ports.
- Search public torrent metadata without assuming peer availability. A downloaded torrent and web seeds are not evidence of active seeders. Downloading over HTTPS avoids incidental BitTorrent upload; public redistribution still requires authorization and appropriate rights.
