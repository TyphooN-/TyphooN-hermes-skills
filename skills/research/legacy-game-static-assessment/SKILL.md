# Legacy Game Static Assessment

## Portable scope

This copy preserves a locally developed workflow, not transferable approval. Resolve the current task, repository, active Hermes profile, tools and ownership on this machine first. Historical project choices and TyphooN-specific executor/build policies are context, not permission to start services, run targets, modify security settings or publish. Project-root variables are documented in the collection's `PORTABILITY.md`; unset variables are not usable paths. Installing a skill installs no external tools or plugins.

## When to Use

Use for recovered game installers, PE binaries and compiled script packages when the accepted phase is preservation or static offline/LAN feasibility research. Keep runtime experiments, binary changes and service implementation separate; this skill does not authorize them.

## Procedure

1. Recover the latest accepted scope, executor decision and ownership checkpoint; inspect saved terminal results before retrying an interrupted lane.
2. Admit only named, credential-excluded inputs and validate their provenance. Reuse source-bound completed proof instead of restarting discovery.
3. Trace canonical original-byte/script evidence with explicit extents, receivers, state ownership and unknowns.
4. Cross-check only the missing native anchors through the qualified workbench, keeping decoder observations separate from runtime claims.
5. Finalize the assessment and receipts, freeze the complete artifact manifest, and obtain the required independent verdict before accepting the tranche.

For the serial raw-window query, comparison, reboot-recovery and freeze recipe, use [Bounded native evidence](references/bounded-native-evidence.md).

## Evidence and scope

- Use engine lineage to choose a differential reference, not to assume a drop-in server. Cross-check public engine claims against the admitted build's package/licensee layout and native/script structures; package-format numbers are not wire-protocol versions. Separate reusable engine replication/startup machinery from game-specific login, realm, database and state behavior, and test whether surviving host code can be reused before proposing a full protocol rewrite.
- Pin input paths, sizes and streaming SHA-256 against the preservation inventory before tracing; filename/build labels and unchanged size/mtime do not prove byte identity or an embedded build.
- Resolve snapshot library coordinates before reading: a recorded `path` can be relative to the owning snapshot, while `original` is historical provenance, not an instruction to reopen the original project. Prefer an already-frozen definition whose exact digest matches the declared library; retain both coordinates and never refresh hashes to admit a different body.
- Inspect retained web/API snapshot framing before parsing or declaring an empty search. Unlabelled Markdown fences and labelled JSON fences can wrap complete responses; remove only verified framing, require a complete parse, and compare declared totals/start offsets against collected rows. A complete historical search-result list is still not an archive-member inventory or an exhaustive absence proof.
- Preserve historical manifests and failed checks. Verify a separately identified current manifest from the directory its entries are relative to, recording the working directory as well as argv and exit status.
- Read the checkpoint's source classification before running Git preflight. For a preserved non-Git media or evidence directory, record HEAD/status as not applicable and continue its named inventory/hash checks; an unconditional Git command can abort recovery before any saved evidence is inspected. Do not initialize a repository merely to satisfy a repository-oriented wrapper.
- Keep recovered media and raw receipts immutable. Write derived outputs to a distinct phase directory and preserve corrections in new evidence rather than rewriting historical proof.
- Exclude credential-bearing legacy configuration from the tracing inputs and model context. Never decode, print, authenticate with or contact embedded login/FTP/game endpoints during a static phase.
- When preservation excludes credential metadata as well as content, skip those named entries before stat/open/hash. Compare directory-entry names against the baseline's known parent-directory set rather than using a file predicate over every path; generic recursive `is_file` checks can stat an excluded credential path. Count exclusions separately from hashed and metadata-only artifacts, and state that their identity/content was not verified.
- Recover credential exclusions from the accepted checker before opening any inventory-listed inputs. Historical inventories can include hashes for credential-bearing files without an exclusion flag; generic key/value detection is not a substitute for the explicit filename/path rule. Keep any failed preparation's exclusion history separate from a corrected check.
- Compare hash-backed inventory rows by required size/hash without assuming every row carries an mtime. Require size/mtime only for explicitly metadata-only rows, and retain their weaker identity boundary.
- Execute only trusted host analysis tools and owned parsing/check scripts. Do not load recovered code through Wine, an installer, debugger, emulator or script runtime merely to make progress in a static-only assignment.

## Native tracing

1. Validate PE format, architecture, optional-header bounds and section ranges. Treat VA, RVA and file offset as separate quantities; PE32+ has a 64-bit image base. Mark zero-fill and alignment padding explicitly and test conversion roundtrips on actual anchors.
2. Classify literal matches as whole strings, suffixes, prefixes or interiors. A production hostname inside a test hostname is not a second configuration setting.
3. Use canonical native disassembly to identify instruction operands. A raw pointer match or a preceding opcode-looking byte does not establish an instruction boundary. Tie useful operands to original bytes and base relocations; validate direct calls using their signed relative displacement.
   Supply bounded original-byte projections for pointed-to strings whenever a branch interpretation names those literals. Bind each exact load instruction, pointer value, NUL-terminated encoding, file offset and admitted image identity. A hardcoded helper description or names proved in an omitted earlier tranche do not close the current review packet's evidence gap; include that dependency or keep the claim at pointer selection. Test missing mappings, swapped pointers, missing terminators and namespace normalization without letting whole-file hash refusal mask those checks.
4. Recover function extents from prologue, predecessor/return/padding evidence and bounded direct-control-flow analysis. A long-padding heuristic can include neighboring routines; label uncertainty and unresolved indirect branches. Structural traversal is not observed runtime reachability. Inspect incoming normal-CFG edges before treating a local block certificate as universal: an interior entry can bypass zeroing or a register definition. Bind the proof to its named entry unless every dispatch path satisfies those prerequisites, and preserve alternate-entry state as unproved.
   Reduce large admitted helper prefixes to source-bound normal-CFG projections before model inspection: retain every reached canonical row, branch edge, call, return and unknown frontier, and bind the full original captures by hash. Validate direct-branch operands against encoded displacements and the selected rows against original bytes. Preserve omitted rows as uninspected rather than nonexistent; assumed normal returns from calls do not prove callee side effects, exception behavior or unique global function extents.
   Tokenize mnemonic and operand whitespace before interpreting stack arithmetic; objdump's aligned columns are not single-space syntax. Require independent caller-offset anchors and a paired-allocation/release omission control, because ignoring both stack adjustments can leave return balance unchanged while shifting every inferred input and local buffer.
   Compute buffer-relative operands through tracked caller ESP deltas and callee cleanup before equating stack displacements; a wrong cleanup shifts the inferred field. For aggregate handoffs, account separately for preceding pointer arguments, aggregate reservation, constructor argument pushes, constructor cleanup and the selected dispatch cleanup. Bind cleanup amounts to original-byte `ret` instructions where available, and label the balance as a normal-return proof rather than exception/SEH or observed-execution coverage. Keep ABI expectations for uninspected imports separate from inspected cleanup.
   Include ESP-relative stores in saved-register ownership proofs: optimized code can reuse a volatile-register push slot or the caller's argument-home word as scratch. Track which slot is overwritten before crediting a later pop. Distinguish conservative live-register clobbering by a call from corruption of saved stack slots, and state the normal-return/stack-integrity assumptions. Test wrong saves, wrong restores, saved-slot overwrite and wrong cleanup independently of raw-byte identity.
   Track overlapping byte/word stores in static aggregate-initialization proofs. Conservatively invalidate a previously tracked wider value when a partial or unaligned store overlaps it; a separate byte-key entry must not leave a stale zero-word proof intact. Pair the ordinary non-overlapping case with an original-width synthetic alias mutation that reaches the semantic guard without whole-file identity refusal.
5. Trace dispatch and ownership through concrete references. Track receiver definitions, overwrites, spills and branch-specific exits before assigning a later indirect call to the entry receiver; preserving a register on entry does not preserve its identity after a helper result replaces it. A factory name, constructor assignment and virtual-table slot can support class association without inventing a method symbol or a live caller.
   Trace output origins across pointer-validation or forwarding helpers before naming a factory: a value passed to a dispatch bridge may come from an existing register or cached field. Keep its identity across lazy initialization conditional on the uninspected callees' register, stack and memory effects.
   Qualify primary RTTI/table identity separately from slot-specific target validity. A candidate helper that requires an executable target at the requested slot can reject a valid base table when that slot exists only on a derived class; do not describe that rejection as absent or ambiguous RTTI. Inspect additional slots only on concretely selected, layout-supported tables, checking pointer relocation and executable target while retaining the selected-class scope.
   Bind a table writer's role and exact virtual index to its actual body and table words. A vptr/table-literal store can also occur during teardown, and language conventions do not guarantee that a selected wrapper occupies slot zero; retain setup-versus-cleanup and caller-ABI uncertainty until the relevant instructions support it.
6. For native-name tables with zero function slots on disk, trace static initializer assignments and the lookup consumer before naming the callable implementation. Never interpret neighboring data as a function pointer without a validated layout.
7. Verify the lookup consumer's return semantics before describing a binding. An address computed for a function-pointer slot is not the loaded function pointer or observed VM dispatch; retain that distinction even when the table entries are populated.
8. Distinguish incoming failure-response diagnostics from local developer-mode checks. A message mentioning an avatar option or listen server is not a tested launch recipe. A host override is not a server implementation.
9. Treat a return-only callback as having no established return value unless its instructions assign one. A bare `ret` preserves prior register contents; it does not prove a false/zero predicate or justify skipping a server reply.
10. Bind return cleanup to the selected routine's recovered entry and control flow, not the last return in a broad disassembly window. A neighboring function's `ret imm` can manufacture a false caller/callee ABI mismatch; preserve the broad exploration and add a regression that rejects neighbor contamination.
11. Inspect stored script role predicates before pursuing more transport helpers. Literal client/server guards can bypass initialization or Spawn blocks even when matching native code exists; bind literals and branch targets to original script bytes, distinguish syntactic callsites from normal-path reachability, and retain uncertainty about loaded overrides or another script provider.
    Resolve role helpers through their actual predicate body and the selected property's serialized enum binding. Do not assume a stock engine comparison or treat standalone as listen/dedicated merely because the helper is named IsServer; keep the selected enum-container interpretation and unobserved native role assignment separately qualified.

## Script packages and failed lanes

- Treat native-function declarations and their serialized parameter/Return/Nothing bytecode separately from C++ implementations. A Native-flagged two-byte script body or native index zero does not prove an absent implementation, an executable no-op, or a false/zero return; resolve the native binding and inspect the actual body before making those claims.
- Count creations and dependencies from decoded assignment/call trees with package-scoped references, not a union of object constants or a list of familiar class names. Resolve positive exports as one-based IDs and negative imports as `-(index + 1)` through the qualified package API; a class reference alone establishes neither object construction nor a mandatory or safely skippable LAN service.
- Validate version/licensee-specific package tables and serialized ranges before assigning a literal to a named export or function. When consistency checks fail, retain exact literal offsets but leave function ownership and server-side behavior unproved.
- Salvage partial executor work only after ownership release is established. Checkpoint the inherited path/size/hash set before takeover, validate saved captures against original bytes and recorded command/exit/log bindings, then inspect and run only the missing authorized finalization or tests. Attribute those commands to the recovering executor and keep an unknown original worker outcome unknown; a successfully recovered trace is not independent acceptance.
- Persist a native delegation's returned handle, ownership root and canonical continuation pointer immediately after dispatch, before disjoint diagnostics or other work. A reboot can lose the owner before an end-of-turn checkpoint; resume an already source-bound failing tracer at its missing GREEN instead of repeating discovery or erasing its RED evidence.
- Materialize and fsync partial machine-readable maps after bounded discovery batches rather than deferring every artifact until all tracing is finished. A quota interruption can otherwise leave only large tool transcripts and no reusable verified checkpoint.
- On reboot-unstable hosts, fsync each new helper source and containing directory before invocation; batch restored helper creation with its first execution so a successful write does not remain lost or unexecuted preparation. Recreate missing preparation from retained exact source while preserving completed proof and unknown interrupted exits.
- Parse native disassembly with a sufficient instruction-byte width, reject wrapped or missing operands, and compare each admitted instruction with original file bytes. Never replace a missing byte column with an arbitrary fixed-length read; that loses instruction boundaries.
- Reject `.byte` and `(bad)` listings even when their raw bytes match the original image; byte equality alone does not qualify a complete canonical instruction. Require admitted rows to partition the declared half-open window contiguously without gaps or overlaps, with each declared instruction size matching its byte column and the architecture's width limits. End finalized windows at validated instruction boundaries and exclude neighboring routines. Test missing-start, missing-tail, noncanonical-instruction and invalid-extent cases: individually matching rows can still omit bytes from an allegedly complete window.
- Separate canonical-window validation from complete-body validation. A prefix ending before a one-byte return can be a valid instruction window; require a separately source-bound entry/epilogue or control-flow extent when claiming the whole body. Preserve an observer's mistaken rejection expectation instead of weakening the decoder or treating a missing return as independently proved.
- Test helpers with explicitly synthetic fixtures. Cover address conversion, malformed/header/file-backed ranges, full-string versus suffix matches, completed-context retention, context caps and disassembly window selection. Do not present fixtures as observed game output.
- Admit an unsupported cast/token grammar only after binding its selector registration, operand consumption and nested dispatch to original native handler instructions or pinned source; a successful parse under a provisional extension is not proof. Preserve unknown semantic names and reject unbound selectors.
- Qualify candidate/reference-scan conclusions when any relevant function is undecoded; a successful subset does not prove the absence of other assignments or state providers. Add an integration regression that prevents exhaustive wording and binds each predicate to successfully decoded statements.
- Keep independent acceptance separate from reproducible parsing and tests. Preserve a pending receipt when a reviewer is interrupted or quota-locked; publish a separate later acceptance receipt only after a final verdict, completion quorum and frozen-hash checks.
- Partition only an unfinished restart-prone review into complementary source-bound parts when a monolithic request repeatedly loses its judgment. Preserve the original candidate and manifest identities, qualify lossless views and byte-identical full-source reuse, and prove cumulative coverage of every original and integration input. Persist each actual verdict, exact exit and runtime guard; require a separate independent whole-candidate integration before superseding HOLD. A component PASS, a planned union or a return-only projection is not whole acceptance.
- Stop identical review relaunches after repeated reboot interruptions yield no terminal judgment or transferable public findings. Preserve each unknown exit and source binding, finish any disjoint already-admitted static proof, then keep the acceptance-dependent milestone on HOLD with the missing verdict named; packet preparation, route initialization and a smaller review scope are not acceptance.
- Follow string consumers through the declared receiver property, the selected class override and any final superclass call before naming the boundary; a virtual function name alone does not fix the runtime target. A parameter named URL and unchanged forwarding establish its selected-script role, not its wire syntax, endpoint, absence of embedded session/credential data or successful travel.
- Treat compiled configuration selectors as symbolic references, not resolved class values. Preserve prefixes such as `game-ini:` verbatim; validate the actual selector namespace with positive/negative fixtures instead of normalizing it to `ini:`. Keep selector syntax, consumer behavior, separately admitted credential-excluded configuration values and actual runtime class selection as distinct claims.
- Keep shipped base/default template declarations separate when precedence, generated overlays or earlier resolver paths are unproved. Trace branches that bypass default selection before calling a template value effective. A named option literal does not establish its helper's semantics, receiver type, runtime role or a tested launch recipe.
- Characterize narrow allowlisted configuration projections with explicit synthetic fixtures against the exact hash-qualified producer. An AST harness may remap only documented I/O roots, but is not an OS sandbox. Test unrelated-value exclusion, credential-like-field refusal, invalid/unqualified tokens, encoding refusal, case preservation and duplicate retention; keep synthetic raw inputs clearly distinct from sanitized real evidence.
- Honor an explicit user-approved alternative review route without relabelling it as Opus acceptance. Pin and verify the independent reviewer's actual provider/model, preserve original pending receipts, and record the route change and final verdict in a separate acceptance artifact.
- Preserve the full structured result from native delegation delivery and its completed manifest; live human-readable transcripts may truncate final summaries and tool results. Do not reconstruct a verdict from a truncated transcript or describe truncated command summaries as full execution logs.
- Reconcile a stale native-review running manifest with the managed runtime and saved verdict before replacing the reviewer. Preserve unknown termination and partial passing checks as checkpoint evidence; never manufacture a completed manifest or acceptance when the final verdict is missing.
- Separate reviewer session-reported provider/model metadata from host-attested routing. Null provider/model overrides in a native manifest do not independently attest the effective inference route; preserve this provenance limit rather than upgrading it to verified runtime identity.
- Interpret an empty confirmed-dependency list as no dependency established within that traced scope, not proof that none is needed. In-process objects do not establish the complete process topology, an abstract database API does not prove an in-memory implementation is sufficient, and a Linux-first preference is not compatibility evidence. Correct overbroad summaries in a new superseding artifact without changing frozen originals.
- Record self-hosting and container preferences separately from runnable-server proof. A LAN-first/public-later target does not supply missing server executables, protocols or state, and Docker compatibility or runtime/deployment approval must not be inferred from available hosting resources.
- Allow explicit null/unknown values in dependency-contract schemas. Do not force unproved login/service requirements into booleans or prefill launch commands from generic engine conventions; that converts missing evidence into false certainty.
- Validate interrupted exploration as replay and checkpoint evidence, not finished acceptance. Preserve selected tool outputs and disassembly with input hashes; label heuristic write/reference filters and unimplemented helper flags before handing the lane back to its owner.
- Retain finished reference hits separately from the queue waiting for trailing context; collecting only pending hits at EOF silently loses the useful evidence.

## Linux-first analysis workbenches

- Evaluate a workbench such as REA through its implemented provider and host/target admission, not its product slogan. Headless Ghidra on Linux can inspect admitted Windows-format native binaries without running them or requiring a Windows host; verify the actual target and toolchain before claiming operational readiness.
- Resolve provider/JDK and build requirements from the pinned checkout, and distinguish a source clone from an installed, built, configured runtime. Do not run setup or change global agent/MCP permissions merely to answer an applicability question.
- After an upstream pull, compare the updated checkout with the actual analysis workspace's source pin and built package version. A pull does not refresh an archived runtime or erase its failed checks. Stage any newer build separately, preserve frozen evidence, and requalify a real provider query before treating source fixes as a resolved readiness blocker.
- Keep qualified original-byte PE and custom script-package decoders alongside the workbench. Loader-fixed memory, inferred types and pseudocode are not original file bytes or a recovered protocol, and independent load-image attestation may not cover the selected format.
- Qualify capture and instrumentation separately: HAR or mitmproxy evidence is not a generic custom game-packet decoder, and a Linux Frida fixture does not prove instrumentation of a legacy client under Wine. Admit only credential-free targets and preserve runtime/isolation approval boundaries.
- Treat a healthy provider doctor and successful lazy `open_binary` as prerequisite checks, not native-analysis completion. Require a query that actually imports/analyzes the target and reaches the provider bridge, compare its instruction evidence with original-file bytes, and retain the final closed-session artifact plus cleanup/exit proof. Do not infer completion or failure from the last progress file, which may still show a completed close operation as querying. An interrupted auto-analysis with only startup progress remains incomplete.
- After an orphaned runner or reboot, inspect saved results and process ownership before retrying. A changed boot ID establishes that old processes cannot remain alive; it does not erase successful exits and closed-session artifacts recorded before the reboot. Revalidate those source-bound results and reuse them without rerunning analysis. When exit/final receipts are absent, retain interrupted with unknown exit rather than inventing timeout or completion, and preserve the original attempt separately.
- Use a tiny byte-exact raw window from the admitted source as a low-cost bridge control when whole-image startup is impractical. Pin its original VA/file offset/hash, add no synthetic bytes, and compare native decoder output with the original instruction. Record caller-supplied raw/generic compiler conventions and seeded entries explicitly; this control does not qualify the full PE loader, original function extent, Windows ABI, callee behavior or live execution.
- Compare native instruction addresses within the provider's reported body ranges and check selected decoded bytes, widths and direct targets against the canonical source separately. Retain original no-op/alignment slots that a provider excludes, document the exact coverage difference, and never silently trim the canonical span or claim all listed bytes were individually compared.
- Verify disabled analyzer names against the selected program's analysis options. A name found in an installed JAR may be unavailable for that target; a pre-script error can abort analysis while the outer headless JVM exits zero, so inspect script errors and require the expected result artifact.
- Use a trusted bounded headless `-noanalysis` script when whole-program preparation prevents a useful native query. Admit only known function entries, compare decoded calls with original bytes, preserve full decompiler output, and qualify seeded extents, unresolved register contexts and inferred prototypes. A successful direct Ghidra fallback does not establish REA bridge readiness.
- Set Java's namespace-local `user.home` explicitly for direct headless launch when the passwd home is unmapped; `HOME` alone does not change that JVM property. Keep the override per invocation and never expose the host home or change global Java/agent settings to fix it.
- Preserve imported ordinals literally until the matching pinned DLL's export table resolves them. An import thunk linked to an SSL DLL establishes static library coupling, not the exact API name, live network use, cipher semantics or a recovered wire protocol.
- Check the preserved installer before treating a DLL absent from a selected extraction as missing media. Selectively list/extract only the admitted DLL into new evidence and require its individual payload checksum; never extract all configuration or run the installer. When payload baselines are metadata-only, bind fresh hashes to a hash-pinned stored archive member and keep known whole-archive CRC failures distinct from the selected-file checksum result.

## Source-backed helper oracles

- Verify normalized recovered source against the pinned originals before extracting an oracle: record the original hash and the exact encoding/newline transformation. Compile unedited pure helper bodies in a small ABI-checked harness with bounded, explicitly synthetic inputs; preserve commands, exact exits, definitions and vectors. Keep selected-helper equivalence separate from full gameplay, platform ABI or historical Toolbox/runtime proof.
- Preserve constructed RNG/raw-value fixtures as synthetic supply controls. Matching a scaling routine with manufactured seeds does not establish the historical generator, wall-clock seed behavior or observed gameplay.

## Closeout

- Record exact commands, cwd, source hashes and exits. Keep native observations, code-derived interpretations, assumptions and unobserved runtime claims separate.
- Save the actual managed-process exit before parsing a native capture, and inspect the producer's stdout framing. For a fixed cleanup caller that prints a helper summary followed by its own report, require exactly both complete JSONL records and validate the case/label and both exit fields; neither a single `json.loads` over the whole capture nor taking only the last row is correct. Preserve raw bytes and observer-only framing failures, repair the projection, and reuse the completed native case rather than rerunning a spent admission.
- Verify derived reports against their pinned inputs on rerun; refuse unexpected differences instead of silently replacing evidence to obtain a pass.
- Validate carried-forward JSON receipts as nonempty, parseable objects with the required verdict/source fields before admitting them to a model packet. A correctly matching SHA-256 of an empty file proves only empty-byte identity, not valid acceptance provenance. Preserve truncated preimages and the original independent verdict; reissue a separate fsynced/read-back receipt from freshly verified bounded proof rather than rewriting frozen history or claiming host clearance.
- Project evidence into JSON-native lists/dicts before freezing, and assert a serialization roundtrip. Tuple-valued import metadata becomes a list on disk and can falsely fail an otherwise unchanged replay; fix the collector's projection rather than rewriting frozen evidence.
- Inspect replay/check helpers for creation side effects before using them on immutable evidence. A `--check` flag or omitted `--write` does not prove read-only behavior when collection unconditionally creates directories or fills missing outputs. Require every retained artifact and block filesystem mutations; a narrowly qualified in-memory existing-directory assertion may avoid a redundant mkdir, but missing evidence must fail closed. Report this harness qualification and collector limitation separately from the byte-backed proof; never edit frozen helpers to obtain a clean replay. Qualify Python replay guarantees to the actual interpreter flags: use `-I -B` or disable bytecode writes before importlib module loading, since `--check` alone does not prevent cache writes. Preserve an unchanged-tree observation separately from any intrinsic write-free claim.
- Preserve bounded instruction/byte evidence and regeneration commands when full logs live in auto-pruned scratch storage. Do not promise that a historical scratch pathname will remain available.
- Finalize reports, tests, handoffs and verification receipts before freezing the source/output inventory; a pre-output snapshot is not a final artifact count. Keep explicitly named mutable parent-control files in the exact path inventory but outside proof-content hashes, disclose the manifest's self-exclusion, and never use mutable control as evidence. Capture subsequent check logs and reviewer outputs outside the frozen tree so verification does not invalidate its own snapshot.
- Deliver a concise report, machine-readable trace and verification receipt with one useful next decision. State missing update chains, unvalidated script layouts, backend-state unknowns and lack of playable LAN proof plainly.
