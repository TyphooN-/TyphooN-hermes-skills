# Candidate intake and source research

Use for URL registration, mixed model/code/collection backlogs, validator changes during qualification, and bounded acquisition research. Queue membership requests stages; it does not admit artifacts or authorize downloads, remote code, inference or serving changes.

## 1. Find and classify the canonical record

1. Locate the canonical source-intake backlog with `search_files`, then read its schema and validators with `read_file`. Distinguish it from executable artifact-transfer manifests before opening large queue files: a requested download stage belongs in pending intake until acquisition is admitted. Search every canonical inventory section for the exact literal URL and host-plus-source identity; do not count historical references as additional records. Parse large inventories locally and return section names/counts, projected identity/state/action fields for exact matches, one verified pending-row template and the maintained test references. Do not print arbitrary first/last historical rows: a small row count does not bound nested artifact arrays. Use exact identifier searches to locate the mutation boundary, then read only that region; reduce search context when it obscures the actual match. Reuse existing schema/preservation machinery for mechanical intake and checkpoint the bounded canonical delta promptly; do not build a new verification framework or spend a refreshed allowance on narrative preparation before registration.
2. Preserve the submitted URL and namespace spelling. Case-fold only the identity deduplication key and include host and source kind, because identically named Hub repositories, code repositories and collections are different sources.
3. Use optional lookup for legacy rows without `url`, then check their host-plus-identifier identity separately; a missing optional field is not evidence that registration is absent. If a matching historical row lacks the usual-queue fields, extend that row in place with the literal URL, source host, missing requested stages and explicitly blocked acquisition state; preserve its historical scope, revision, collected-at value and artifacts. Do not create a second pending row or retroactively label an unreviewed record investigated.
4. Classify before editing: create a pending record for a new identity, leave a fully covered existing record unchanged, or union only missing `requested_actions`. Preserve investigation state, revision, findings, license review, admission and existing acquisition/qualification receipts when a source is resubmitted.
   - Preserve researched-only historical batch arrays when their validator requires investigated state and revision pins. Append uninvestigated submissions to the canonical pending entries, not to those batches; do not invent a revision or weaken historical assertions merely to record intake.
5. Report a same-identity/different-literal-URL collision explicitly instead of normalizing the supplied token silently.
6. Represent collections as typed discovery records with separate counts. Leave membership undiscovered until primary evidence exists, and independently deduplicate/pin/admit each discovered member; a collection is not a downloadable checkpoint.

Completion: each submitted source has exactly one classified canonical outcome, with literal identifiers intact.

## 2. Preserve inventory and ownership before mutation

1. Snapshot the original inventory bytes, parsed document and explicitly owned validator files before writing. Record the exact checkout/base and existing dirty work. Before applying the bounded patch, require current inventory bytes to match that preimage; if they differ, reconcile the intervening owner's changes rather than overwriting them. Update only the count owned by the changed canonical section; preserve historical submission/batch totals and research timestamps, because an intake addition does not re-assess earlier records.
   - For a large JSON inventory, identify the exact containing record and use `json.JSONDecoder().raw_decode` to delimit its object before constructing a targeted patch. Parse the result and verify the complete logical row/count delta; do not reserialize the entire dirty inventory merely to append a record.
   - For an append-only batch, locate the final pending row by its exact literal URL, delimit its object with `raw_decode`, and assert the decoded object equals the parsed queue's final row. Replace only that row block with itself followed by the serialized new rows, using the existing indentation; patch only the owning section count separately. Retain the preimage digest check immediately before the first patch. If either patch is interrupted, parse the surviving file and reconcile rows and count before retrying, because these two edits are not one transaction.
   - Reuse a verified pending-row schema, not evidence from a researched row. Initialize new submissions as queued, uninvestigated, unqualified and acquisition-blocked; do not copy another source's revision, license decision, findings, artifacts or admission receipts.
2. Inspect the actual qualification fingerprint scope before touching tests or docs while a batch owns its inputs. A document can be excluded while every tracked verification file is included; file type alone does not establish permission to edit it.
3. Prove a needed validator change in an isolated checkout against actual canonical primary data without modifying frozen sources. Retain a baseline-bound integration patch and name the remaining primary-suite gap rather than calling isolated proof a primary pass.
4. After the qualification owner releases its inputs, integrate only against the recorded baseline under current authorization, run focused proof on actual primary data and mechanically preserve older records. Remove a released-input blocker after this integration is verified; stale run metadata does not retain ownership by itself.

Completion: the allowed mutation and each protected input are explicit; no active qualification identity is silently invalidated.

## 3. Validate raw source identities

1. Inspect existing validators before introducing a host: some hardcode Hub URL shapes or build repository-keyed dictionaries that discard duplicate rows before validation.
2. Validate host-specific literal URL/identity pairs and check raw-row host-plus-casefolded-identity uniqueness before any dictionary reduction. Exercise same-host repeats, cross-host name collisions, collection/repository distinctions and inconsistent host/URL pairs.
3. Preserve historical assertions and accepted schema differences; extend the maintained contract rather than weakening it just to accept a new submission.
4. Compare the entire parsed before/after document mechanically, not just the requested rows. For append-only intake, assert the old entries remain an unchanged prefix; deep-copy the result, remove exactly the appended rows, restore the owning section count and require equality with the complete preimage. For action extensions, exclude only the explicitly authorized field changes from that comparison. This catches accidental resets of older research, license decisions, receipts and unrelated metadata.

Completion: validators preserve namespace distinctions and every pre-existing canonical record is accounted for.

## 4. Prove the change and recover interrupted intake

1. Run the exact regression node first through `terminal`, using the recorded interpreter and maintained isolation, for example `<python> -B -m pytest <intake-test-path>::<node-id> -q -p no:cacheprovider`. Then run the maintained intake/schema selection and appropriate broader offline checks. Resolve and record an absolute pytest-capable interpreter before replay: native Claude and the Hermes tool process may resolve `python3` to different environments. Preserve a missing-pytest attempt as an environment failure, not behavioral RED, then rerun with the verified installed interpreter without changing global settings or installing dependencies.
2. Preserve each real child command, exit and log before asserting a wrapper's expected outcome, because the wrapper can otherwise obscure a failure during recovery.
3. For inherited documentation failures, capture a pre-edit baseline and compare exact failed identifiers after the change. With `--junitxml`, compare sorted `(classname, name)` identities for test cases containing a `failure` or `error`, and retain node/skip counts; this distinguishes an unchanged inherited failure from a replacement failure. For text-only output, extract identifiers with multiline `r'^FAILED (\S+)'`, because a space-only exclusion can consume line breaks and the next failure marker. Equal failure counts alone do not prove inheritance.
4. Inspect what RED actually demonstrates. If the initial test failed from fixture/schema setup, correct it and rerun against byte-identical pre-edit inventory in a disposable fixture; prove GREEN against actual updated data. Label reconstructed RED honestly rather than claiming the original test-first chronology, and never rewind user-owned primary files to manufacture a failure.
5. After interruption, compare surviving records and validator edits with the baseline before retrying. If the inventory's whole-file digest changed, compute the host/kind/identity-keyed delta against the retained preimage and trace intervening additions to their actual user requests and owning sessions. Prove earlier records remain unchanged and none were removed before treating the difference as additive; do not overwrite another owner's intake or rerun registration from an obsolete count. Keep historical receipts bound to their original inventory and request set: preservation of older rows does not extend an earlier test PASS to new identities. Reapply only a proven missing owned hunk against freshly read content; registration and validator integration may be incomplete at different boundaries.
6. Read back exact canonical entries and compute distinct requested sources, new records and extended existing records. Retain a per-request result with the literal URL, canonical section, raw match count, preserved state and new/already-covered/action-extended disposition. Count collections separately from repositories and exclude historical references; use this result set for the fail-closed batch gate in SKILL.md.

### Reuse unchanged validators for data-only additions

When the schema already covers a new source and offline pytest execution is admitted, prefer a small external parametrized test over changing dirty or qualification-fingerprinted validator files merely to add identifiers:

1. Read the maintained test module and its imports; confirm the assertion accepts the requested identifier/source kind/state and has only admitted offline import effects. Do not import candidate implementations or execute withheld sandbox/native proof through this recipe.
2. Create `test_requested_intake.py` in the private evidence directory. Load the original validator module with `importlib.util.spec_from_file_location`, `module_from_spec` and `spec.loader.exec_module`; do not copy its source into the evidence directory, because module-relative repository-root calculations would then point at the wrong checkout.
3. Parametrize the complete deduplicated request set, including already-covered resubmissions and unfinished earlier additions from the same intake thread, rather than testing only newly appended rows. Call the existing assertion with the actual identifier, source kind and preserved investigation state. The pending-repository form is `test_usual_queue_requests_preserve_one_record_and_existing_research(identifier, "repository", False)`; do not apply that false state to an already-investigated record. Run this selection before mutation so covered sources provide positive controls and missing records identify the actual registration gap. Keep identity-wide uniqueness and literal URL checks in the maintained schema selection as well.
4. For a standalone fixture-free documentation validator, run from the repository root with `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 <absolute-python> -B -m pytest <evidence-dir>/test_requested_intake.py --noconftest -q -p no:cacheprovider --junitxml=<evidence-dir>/intake.xml`. Do not suppress conftests or plugins when the maintained test requires them.
5. Run the maintained intake/schema selection and broader offline documentation checks, then compare baseline/post-edit failure identities and verify validator bytes stayed unchanged. Record the external cases as request-specific proof, not as newly installed persistent repository coverage; do not add overlapping focused and broad runs into an inflated pass total.

Completion: source-bound proof, preservation and deduplicated totals are observed; prior failures and partial work remain available for inspection.

## 5. Research an exact source without admitting it

1. Freeze a compact packet of pending records, a representative schema and relevant runtime/hardware context. Reconcile newer literal submissions with the actual checkout before dispatch, because an older inventory snapshot can omit a later intake section.
2. Reduce large publisher listings mechanically to the selected artifact set, exact revision, sizes, hashes, architecture, format, quantization, auxiliary requirements and license fields. Preserve each full response privately and print only selected options and relevant current-versus-pinned differences; dumping both complete listings repeats unrelated alternatives and consumes the judgment budget. Require complete JSON before parsing or counting: a long single-line response can be display-truncated even when line-based pagination appears complete. Parse the retained full artifact through a bounded script rather than treating a partial display as an empty or malformed publisher inventory.
   - Reconcile a safetensors checkpoint against every filename in its pinned `model.safetensors.index.json` weight map. Include separately named MTP files when the index references them; a sidecar-looking filename does not make required tensors optional, and tensor-byte totals exclude file-header overhead.
   - For a bounded small Git-tracked metadata response, compare its exact body length and declared `blobId` when provided. Compute the Git blob identity over `b"blob " + str(len(body)).encode() + b"\0" + body`, not the body alone, and retain a separate SHA-256 receipt. This is an additional metadata-snapshot consistency check, not publisher authentication or full-weight integrity verification.
   - Whitelist architecture/model-type fields before printing Hub model-info configuration, because full chat templates can be duplicated under several configuration keys; retain the complete response only in private evidence.
   - Inspect declared metadata-file sizes before setting fetch caps, because a safetensors index can exceed 17 MB. Treat a cap refusal as incomplete metadata, not corruption; use an explicitly bounded metadata-only follow-up with exact declared-length validation, or retain the missing-closure blocker.
3. Read primary base and derivative model cards, revision-pinned licenses and maintained backend documentation through `web_search`/`web_extract`. Distinguish missing license metadata from missing terms, and keep exact-source license review separate from the base model or another derivative's acceptance.
4. Check format and backend support independently of bit density or marketing claims. Inspect a code repository's implementation/dependencies before executing it; registering a research URL does not authorize remote-code loading.
5. Complete and checkpoint one per-source disposition before moving on. Do not spend the entire execution window collecting preliminary facts for every candidate without canonical progress; partial worker notes and timestamps remain unaccepted until bound to primary evidence.
6. Separate publisher claims, copied base-model benchmarks, community reports and local measurements. Attribute scores only to the exact evaluated variant.

Completion: each assessed source has a pinned, evidence-backed disposition and explicit remaining admission/acquisition/capability gaps.

## 6. Select precision and inspect bounded remote headers

1. Resolve the installed variant through its exact filename and manifest/downloader, then fetch its publisher inventory and pinned card. Check the filename-family guide before choosing a sibling: legacy releases, multilingual/template repairs, embedded-MTP twins and vision builds may share a repository without being interchangeable. Do not invent suffix combinations or add a standalone draft head to a file that already embeds it.
2. Compare compatible Q8 and full-precision options using declared file bytes in both GB and GiB. Prefer a published native-runtime reference artifact over an unnecessary conversion/backend migration. If an imatrix/i1 listing stops at Q6, inspect its pinned publisher card for an explicitly linked static-quant sibling before concluding Q8 is unavailable; verify the same declared base checkpoint and preserve the originally requested identity while recording the sibling artifact selection. Do not invent a sibling namespace. For sharded GGUFs, enumerate the complete selected sequence; distinguish native numbered shards from byte-concatenation parts that need reassembly. For safetensors, retain every indexed shard, including MTP. Keep alternative formats separate rather than summing them into one model's memory requirement.
   - Parse filename precision independently of source-model dtype words: a name containing `bf16.i1-Q6_K` denotes a Q6-labelled artifact, not proof of BF16 storage. Treat filename labels as hints until header proof; exclude imatrix calibration files, projectors and standalone MTP heads from main-weight choices without excluding full models with embedded MTP. Exercise these distinctions in projection regressions and repair derived reports from retained raw metadata instead of repeating successful publisher retrieval.
3. Record an explicit precision choice as artifact-level selection under the existing source identity, not a duplicate repository record. Preserve prior headers, receipts and observations under their original artifact identities; Q6 proof cannot become Q8 proof merely because the repository revision is unchanged. If canonical inputs are frozen, save a baseline-bound pending selection/patch and name its integration gap. Selection remains distinct from admission and activation.
4. For source screening without full acquisition, request a bounded prefix with HTTP `Range` from a revision-pinned public artifact URL. Require HTTP 206, the exact starting offset, an end within the requested cap and a total matching publisher size before reading the body; reject a full-body 200 response. Use the maintained bounded format parser, not remote repository code. Grow an insufficient prefix only within an explicit byte/request budget: large tokenizer metadata can exceed a small initial range, so truncation is not evidence of corrupt weights.
5. Retain only the consumed metadata/tensor-descriptor prefix, its hash, original public URL, selected file identity and range receipts. State any bounded over-fetch beyond the header; do not retain signed redirect URLs or relabel prefix inspection as full-file integrity verification. Reduce decoded output to architecture/shape, tensor-type counts, embedded-MTP metadata and template hash or narrowly relevant branches rather than dumping tokenizer arrays or personas.
6. Compare identifiers against the checked-out runtime definitions and templates, then name the remaining active-binary/backend and real tool-use tests. Recognized type IDs, template equality and embedded head metadata are source evidence, not successful load, placement or capability qualification. A template's role allowlist or tools-schema omission warrants a compatibility check, not an unsupported claim that the weights cannot learn tool use.

### All-model precision audit

Use when the user requests the highest-quality feasible quantizations across the portfolio, rather than one source addition. Keep selection separate from acquisition and native qualification.

1. **Freeze the census before comparing precision.** Join maintained presets, catalogs, installed-artifact metadata, supplemental workflows and pending/immediate requests by exact checkpoint identity. Enumerate only declared model roots with bounded stat/lstat traversal; record skipped roots, symlinks, incomplete transfers and unknown provenance. Map aliases to weight sets, group complete numbered shards, and classify projectors/adapters separately. Preserve non-GGUF and specialist roles instead of silently excluding them. Save expected IDs and their source membership before research; an older declaration/header manifest may omit installed-but-unaliased models.
2. **Finish one useful comparison, then batch by publisher identity.** Resolve the incumbent variant and list revision-pinned Q8, F16/BF16 and intermediate native-format alternatives using the preceding precision-selection steps. Reuse a bounded publisher listing for sibling options at the same revision rather than fetching it once per alias. Keep fine-tune, multilingual/template, vision and embedded-MTP variants distinct; nominal bit depth cannot establish their equivalence.
3. **Calculate two explicitly different ceilings.** Assess the highest precision plausibly resident on the participating GPUs at the intended context/cache settings, and separately any higher-precision RAM-offload option. Use complete selected artifact bytes and per-device weights, KV/recurrent state, companions, workspace and display reserves. Reuse source-bound calculators where applicable; leave unsupported peak allocations or placement unknown. Do not call RAM-plus-VRAM arithmetic a fit proof, or discard a promising Q8 merely because its new placement has not yet been exercised.
4. **Checkpoint one row per checkpoint identity.** Record aliases/role, current precision, exact higher-precision source/revision/file set, summed bytes in GB/GiB, supported resident target, separate offload option, context/cache assumptions, license/backend evidence, fit gaps and acquisition/native-test status. Preserve immediate priority and its dependencies. Mark conditional candidates explicitly; neither an available filename nor analytical storage fit is a tested winner.
5. **Reconcile identities before reporting completeness.** Persist rows incrementally, then require every expected ID to have exactly one disposition. Compute missing/unexpected/duplicate IDs and separate resolved, conditional and blocked counts in code; a transient source lookup failure stays visible rather than removing its model from the denominator. Keep alias, checkpoint and artifact-option totals separate.
6. **Return an actionable comparison.** Lead with concrete precision upgrades, followed by a compact current-quant / highest-available / resident-target / offload-option / fit-gap table. Name unresolved comparisons and retain machine-readable JSON/CSV evidence. Save selections under the existing source identity or a baseline-bound pending patch; do not download weights, rewrite presets or claim qualification merely to finish the audit.

### Bounded local header capture for budget preparation

Use only when the accepted task permits regular-file data-header reads. This is distinct from stat-only inventory, remote-prefix research and loading a model.

1. **Resolve authority before opening data.** Read the retained task/approval and the reader's complete source contract. Keep source acceptance, header-read admission and native-runtime admission separate. If cumulative bounds are missing, make the smallest extension to the maintained reader, prove its causal refusal controls and obtain required independent acceptance; do not build a replacement parser or admission framework. Once source acceptance arrives, use an already applicable data-read approval without asking again or treating the review itself as permission. Keep unrelated native-lab resource guarantees scoped to their own callers.
2. **Freeze the acquisition manifest and useful projection.** Derive literal paths and original IDs from the retained aliases, supplemental declarations and workflows. Deduplicate shared weight paths and select first numbered shards for header geometry; still inventory every shard for weight-byte accounting. Preserve companion dependencies, missing files, later-shard exclusions and unsupported non-GGUF workflows as separate outcomes. A retained declaration set is not an exhaustive installed-model census.

   Before reading a large batch, trace the selected backend's architecture loader and memory factory and list the metadata keys, expected types and source-supported defaults needed by the intended calculations. Include applicable per-layer dimensions/masks, trunk versus next-token-prediction counts, recurrent/SSM geometry and sliding-window parameters rather than relying on a generic dense-model `shape()` projection. Keep this projection narrow and versioned; verify required fields survive projection using synthetic metadata before discarding decoded headers. Distinguish a key observed absent from a key omitted by the projection, because only the former can justify a loader-defined default. If a later calculation needs uncaptured facts, preserve the original captures and supported results, then name the exact missing keys for a separately bounded follow-up instead of silently assuming values or rereading the whole batch.
3. **Pin the current observation and helper.** Compare the live boot with the input capture before data access. Bind the exact reviewed source bytes and the expected regular file's device/inode, size and modification/change timestamps. Do not upgrade stat equality to publisher-digest validation or serialized integrity. For an already authorized trusted Python helper, compile the same verified source bytes rather than relying on a cache-aware loader: `-B` suppresses bytecode writes, not reads. Never execute model-file contents or downloaded repository code through this pattern.
4. **Check the actual input mount.** Through `terminal`, run `findmnt --json --target "$MODEL_PATH" --output TARGET,SOURCE,FSTYPE,OPTIONS` for each input pathname before deduplicating observed containing-mount identities. An output-directory or sibling model's readiness is not a substitute. On observed Btrfs, use the applicable `btrfs device stats --check "$MOUNT"` predicate; do not run a ZFS-only prerequisite or install tools for a filesystem that is not present. Preserve exact command exits and refuse unsupported, read-only, malformed or failed observations. Mount/counter readiness is not host or content-integrity clearance.
5. **Declare and exercise bounded acquisition.** Set per-file bytes, aggregate bytes, file count and per-file/aggregate cooperative wall limits before the first read. Use one shared budget in a serial batch; independently bounded CLI calls do not create a cumulative budget. First capture one useful header and persist its result, source identity, bounds and actual reserved bytes. Expand only after that path works. If this smoke observation is reused, validate its binding and report its separate limits and reuse explicitly rather than pretending it shares the later batch's lifetime deadline.

   For a reviewed helper exposing `ReadBudget`, the exercised source-bound call shape is:

   ```python
   from hashlib import sha256
   import sys
   import types

   raw = reader_path.read_bytes()
   assert sha256(raw).hexdigest() == reviewed_source_sha256
   reader = types.ModuleType("admitted_header_reader")
   reader.__file__ = str(reader_path)
   reader.__package__ = ""
   sys.modules[reader.__name__] = reader
   exec(compile(raw, str(reader_path), "exec"), reader.__dict__)

   budget = reader.ReadBudget(
       max_bytes=aggregate_bytes, max_files=file_count,
       wall_seconds=aggregate_seconds)
   for path in frozen_paths:
       header = reader.read_header(
           path, budget=budget, max_bytes=per_file_bytes,
           wall_seconds=per_file_seconds)
       geometry = reader.shape(header)
       # Persist only budget-relevant fields, then release decoded metadata.
       del header
   ```

   Inspect startup effects before using this pattern. Verify source identity again at completion. Reservations bound application-level input requests, not heap usage, physical storage traffic or kernel/page-cache readahead; cooperative checks cannot preempt a blocked filesystem syscall or enforce aggregate CPU ceilings.

6. **Checkpoint each file, not only the aggregate.** Before and after each read, check the admitted identity/metadata and current boot. Refuse detected changes; do not claim an immutable snapshot or alias-resistant filesystem sandbox. Persist a create-only per-file result with identity, declared limits, charged file slots, reserved bytes, elapsed time and error category, then flush/fsync it before advancing. Distinguish attempted reading, completed parsing and accepted geometry projection. After a failed or short read, reserved bytes are an upper bound on exposure, not an exact successful-byte count. Record header reads as model-content access even though `model_loaded=false` and no runtime target ran.
7. **Keep decoded output narrow and claims literal.** Retain architecture, dimensions, cache-relevant facts and tensor counts needed by the budget; omit tokenizer arrays, personas, templates and unnecessary display strings. State that only declared metadata was parsed and no tensor payload decoder, tensor-descriptor walk or mmap was requested. A bounded parser does not authenticate physical section boundaries in hostile declarations or establish full-weight integrity.
8. **Calculate only supported components.** Reuse maintained formulas and inspect the selected architecture's state contract before applying dense-attention KV arithmetic. Do not infer dense-only behavior from a model name or assign a generic transformer formula to hybrid/recurrent models.

   - Bind formulas to exact backend source bytes and the relevant loader, hyperparameter accessors, memory factory and allocator. For a Git-pinned llama.cpp reference, extract named files with `git -C "$RUNTIME_SOURCE" show "$PIN:src/llama-model.cpp"` and the corresponding architecture/cache sources; record hashes and original line spans. A nearby checkout, reviewed private copy or matching revision label is not proof that its blobs match the selected reference, and source correspondence does not prove the served binary's layout.
   - Derive the layers actually allocated by each memory path. A declared block count can include MTP layers or mix full attention, recurrent and sliding-window layers; inspect the loader defaults, masks and allocation filters before counting them. Do not borrow missing geometry from a similarly named variant.
   - Use the backend's row-size/block-size/type-size semantics for the actual K/V shapes and supported cache types. Quantized blocks carry storage overhead, and width divisibility, layout and alignment can affect allocation; nominal bits per element alone are not a byte formula. Keep calculated tensor storage separate from runtime padding and peak allocations not established by the source.
   - Record each conditional component as quantity, symbolic formula, required metadata/runtime inputs, source references and applicability conditions. Leave sequence capacity, rollback/snapshot slots, MTP mode or other unobserved caller parameters explicit rather than substituting zero or an unverified default. A tool-free source assessment can establish symbolic requirements, not numerical execution, estimator acceptance or native fit; evaluate supported arithmetic with the maintained calculator and preserve its real command and exit.
   - Retain every original identity, configured profile and topology in the result, including unsupported and missing-data rows. Mechanically reconcile those sets and counts against the input matrix, and count supported profiles separately from aliases or weight sets. Preserve CPU-baseline comparisons and valid earlier components when extending the report. Keep workspace, activation, extra MTP state, allocator and tensor-placement gaps unknown; file-size proxies and conditional allocations are not peak-memory fit or native admission.
9. **Close the data stage against coverage and exits.** Reconcile captured, reused, refused and excluded paths against the frozen manifest, preserving the original alias/workflow IDs. Validate the actual worker exit and absence of surviving descendants before transferring ownership. Keep per-file observations if the aggregate is interrupted, preserve unknown exits honestly, and continue only the next admitted missing calculation rather than repeating accepted source review or completed captures.

Completion: every declared acquisition outcome and its bounds is recoverable, at least the exercised header path is backed by real execution, and unsupported geometry, runtime fit, host trust and activation remain separately stated. A running batch is not a completed capture or benchmark.

## 7. Report the actual stage

Name the canonical path and checkout, literal registered identities, deduplicated counts, preservation checks and exact verification exits. Distinguish isolated/uncommitted/local-commit/integrated state. State intake or research completion without implying source admission, artifact acquisition, implementation, qualification or activation.
