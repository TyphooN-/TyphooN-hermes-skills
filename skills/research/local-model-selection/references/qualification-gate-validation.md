# Qualification gate validation

Use when implementing or accepting a role-specific qualification gate, or recovering its independent review after interruption. This recipe verifies the gate implementation; it does not qualify a real model.

## 1. Recover the frozen review inputs

1. Read the implementation handoffs, complete changed-path manifest, source hashes, exact commands/exits and independent-review artifacts before commissioning another review.
2. Reproduce the saved source-binding contract before interpreting a mismatch: pinned base, relative-path root, complete path set, per-file value shape, mode representation, ordering and serializer. For a map of `{sha256, bytes, mode}` records, construct the same records and compare `current[path]['sha256']` with `saved[path]['sha256']` for content, or compare both complete records for the full binding; never compare a digest string with the saved record object, because every file then falsely appears changed. Recompute the aggregate with the recorded serializer, not a hashes-only substitute, and print only genuine changed/added/removed paths. Resolve citation strings to their bound artifacts rather than treating them as binding objects. Preserve format/adapter discrepancies separately from source drift, then recheck the pinned inputs. Do not add `mtime_ns` or other observation fields to a byte/mode fingerprint: copying or extracting unchanged files can change timestamps without changing the reviewed source. Compute a complete delta over the union of old/new paths by comparing their bound records; set difference alone reports additions and omits modified or removed existing files. Preserve useful adversarial probes and logs, but distinguish a final verdict from progress notes, partial read-through or a missing handoff.
3. Give the replacement owner compact artifact pointers and a stage ledger: source edits present, checks completed with bound receipts, missing checks, self-review and independent verdict. Assign only the unfinished stage; an applied port with no tests needs proof, not another port. Do not make it consume the full predecessor transcript or giant source files when targeted symbol windows suffice; repeated discovery spends the execution budget before obtaining new proof.
4. Match the handoff channel to enforced capabilities before dispatch. For a reviewer authorized to write private evidence, require an initial HOLD handoff with `scope_complete=false` and all unreviewed paths, then incremental completed judgments and finding receipts. For a restricted source-only reader, let the parent create that initial pending record and require a schema-backed terminal report containing scope, findings, source references and missing proof; do not grant Write merely to obtain `handoff.json`. Preserve available complete finding records while distinguishing source-established defects from executed reproductions. Permit an early BLOCK with an explicit unreviewed remainder; require complete scope for a clean verdict. Once source judgments and proof reconciliation are complete, persist the reviewer's explicit terminal verdict before optional housekeeping or final prose. A successful verification checker without the model's acceptance judgment still leaves HOLD; do not repeat completed proof to recover only that missing judgment.
5. Validate supplemental probe inputs separately from candidate hashes. A runner that hashes only the frozen candidate does not bind a newly authored reviewer test to its execution. Retain its real exit and log as partial evidence, record the current probe hash without retroactive attestation, and rerun only that small missing proof with test-source before/after hashes if acceptance needs it.
6. Collapse CLI `text` delta events into bounded message text before inspecting a streamed judgment; printing every token event floods the supervisor without adding evidence. After interruption, recover only individually complete JSON fields and retain the exact truncated text. Do not invent closing tokens, a final result or an exit status. A recoverable material finding may be reproduced in source-bound offline fixtures, but a partial `scope_complete` claim is not completion quorum or clean acceptance.

### Quota-interrupted independent acceptance

Confirm the managed reviewer has terminated and no owned descendants remain before transferring ownership. Recover only targeted findings and receipt/log pairs, verify their hashes and current source bindings, and save a compact missing-work ledger. A successful build or completed functional probe without an explicit completed reviewer verdict remains HOLD; parent reconstruction checks and implementer self-review do not replace independent acceptance. Keep subset reruns separate from nonoverlapping coverage counts. Reconcile pytest totals with its observed collection/results, including top-level functions as well as class methods; static method-only counts omit ordinary functions, and inherited or parameterized instances are not distinct implementations. Preserve a failed accounting artifact and correct only the ledger when executed source and receipts already match.

Record the quota report verbatim with its observation time. Do not infer an absolute reset date from a timezone-free clock or repeatedly retry before a confirmed reset, and do not accept provider suggestions as permission for paid usage or fallback. Continue only a separately owned safe offline implementation slice while review is blocked; preserve the frozen candidate and prohibit integration or activation until the required review completes.

For abort/death-test proof, disable core dumps only in owned disposable test processes before launch. Preserve prior incident metadata without reading or deleting system core payloads; never alter system-wide coredump settings to suppress a fixture side effect.

### Bind a forward-ported candidate

Use this branch when the target repository advanced while the reviewed gate or helper integration was frozen.

1. Record the recovered base, pinned destination base and complete owned tracked/untracked path set. Through `terminal`, obtain `git diff --name-only <recovered-base> <destination-base> -- <owned-paths>` and compute the intersection mechanically; unrelated upstream history is not a reason to re-audit the whole repository.
2. Port into a clean checkout at the pinned destination while preserving the dirty primary and recovered candidate. Merge the intersecting files rather than copying old versions over newer behavior. Compare both the feature edit blocks and the intervening upstream edit blocks; an unchanged feature delta alone does not prove that upstream fixes survived.
3. Bind every owned path by repository-relative name, content hash and file mode. Record byte-identical reuse separately from merged overlaps and new regressions. Include untracked additions without staging them; the staging index is not the review scope.
4. Record one reproducible complete-patch construction. From the checkout root, use `git diff --no-color --no-ext-diff --no-textconv --binary <pinned-base> -- <owned-tracked-paths>`, then append explicit untracked additions in sorted repository-relative order. On POSIX, `git diff --no-index --no-color --binary -- /dev/null <relative-new-path>` captures an addition; its exit 1 means a difference, not a command failure. Record the exact commands, path prefixes, context settings and concatenation order alongside the patch hash.
5. Classify a raw patch-hash mismatch before declaring source drift. Compare the pinned base, complete path set, per-file bytes/modes and serializer settings first: different prefixes, ordering, context or addition handling can change patch bytes without changing source. Preserve strict source guards and the original discrepancy; reproduce the same construction before resolving it, rather than changing staging or restoring files to force a match.
6. Run fresh focused proof for the merged overlaps and relevant ordinary-consumer control paths. Reuse older independent findings only for hash-identical source, and validate receipt input bindings separately. Check imported module origins against the destination checkout; a passing test against the primary or a stale worktree does not verify the port.
7. Freeze this candidate through independent acceptance. Compare the current primary with the pinned destination before integration; assess any newly relevant delta explicitly without retroactively calling the completed pinned review invalid or silently treating it as proof of the newer base.

Completion: every owned path and overlap is accounted for, the full patch is reproducible, actual test imports bind to the candidate, and source acceptance remains distinct from host readiness and real-model qualification.

## 2. Compare fixtures against real callers

1. Trace and exercise the actual public consumers against a disposable fake transport; do not reconstruct their prompts manually in the test harness. Verify synchronous and asynchronous entrypoints separately. A harness calling a nonexistent method is a test-wiring failure, not a capability or production defect; do not add a production API merely to satisfy it.
2. Validate guard propagation in the canonical runner's actual file child before crediting its captures. Check the child-recorded protected roots, native bypass flag and strict offline audit; a guarded orchestrator can spawn a child without its startup guard. Ensure isolated HOME still resolves protection for the real operator home, because default deny roots can otherwise move into the disposable fixture.
3. Capture and compare serialized messages, message ordering, body keys, headers, token limits and response parsing with the versioned gate cases. Exercise the caller's real sorting, normalization and truncation rather than duplicating those transformations in the expected-value builder.
4. Recheck the four distinct identities: caller source, fixture contract, request bytes and validator semantics. Trace source bindings through dependencies that can affect config resolution, observer/deadline budgets, identity and transport. Pin that justified dependency closure rather than retaining a fixed entrypoint-only list or indiscriminately pinning the whole repository; a source hash match proves neither fixture fidelity nor request identity.
5. Classify a mismatch before changing anything: caller nondeterminism, stale case construction, intentional normalization or materially different behavior. Preserve the predecessor contract and separately version/review a necessary correction instead of refreshing its pins in place or changing live code to fit an old measurement. Record fixture revision, schema version and wire ABI independently; changed source pins or corrected expected ordering do not automatically require a wire-ABI change.

Keep the fake transport credential-free, tool-free and confined to owned offline fixtures. Its responses are protocol evidence, never model capability evidence.

### Compare served presets without mistaking serialization for drift

1. Capture the configured effective preset, selected alias's bounded live preset and actual child argv separately. Compute missing, added and changed keys before editing anything; an exact dictionary mismatch does not distinguish a documented spelling alias from a changed setting.
2. Verify aliases against maintained backend argument definitions. For example, llama.cpp accepts `--gpu-layers` and `--n-gpu-layers` for the same setting; a narrowly defined canonical key can compare their values. Reject simultaneous aliases rather than silently choosing one, even when their values agree, because duplicate representations can hide precedence differences.
3. Accept an extra runtime-generated switch only when its origin and value are established. For an inherited `metrics=1`, verify the actual child argv contains `--metrics`; do not ignore arbitrary extra keys or drop the raw metrics value. Bind both raw live metadata and the semantic comparison into the observation so later changes remain visible.
4. Exercise pure comparison controls before another live attempt: the captured equivalent preset must pass, while changed context, model path, devices, cache type, parallelism, load mode, reasoning, unknown keys, duplicate aliases, foreign sections and unverified inherited switches must refuse. Preserve original prompts, request budgets and judges.
5. Keep a diagnostic adaptation in private evidence when that is the authorized scope; changing the reviewed native observer requires its own implementation/acceptance boundary. Parser controls prove only the comparison. Exercise the actual-child observer before dispatch, and retain a provenance HOLD if mapped-file identity still cannot be established.

Do not generalize CLI-key normalization into filesystem-identity normalization. Report mapped versus pathname device and inode fields separately; a device-only discrepancy is not proof of replaced bytes, and matching sampled inode numbers is not proof of complete provenance. Preserve an inaccessible `map_files` confirmation as a limitation rather than weakening the device check or presenting an unvalidated workaround as a reliable recipe.

- Reject Btrfs snapshot/subvolume identity based only on equal inode numbers, canonical superblock device, pathname ancestry and stable mountinfo: distinct subvolumes can satisfy those comparisons after a completed overmount. Require the kernel-held `map_files/<exact maps range>` object's synthetic device and inode to match the sampled disk object before accepting a device-mismatch fallback; unreadable references must fail closed.
- Exercise the snapshot collision and mapped-reference permission failure through the actual fingerprinting consumer, asserting rejection before any content fingerprint. Keep those simulated controls separate from evidence of real kernel access, and never change capabilities or security settings merely to obtain that live proof.
- Distinguish reading a `map_files` link from following it: current Linux can permit `readlink` while rejecting target `stat`/open with EPERM because the follow operation requires `CAP_CHECKPOINT_RESTORE` or `CAP_SYS_ADMIN` in the initial user namespace. Verify the running-kernel header, local kernel source and an actual-directory-entry self probe before proposing a fix; `lstat` identifies the procfs link, not the mapped object. Do not blame Yama, chmod, group membership or a child user namespace for a separately capability-gated follow failure.
- Keep any proposed privileged attestation outside Hermes, Python and the model server. A metadata-only one-shot helper is a design option, not an approved or proven solution: require explicit elevation approval, immutable reviewed code, bounded PID/start-time/UID/cgroup/namespace binding, constrained operations and output, and independent security acceptance before use. Never grant a capability to a general-purpose interpreter or weaken the accepted provenance fallback to avoid the prerequisite.
- Refresh boot and managed MainPID after an interrupted permission investigation; do not reuse a dead process identifier or infer present residency from prior-boot load evidence. Bind metadata comparisons to their observation snapshots, and keep an inaccessible mapped-object proof as HOLD rather than a real-model capability result.

## 3. Prove admission rejects the intended conflicts

1. Trace all inherited waiver sources and the conflict observation through the real loader, preflight and shared filters. For a strictly unwaived role, reject any nonempty waiver set before invoking preflight; merely observing unfiltered conflicts is insufficient because an idle host can otherwise admit a waived configuration.
2. Exercise two offline inputs: a configured waiver with no observed conflict, and a synthetic conflict paired with the waiver that would normally hide it. Require refusal before dispatch for both.
3. Repeat the boundary through fresh execution, cached-receipt reuse and forced requalification. Inject a late waiver/conflict mutation at dispatch and after a response; require that no new reusable success receipt survives.
4. Add preservation checks for other gates' authorized legacy waivers. Repair the strict role's policy without changing a shared default or broadening the correction into a supervisor-policy migration.

Record actual dispatch counts and receipt transitions:

| Boundary | Required observation |
| --- | --- |
| Refusal before dispatch | No inference request; preserve an existing reusable receipt only where the maintained contract permits it |
| Late conflict or identity mutation | Do not produce or retain a reusable success receipt; classify capability as unassessed or inconclusive |
| Failed dispatched retest | Do not resurrect an older pass |
| Cache reuse | Revalidate the same admission and identity requirements as fresh execution |

Check the preflight path, not just the final receipt fields: a waiver can remove a conflict before those fields are built. Repair role-specific admission without silently widening or narrowing other gates' policy.

## 4. Classify order-sensitive async failures

Read the failing receipt's exact selection and isolation environment. Reproduce that scope through the project's canonical runner, then run the selected failing test alone. For repositories using the Hermes runner, the exercised command shape is:

```sh
bash scripts/run_tests.sh -j 1 --file-timeout 120 <test-file> -q -k '<selection>'
```

Use the interpreter and guarded HOME/HERMES_HOME/TMPDIR setup recorded in the handoff; do not suppress a live-state guard to make a rerun pass. Run standalone gate tests through their maintained discovery command, for example:

```sh
python3 -B -m unittest discover -s <gate-test-directory> -p '<role-test-pattern>'
```

If mixed order fails but isolation passes, inspect resources created by earlier tests and those created by this test separately. For weak event-loop/semaphore caches, use fixture-only weak-reference and collection probes to distinguish retained resources from an immediate global-empty assertion. Do not add production garbage collection or broad cache clearing merely to satisfy that assertion. An isolated pass does not erase the original failure; require evidence that profile isolation, capacity and resource lifetime remain correct before classifying it as test contamination.

### Keep offline instrumentation separate from fixture state

- Place the observer module and terminal JSON results outside the pre-sandbox `HOME/.hermes` and custom `HERMES_HOME`; maintained real-home guards deliberately protect those roots, even when the roots are disposable fixtures. Use a unique owned ignored checkout instrumentation directory and retain the real guards unchanged.
- Refuse real credential-store paths and symlink escapes, but distinguish empty owned fixture files with the same names from production credentials. Pin a per-run fixture root and check both lexical and resolved containment; never grant a broad real-home exemption or copy actual credentials.
- Partition parameterized pytest selections using test IDs, not just role words: `-k` also matches the file name, so a role named in the file can select every role and hit the unchanged timeout. Reconcile the nonoverlapping selected-node union against the collected scope.
- Retain successful source-identical offline partitions from prior boots only as explicitly prior-boot evidence. Verify their log/document hashes and source bindings, count by node ID and boot, and exercise only the missing scope; do not call this current-boot model qualification.

## Managed maintenance lock contracts

- Bind all cooperating maintained entry points to the same checkout-relative lock, acquire it before narrower per-root locks, and retain it through weight hashing, metadata and final report publication. Document any scanning/validation performed before acquisition and the nonparticipating clients/checkouts; a cooperative lock is not a global resource reservation.
- Keep fatal and signal-driven shared-state publication inside a successfully owned lease, and reset ownership in finally with deterministic descriptor closure. Test preparation failures and signals before acquisition while another owner holds the lock, plus retained tracebacks, so an unleased error path cannot overwrite that owner's state.
- Trace ownership through every real CLI branch that calls a shared signal handler. A flag set only by the ordinary branch can misclassify an opt-in branch's independent lease and bypass child forwarding. Exercise actual run_step with a fresh owned policy child, a signal/readiness barrier and a delayed exit; prove forwarding, terminal step publication, lease exclusion until child completion, supervisor reaping and later reacquisition. Mocking run_step does not cover this interaction.
- Retain traceback objects with an explicit try/except around the real execution when proving descriptor cleanup. unittest.assertRaises clears an exception's traceback to break cycles, so a check after that context can silently remove the retention that the regression must exercise.
- Establish managed service membership from exact cgroup path components in valid v1/v2 records, never a unit-name substring. Cover unrelated prefixes/suffixes, malformed records, legitimate descendants and both conflict classification and runtime provenance; pin any new shared classifier module in admission/cache source identity and test missing, changed and late-mutated bytes.
- Restrict a busy/EAGAIN catch to lock acquisition. Exercise an EAGAIN from actual report publication separately: an I/O failure after partial work must not be flattened to a harmless busy retry or credited as completed coverage.
- Prove both acquisition orders with fresh executable children, explicit readiness barriers, real flock operations and bounded owned-child cleanup. Cover normal exit, SIGTERM/SIGKILL, the second-lock refusal, competing roots and the final publication boundary; persistent lock files are expected and must not be unlinked to manufacture recovery.
- Separate migration-only lock-lifetime proof from live gate-descendant cleanup. A killed supervisor's flock can be released while orphaned children remain; require the maintained process/cgroup cleanup and unchanged host-admission contract before claiming model execution exclusivity.

## Report admission and owned metadata

- Give reports and per-artifact receipts distinct schemas, and verify the complete same-root report shape before granting overwrite ownership. A shared marker alone is not ownership. Define strict metadata-only legacy migration and preserve marker-only, wrong-shaped and differently owned JSON.
- Check both lexical symlink refusal and resolved report/root containment. Open existing reports with nonblocking/no-follow flags, verify regularity through fstat, cap every read and close the descriptor on every error; a path-only size check followed by read_text can hang on a FIFO. Keep general parent-directory races and source-descriptor hardening explicitly separate.
- Revalidate mutable output ownership after acquiring all managed leases. A legitimate participant can publish between preflight and acquisition, so an earlier missing-file observation is not permission to overwrite its report. Create output directories only after lease admission, and keep publication/admission I/O failures outside the lock-busy catch.
- Exercise FIFO admission in fresh bounded CLI children with owned-child cleanup. Check retained validation tracebacks for closed descriptors, valid legacy repeat behavior, late-owner refusal, schema/type/count consistency and unchanged source/receipt bytes. Record supplemental controls separately from genuine RED/GREEN tracers.

## Evidence finalization after repeated reboots

1. Recover the immutable preparation manifest, complete candidate path set, saved checkpoint baseline and terminal receipts before editing the finalizer. Compare source bytes, modes, base/branch, staging index and protected primary state against those bindings; stop on unexplained drift rather than altering source or staging to make an evidence check pass.
2. Read the current boot identity through `terminal` using `Path('/proc/sys/kernel/random/boot_id').read_text().strip()` on Linux, and record preparation, execution and finalization boots separately. Retain completed source-identical offline proof as explicitly prior-boot evidence; rerun only missing or invalidated scope, because a fresh label alone adds no source proof. Never infer host clearance or current-boot model qualification from that retention.
3. Validate each receipt against its actual log and expected command, checkout, selection and source hashes. Treat labels such as `green` or `pass` as names only; the recorded child exit and observed test outcomes determine success. Evaluate confinement validity separately from behavior: a properly guarded failing suite remains failed, while a guard-invalid attempt earns no behavioral credit. Require the receipt's exit field to have exact integer type and the expected value, no timeout, matching execution start/end boots and unchanged before/after source bindings. Compare the log hash, terminal summary and exact failure identifiers; missing fields, bool exits, fabricated summaries and permissive conditions such as `or True` must refuse credit. Hash original file bytes through the execution tool; line-numbered `read_file` text can omit a terminal newline and is not a byte-identical hash input. Use the source-binding comparison procedure in section 1 for reference-map adapters. Preserve adapter errors as ledger issues, not false source-drift findings or reasons to repeat completed functional proof.
4. Reconcile collected node IDs with JUnit `(classname, name)` identities using a multiset, then reconcile base cases and subtests against the terminal summary. Do not assume the number of `<testcase>` elements equals a suite's `tests` attribute when subtests are enabled. Preserve empty module components for supplemental tests outside the checkout CWD: an observed `::test_name` can correspond to JUnit classname `""`, and requiring `.py::` silently omits that executed case. Verify baseline failures by identifier, and keep focused subset reruns and finalizer-control tests outside additional candidate capability totals.
   Exclude pytest's `current` symlink aliases when counting retained fixture observation directories. Check real owned directories and containment, then reconcile them with executed node identities; a glob can otherwise count the same successful observation twice. Preserve the failed accounting attempt and correct only enumeration, not source assertions or receipts.
5. Reconstruct the original-base aggregate patch and checkpoint delta separately with their recorded path order, prefixes and serializer. Use a saved `difflib` baseline as that baseline, not an invented Git commit. Require both byte/hash matches, run aggregate `git diff --check`, and confirm scoped owner/descendant cleanup; do not confuse a serializer mismatch with source drift or PID absence with an observed exit. Give each attempt fresh exclusive reconstruction directories: rewriting tracked baseline files does not remove additions from an earlier patch, so `exist_ok=True` does not make `git apply` idempotent. Materialize baseline modes before application under an explicit creation mask inside a private evidence root, then compare the actual applied contents and modes without post-apply chmod normalization. Scope D-state ownership to the tracked boot, PID/process group and inspected ancestry; an identified unrelated kernel build is not a lane descendant. Leave its workloads and blocked command lines alone, retain unknown/related process holds, and do not alter live qualification admission to repair an evidence-only ownership check.
6. Exercise the maintained finalizer's real check-only path in a bounded child before publication, preserving its original failing artifact and RED/GREEN receipts. Test refusal of altered exits, boot/source/checkout bindings, log hashes, summaries and runner selection in disposable metadata fixtures. Publish a new private handoff only after the checker passes and preserve the original receipts/manifests. Inspect catalog bindings before correcting stale RUNNING metadata: if the status file is hash-bound, append a parent-owned completion record instead of rewriting the frozen preimage, because bookkeeping must not invalidate replayable proof. Finalization remains separate from independent acceptance and live activation.

## Kernel-backed proof holds

Choose the admitted continuation scope before launching work; a proof hold is not automatically a source-work prohibition.

For source-only continuation:

1. Transfer released ownership, preserve matching partial files and assign only unfinished implementation or finalization. Declare non-executing source checks as the admitted scope; do not import candidate/fixture modules, because import-time code can dispatch the withheld workload.
2. Inventory maintained controls, regression identities and pending specifications separately. Use `read_file` and `search_files` to map proposed test-helper calls to actual production definitions and callers; apply the real-caller contract discipline in section 2 rather than adding a framework to satisfy an imagined harness API. Keep unresolved specification sources explicitly pending.
3. Check syntax with `ast.parse` or `compile(source, path, 'exec')` without executing the code object, then inspect call names/signatures and JSON/manifest/file/hash consistency independently. Update static validators whose old purpose was to preserve pending specification ASTs when those specifications legitimately become implemented; retain the old checker and explain the changed assertion scope rather than silently dropping checks. Record static API checks as structural observations, not functional proof.
4. Include untracked additions in complete original-base diff and whitespace review using the patch construction above; a plain `git diff --check` or empty diffstat can omit an entire new challenge pack. Refresh the manifest from that same complete current source set, including added helper modules, without staging files merely to expose them.
5. Record trusted buggy/reference/reject payloads as synthetic controls, not model responses. Preserve exact deferred commands, selection, confinement and expected observations as UNEXECUTED; writing a recipe or parsing its sources earns no causal RED/GREEN credit.
6. Publish source-complete/proof-held only after admitted implementation and test/API reconciliation are complete; otherwise publish source-partial/proof-held with the exact pending definitions or checks. Include static commands/exits and missing dynamic and independent acceptance. Resume only missing obligations after their admission changes, because source completion does not clear host trust or qualify a model.

For admitted dynamic recovery:

- Keep infrastructure HOLD exceptions outside `unittest.subTest` or equivalent framework scopes that record an error and continue. Guard every public launch entrypoint with the same fatal-HOLD state, including direct repository calls as well as the grading wrapper; protecting only one path leaves a bypass. Under admitted execution, inject an unreapable/setup failure and prove zero subsequent launches through each entrypoint. Require the outer orchestrator to stop on the maintained CLI's HOLD exit, because a process-local latch is not shared by separate CLI invocations.
- Retain failed-run identity, complete logs and reaping state in persistent private evidence outside automatically cleaned workspace contexts. Preserve resources when a child is unreaped; a truncated exception message or a temporary-directory cleanup is not lifecycle evidence.
- Refuse confinement/import verification failures as infrastructure HOLD before evaluating a control's behavioral outcome. Negative-control assertions must require valid isolation plus the intended causal mechanism, so an infrastructure refusal cannot masquerade as a successful rejection.

1. Stop repeated guarded launches while an owned process remains in kernel D-state with SIGKILL pending. Bind PID/start identity and wait channel to the saved boot and process group; a timeout-wrapper exit does not prove descendant cleanup. Preserve the checkout and missing high-FD/concurrency proof as HOLD rather than substituting a lower-bound or single-threaded setup pass. Inspect shared blockage without signaling unrelated workloads.
2. Before a recovery run, verify the old owner and test descendants are gone and the complete reviewed source manifest still matches its pinned bases and hashes. Reuse completed independent source review; assign only the unresolved proof instead of repeating the whole audit. Require explicit approval for reboot or system-affecting recovery.
3. If the user authorizes bounded continuation while host trust remains unresolved, run only the missing safe offline proof, serially, with its original canonical selection and guards. Use unique isolated HOME/HERMES_HOME/TMPDIR directories, the recorded interpreter and intended checkout imports. For the Hermes runner, retain `HERMES_TEST_FILE_RETRIES=0`, `PYTHON_CPU_COUNT=2` and `-j 1`; preserve the recorded file timeout rather than silently widening it. Stop further launches if an owned child becomes unreapable.
4. Save each subprocess's exact command, environment bindings, boot, source hashes, real exit, canonical summary, log hash and descendant-cleanup result. Parse the terminal summary once; do not add a focused rerun to a suite that already contains it.
   Keep application sources read-only while granting the maintained test scratch path a fresh private fixture bind. If a full suite refuses with EROFS in a hardcoded ignored scratch directory, trace the setup path, verify it is ignored and unowned, preserve the failed receipt, and adapt only that mount; do not make the whole checkout writable, alter assertions, or classify setup refusals as application regressions. Record actual-child namespace, protected-root, credential-environment and scratch-write checks before crediting the adapted run. Verify reviewed source remains unchanged before treating the new receipt as bound to that review.
5. Classify an unskipped exit-zero guarded run as successful functional evidence, provisional if host integrity is unresolved. Close only that missing test observation: do not infer host clearance, complete independent acceptance, current-base integration or real-model qualification. Retain the earlier failure and the remaining gates explicitly.

## Observer deadline composition

- Include pre/post/error observers in end-to-end deadline and cancellation proof. An observer-only, fail-open callback can still hold permits or stall the async loop; checking the remaining time after synchronous delivery only rejects a late result, it does not bound elapsed time.
- Reproduce with actual registered callbacks and dispatcher timeout semantics, not a mocked hook runner. Cover slow pre/post callbacks, async heartbeat, host/native cancellation, permit recovery, profile identity, saturation and bounded cleanup for the chosen scheduling design; never claim a timeout kills arbitrary Python callbacks.
- Retain observer admission until the queued work item is actually consumed, not merely until its Future becomes done. `Future.cancel()` leaves its payload in the executor queue, and submission can raise after enqueue; releasing a slot at either point can create an unbounded tombstone queue. Test cancellation and post-enqueue thread-start failure with an initializer barrier, then prove drain-time permit recovery.
- Preserve a guard-aborted canonical attempt without behavioral credit. If a guarded standalone reproduction proves the defect, bind its probe/log/source inputs and explain any changed positive-test outcome before crediting the correction.
- Give every rerun a fresh owned observation directory when a retained probe uses exclusive-create outputs. Redirect only its recording destination and bind that adaptation; preserve prior observations and assertions rather than deleting evidence or crediting `FileExistsError` as a behavioral result.

## Strict numeric JSON boundaries

- Reject float overflow as well as explicit nonstandard constants. `parse_constant` refuses `NaN`/`Infinity` but cannot catch standards-valid tokens such as `1e999` that convert to non-finite Python floats; supply a `parse_float` callback that verifies finiteness before accepting the value.
- Exercise nested, otherwise-unused metadata and admission identity fields through the actual bounded decoding path. Keep finite numbers and numeric-looking strings as positive controls; a schema check of only the consumed fields is not a strict whole-document parser.
- Inject exact numeric lexemes into serialized fixture bytes rather than first constructing Python floats: serializing `float('1e999')` produces `Infinity`, so it does not exercise overflow-token decoding. Construct a legacy control by changing its actual schema marker while preserving every required report field; unrelated shape rejection is not numeric-admission proof.
- Bind complete final-source partitions by collected node IDs and outcome, not by file counts or summed reruns. Retain intentional skips and baseline failures explicitly, and credit no node twice.

## 5. Hand off the smallest actionable result

Save source hashes before/after, source locations, the exact reproduction and exits, artifact paths/hashes, smallest correction and any unreviewed scope. Keep these dispositions distinct:

- **BLOCK:** a material implementation or admission defect established by cited source or a bound reproduction; state that provenance, retain any missing dynamic proof and route the finding to a separate owning executor.
- **HOLD:** required review or proof is missing; do not call absence of a verdict clean.
- **Clean implementation review:** the reviewed offline implementation passed its required scope; real-model execution and admission remain separate.

Do not promote an inconclusive post-response mutation result to a model failure automatically. Inspect whether the gate correctly refused reusable qualification after its inputs changed. Conversely, do not promote successful fixture execution or matching hashes to completed independent acceptance or live-model qualification.
